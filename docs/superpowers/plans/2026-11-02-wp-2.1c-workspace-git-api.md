# WP-2.1c Workspace and Git API — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HTTP API for the project repository: tree, file read/write/create/delete with `expected_sha256`, atomic patches, git status/diff/branches/log, branch creation and local commits.

**Architecture:**
- A framework-free service, `app/services/workspace_api.py`, sits over the WP-1.2 `Workspace` and `GitAdapter`.
- The service adds three things: authorisation and the repository/write preconditions, the per-project workspace lock around commits, and audit events.
- Thin routes live in `app/api/routes/workspace.py` (tree, files, patches) and `app/api/routes/git.py`.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, the existing `Workspace` (fd-based path checks, flock), and `GitAdapter` (git CLI without a shell, `GIT_LITERAL_PATHSPECS=1`).

**Spec:** `docs/superpowers/specs/2026-11-02-wp-2.1c-workspace-git-api-design.md`

## Global Constraints

- **Routing:** every route sits under `/api/v1/projects/{project_id}` and declares `require_project_permission(<perm>)`. Out-of-scope requests get 404.
- **Permissions:** `workspace:read`, `workspace:write`, `git:read` and `git:branch`, exactly as API_CONTRACTS §3/§4 name them.
- **Repository precondition:** `repositories.sync_state == "ready"` and `repo/.git` is a directory.
  - Otherwise 409 `CONFLICT` `reason=repository_not_ready`, or `repository_missing` when the folder is gone.
  - The service never writes `sync_state` (AG-13 entry condition, WP-2.1b).
- **Write precondition:** `projects.status == "active"`, otherwise 409 `CONFLICT` `reason=project_archived`.
- **Access level:** user access only (`Access.USER_READ` / `Access.USER_WRITE`); agent access is not used here.
- **Git hygiene:** `.kk` is never staged by a commit; branch names starting `kk/` are refused with 422.
- **Audit:** one event per successful write, carrying only paths and shas, never file content. The actions are `workspace.file_written`, `workspace.file_created`, `workspace.file_deleted`, `workspace.patch_applied`, `git.branch_created` and `git.commit`.
- **Routes stay thin:** validation plus a service call. No `subprocess` outside `app/gitops/`.

## Review Focus

1. **URL-encoded traversal in the `{path:path}` segment** (`%2e%2e/`, `..%2f`, a leading `/`, NUL). Expected: `PATH_VIOLATION` or 404, and nothing is read or written outside `repo/`. Test: Task 6, `test_paths_from_the_url_never_leave_the_repository`.
2. **A write racing a commit.** Expected: the commit contains either the old or the new file, never a half file, and the write is not lost. Test: Task 5, `test_a_write_during_a_commit_is_either_in_it_or_left_for_the_next`.
3. **A `.kk/` file that the archive already committed, then changed.** Expected: the API commit leaves it out. Test: Task 1, `test_commit_never_stages_kk_even_when_tracked`.
4. **`base`, branch `name` or `from` starting with `-`.** Expected: 400 `BAD_REQUEST` (`GitInputError`) and no git invocation. Test: Task 6, `test_git_inputs_are_never_options`.
5. **Archived project.** Expected: reads still work and every write gets 409 `project_archived`. Test: Task 3, `test_an_archived_project_is_read_only`.

### Task 1: Adapter commit with paths and `.kk` exclusion; public workspace lock

**Files:**
- Modify: `backend/app/gitops/adapter.py` (new `commit`; `commit_all` becomes a call to it)
- Modify: `backend/app/workspace/fs.py` (new `Workspace.exclusive`)
- Test: `backend/tests/integration/test_git_adapter.py`, `backend/tests/unit/test_workspace_fs.py`

**Interfaces:**
- Produces:
  - `GitAdapter.commit(target: GitTarget, message: str, author: Author, *, paths: list[str] | None = None, exclude: tuple[str, ...] = (".kk",)) -> str | None`. It stages `paths` (all files when `None`), unstages every `exclude` path, and returns the new HEAD sha, or `None` when nothing is staged.
  - `Workspace.exclusive() -> AsyncContextManager[None]`. It holds the same flock that the writes use. Wait limit: `LOCK_WAIT_S`, then `WorkspaceBusy`.

- [ ] **Step 1: Write the failing tests**
  - `test_commit_only_the_given_paths`: change `a.txt` and `b.txt`, then `commit(paths=["a.txt"])`. `git show --name-only HEAD` lists only `a.txt`, and `b.txt` stays modified.
  - `test_commit_never_stages_kk_even_when_tracked`: commit `.kk/old.xml` through a raw git call, then change it and add `.kk/new.xml` plus `x.py`. `commit()` with no paths contains only `x.py`.
  - `test_commit_with_only_kk_changes_is_nothing`: returns `None`.
  - `test_exclusive_blocks_a_write_until_released`: inside `async with ws.exclusive()`, a concurrent `ws.write_file` is still pending after 0.3 s and completes once the block exits.
- [ ] **Step 2: Run them and see them fail**
  - Command: `uv run pytest -q tests/integration/test_git_adapter.py -k "commit_only or never_stages_kk or only_kk" tests/unit/test_workspace_fs.py -k exclusive`
  - Expected: AttributeError (`commit`, `exclusive`).
- [ ] **Step 3: Implement both**
  - `commit`:
    - Validate with `_message`/`_author`, and each path with `_pathspec`.
    - Run `add -A -- <paths>` (or `add -A`), then `reset -q -- <exclude...>` (`check=False` for paths git does not know).
    - Then reuse the `diff --cached --quiet` and `commit` steps of `commit_all`. Make `commit_all` call `commit(..., paths=None)`.
  - `exclusive`: an `asynccontextmanager` that opens the root and takes the flock in `asyncio.to_thread` (reuse `_locked`), then releases on exit.
- [ ] **Step 4: Run them and see them pass, plus the whole git adapter and workspace fs test files**
- [ ] **Step 5: Commit** `feat(gitops): commit selected paths, never .kk; public workspace lock`

# WP-3.2f1 Cancel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /tasks/{task_id}/cancel` membatalkan task secara nyata.
- Task tanpa lease hidup langsung `cancelled`.
- Task yang sedang dikerjakan engine dihentikan lewat token, ≤ `heartbeat_s`, lalu engine menulis `cancelled`.
- Proses sandbox task dibunuh. Kill yang gagal ditandai `cancel_unconfirmed`.

**Architecture:** Penulis `cancelled` bersifat hibrida (spec §16.7 #101).
- **API** memakai `app/workflow/control.py` di bawah kunci baris: pasang flag, lalu `transition` bila tanpa lease hidup. Sesudah commit, kill dijalankan di luar DB.
- **Engine** membaca flag di claim, di setiap `_locked`, dan di setiap pelepasan lease. Heartbeat engine membaca flag lewat `renew_lease_flags` dan memicu `StepContext.cancel`. `AgentStep` meneruskan token itu ke runtime.

**Tech Stack:** FastAPI, SQLAlchemy async/asyncpg, PostgreSQL 16, Redis, pytest (+ `capture_logs`), import-linter.

**Spec:** `docs/superpowers/specs/2026-11-17-wp-3.2-workflow-engine-design.md` §16.7 (#100–#114, §16.7.3 A–K, ruling R-F1–R-F10 §16.7.4). Discovery: scratchpad `discovery-3.2f.md`.

## Global Constraints

- **Status:** hanya lewat `workflow.states.transition` (CLAUDE.md #4). Modul baru yang memanggilnya wajib masuk `TRANSITION_WRITERS` (daftar eksak, `tests/unit/test_status_writer_guard.py`).
- **Aktor engine:** `ACTOR = Actor("system", "engine")`, alasan transisi `"cancel_requested"`. Aktor API adalah user peminta, juga dengan alasan `"cancel_requested"`.
- **Flag:** dipasang dengan Core `UPDATE tasks SET cancel_requested = true` (`synchronize_session=False`), tanpa menaikkan `version` (R-F8).
- **Lease hidup:** `lease_owner IS NOT NULL AND lease_expires_at > clock_timestamp()` (jam DB), dibaca di bawah `SELECT … FOR UPDATE`.
- **Kill:** sesudah commit, di luar sesi DB, `asyncio.timeout(KILL_TIMEOUT_S)` dengan `KILL_TIMEOUT_S: Final = 10.0`. Kill hanya dijalankan bila lease hidup atau `status_before in {"running", "validating"}`.
- **Audit** (hasil hanya `success`, `denied`, `error`: CHECK di `app/models/audit.py`; R3):
  - `task.cancel_requested` (`result="success"`, metadata `{"reason": <teks teredaksi, ≤ 200>}` bila ada);
  - `sandbox.run_killed` (`result="success"`, metadata `{"killed": n}`), **hanya bila `n > 0`**;
  - `task.cancel_unconfirmed` (`result="error"`, metadata `{"error_type": <nama kelas>}`).
  - `resource_type="task"`, `resource_id=str(task_id)`, `project_id`.
- **Event:** `task.log` dengan payload `{"level": "warning", "code": "cancel_unconfirmed", "message": "The sandbox could not confirm that the task's processes were stopped."}`, ditulis di transaksi yang sama dengan audit `task.cancel_unconfirmed` (R-F10).
- **HTTP:**
  - 200 `Task`;
  - 404 bila task tidak ada atau di luar scope;
  - 403 bila tanpa `task:control`;
  - 409 `INVALID_TRANSITION` untuk `completed`/`rejected`;
  - 422 untuk `reason` > 200 karakter.
  - Route ini tidak digerbang `ensure_engine_available`. Tidak ada `Idempotency-Key`; idempotensinya alami (#111).
- **`Stopped`:** mendapat nilai `"cancelled"`. `task.step_finished` mendapat status `"cancelled"`, yang tidak masuk `completed_steps`.
- **Log:** hanya id, step, jenis, dan tipe galat. Tanpa `exc_info`, teks galat, token, maupun owner lease.
- **Semgrep:** tidak ada `rf"…{x}…"` di modul yang punya kelas dengan method async.
- **Fixture:** fixture mirip secret dirakit dengan penggabungan string.
- **Import:** route hanya bergantung pada `app.services` (import-linter). `CancelToken` diambil dari `app.core.cancel`.
- **Pytest:** satu DB untuk satu proses pytest. Runner `scratchpad/p32-pytest.sh` (DB `_32`, Redis 14); reviewer paralel memakai `p32b-pytest.sh`.

## Review Focus

1. **Dua cancel bersamaan atas task ber-lease.** Kunci baris membuat yang kedua melihat flag sudah menyala. Hasilnya 200, tanpa audit `task.cancel_requested` kedua, dan kill boleh diulang (Task 4, Task 6).
2. **Cancel tepat saat claim `draft`.** Flag dibaca sebelum `count_planning_attempt`, sehingga tidak ada percobaan planning yang terbuang dan tidak ada langkah yang berjalan (Task 3).
3. **Kill menggantung lebih lama dari `KILL_TIMEOUT_S`.** Respons kembali ≤ `KILL_TIMEOUT_S` + margin, dengan penanda `cancel_unconfirmed` (Task 5).
4. **Project `archived` atau sedang dihapus.** Cancel tetap 200; pembatalan tidak bergantung pada status project (Task 6).
5. **`reason` memuat teks mirip secret.** Teks itu teredaksi di audit dan tidak pernah muncul di log (Task 4).

# WP-3.1f2b1 — integritas akhir run: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every `agent_runs` and `tool_calls` row that is left `running` without a live worker, using only facts from the DB. Also: no orphan rows when an ack is lost, caller-held run ids, and a budget audit that is not lost on the minimal end.

**Architecture:**
- The run id comes from the caller (`AgentRunRequest.agent_run_id`), and `RunStore.start` is idempotent. This removes N5/D-I6.
- A new service `app/services/run_recovery.py` (second writer of `agent_runs`) runs in the existing `recovery_sweep` job after task recovery.
  - Its unit is the task, in one transaction: runs and tool calls are closed together.
  - Tool calls are closed by a new function in `app/tools/gateway.py` (single writer of `tool_calls`).
- `RunStore.fail` carries the known budget breach.

**Tech Stack:** Python 3.12, SQLAlchemy async, PostgreSQL 16, Celery, pytest (+ PostgreSQL/Redis lokal), import-linter.

**Spec:** `docs/superpowers/specs/2026-11-15-wp-3.1f2b-runtime-recovery-design.md` (Goals G1–G6, Keputusan Lead 3.1f2b #2–#8, #10–#12).

## Global Constraints

- **Writers.**
  - `agent_runs`: only `app/services/agent_runtime.py` and `app/services/run_recovery.py` (AST guard).
  - `tool_calls`: only `app/tools/gateway.py`.
  - Ledger: only `app/services/usage.py`. This WP writes no ledger rows.
- **Layers.** `app.workflow` never imports `app.services`, and `app/agents/runtime.py` imports no models/DB. `uv run lint-imports` must stay "10 kept, 0 broken".
- **Concurrency.** The sweep is safe with several workers: `FOR UPDATE SKIP LOCKED`, and every UPDATE is conditional on `status='running'`. Time comparisons use the DB clock `clock_timestamp()`, never the worker clock.
- **Values.**
  - Recovered run: `status='failed'`, `error_code='interrupted'`, `error=ERROR_TEXTS["interrupted"]` ("the run was interrupted: its worker is gone").
  - Recovered tool call: `status='error'`, `error_code='outcome_unknown'`, `output_summary=UNKNOWN_OUTCOME`.
  - `RUN_CLOSE_BOUND_S = 60`. Missing profile timeout: `MAX_TIMEOUT_S = 3600`.
  - Recovery actor: `app.workflow.recovery.ACTOR` (`system`/`recovery`).
- **Recovered usage.** Usage of a recovered run is never complete: `incomplete_run_totals(run_usage(...))`, which gives `partial` with ledger rows and `unavailable` without.
- **No new library. No migration.**
- **Secret-like test fixtures** are built by concatenation (e.g. `"-----BEGIN " + "RSA PRIVATE KEY-----"`), so no committed line matches a gitleaks rule.
- **No `rf"…{x}…"`** in Semgrep-scanned modules with async methods in a class (use concatenation or a `.replace` template).
- **Commands.** Backend checks: `uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run lint-imports`. Never two pytest processes on one DB.
- **Language.** Docs in Indonesian, identifiers in English, claims labelled [Pasti]/[Kemungkinan Besar]/[Menebak].

## Review Focus

1. **A runtime `finish` racing a recovery of the same run.** Exactly one terminal write and one `agent.run_finished`; the loser sees `RunAlreadyFinished` / skip (Task 5).
2. **Two sweeps at once** (two workers starting). Each run and tool call is closed once, with one event each (Task 5).
3. **A live run under a live lease within its deadline.** Never touched, including its own `running` tool call (Task 5).
4. **A run whose agent profile is gone, or has no `timeout_seconds`.** The 3600 s bound applies, not "never stale" and not "always stale" (Task 5).
5. **An idempotent `start` replayed for a different task or agent under the same id.** Refused loudly, with the row unchanged (Task 1).

**Interfaces:**
- Consumes: `close_abandoned_calls` (Task 4); `run_usage`, `incomplete_run_totals` (`app/services/usage.py`); `ERROR_TEXTS` (`app/agents/runtime.py`); `emit_task_event`, `publish_pending`.
- Produces:
  - `RUN_CLOSE_BOUND_S: Final = 60`;
  - `MAX_TIMEOUT_S: Final = 3600`;
  - `@dataclass(frozen=True, slots=True) class RunRecoveryResult: tasks: int; runs: int; tool_calls: int; failed: int`;
  - `class RunRecoveryIncomplete(RuntimeError)`, which carries the result and has a `__reduce__` like `RecoveryIncomplete`;
  - `async def recover_runs(sessions: async_sessionmaker[AsyncSession], bus: EventBus, audit: AuditWriter) -> RunRecoveryResult`.

Predicates (DB clock):
- `lease_dead` = `tasks.lease_expires_at IS NULL OR tasks.lease_expires_at < clock_timestamp()`.
- `stale` = `agent_runs.started_at + make_interval(secs => COALESCE((agent_profiles.limits->>'timeout_seconds')::int, 3600) + 60) < clock_timestamp()`. Outer join `agent_profiles` on `agent_id`.
- A run is closed when it is `running` AND (`lease_dead` OR `stale`).
- A tool call is closed when it is `running` AND (`lease_dead` OR its run is closed in this transaction OR its run's status ≠ `running`).
- Candidate tasks are the distinct `task_id` of either.
- Each task is handled in its own transaction:
  1. lock the matching runs and tool calls `FOR UPDATE SKIP LOCKED`;
  2. close the runs (UPDATE like `AgentRunWriter.finish`, with usage from `incomplete_run_totals`, `finished_at`/`duration_ms` from the DB clock, `agent.run_finished` in finish's envelope);
  3. call `close_abandoned_calls` with the task's `project_id`;
  4. commit, then publish.
- A failing task is counted, logged by type only, and does not stop the others.

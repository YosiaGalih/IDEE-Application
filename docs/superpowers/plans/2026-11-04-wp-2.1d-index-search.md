# WP-2.1d Repository Index and Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Index each project's HEAD commit (files and symbols) into `repo_index_entries` from a worker job, and serve text search (live working tree) and symbol search (index) over HTTP.

**Architecture:** All content parsing runs inside git processes started by `GitAdapter` (`ls-tree`, `git grep -o` on the commit, `git grep --untracked` on the working tree), bounded by timeout and output caps. `app/workspace/index.py` holds the framework-free language and symbol rules. `app/services/repo_index.py` owns the index job, the request path (Redis lock + `JobQueue`), and search. A thin route `app/api/routes/repository.py` serves the two endpoints.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2 async, Alembic, Celery, Redis, git 2.43+.

**Spec:** `docs/superpowers/specs/2026-11-04-wp-2.1d-index-search-design.md`

## Global Constraints

- `subprocess` only in `app/gitops/`; every user value reaches git as an argument after `-e` or is never passed (T3); `GIT_LITERAL_PATHSPECS=1` stays.
- No writer of `repositories.sync_state` or `repositories.error` (AG-13 entry condition, WP-2.1b).
- Index limits: 50 000 files, 200 000 symbols, 2 000 symbols per file, path ≤ 1000 chars (longer skipped), symbol ≤ 300 chars (cut), symbol grep output ≤ 64 MiB, 300 s per git command, lock TTL 30 min, job `time_limit` 20 min.
- Search limits: `q` 1–500 chars without `\0 \n \r`; `glob` ≤ 256 chars and ≤ 8 `*`; `limit` 1–200 (default 200); text search timeout 10 s, output ≤ 4 MiB, preview ≤ 200 chars; symbol candidates ≤ 5 000.
- Rate limits: `POST /index` 10/hour per user; text search 60/min per user (`enforce_rate`).
- Audit action `project.index`, one event per job run; metadata `{commit, files, symbols, truncated, unchanged, trigger}` or `{reason, trigger}` on error.
- Test DB for this session: `TEST_DATABASE_URL=postgresql+asyncpg://kodekantor:kodekantor@localhost:5432/kodekantor_test`, `TEST_REDIS_URL=redis://localhost:6379/9`.

## Review Focus

1. Paths that are not valid UTF-8 (git prints raw bytes with `-z`): skip them in the index and in text results instead of returning a path the file API cannot open (Task 2, 4).
2. A matching line of several MB (minified JS): preview stays ≤ 200 chars and the request stays under the output cap (Task 2, 5).
3. A query that matches thousands of lines: exactly `limit` hits and `meta.truncated = true` (Task 5).
4. Symbol queries with `%`, `_` or `\`: matched literally, never as LIKE wildcards (Task 5).
5. A project deleted while its index job runs: the job ends with an audited error (or a skip), never an unhandled exception that leaves the lock until TTL (Task 4).

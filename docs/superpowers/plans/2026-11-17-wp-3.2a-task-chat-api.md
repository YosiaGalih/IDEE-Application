# WP-3.2a — API task & chat: rencana implementasi

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun conversations/messages dan pembuatan/daftar/detail task (API §5) di belakang gerbang engine, supaya chat → task punya data dan kontrak yang siap dipakai engine (3.2c1) dan layar (3.2h).

**Architecture:**
- Service tipis di `app/services/tasks.py` dan `app/services/conversations.py`; validasi `context_refs` di `app/services/context_refs.py`; route di `app/api/routes/tasks.py` dan `app/api/routes/conversations.py`.
- Satu transaksi per request. Pembuatan task mengunci project (`authorize(lock=True)`).
- Gerbang `RUNTIMES_AVAILABLE["workflow_engine"]` ditolak 503 sebelum menulis apa pun.
- Tidak ada enqueue, tidak ada event task.

**Tech Stack:** FastAPI, SQLAlchemy async, PostgreSQL 16, Alembic, Pydantic v2, pytest + httpx.

**Spec:** `docs/superpowers/specs/2026-11-17-wp-3.2-workflow-engine-design.md` (§8 Keputusan #7, #13, #17, #18, #21–#26; §12 rancangan rinci 3.2a).

## Global Constraints

- Lapisan import-linter tidak dilonggarkan: `app.api` hanya memanggil `app.services`; services tanpa FastAPI. `uv run lint-imports` harus bersih.
- Status task hanya `draft` saat INSERT (trigger `tasks_status_guard`). Tidak ada penulisan `.status`.
- Redaksi sebelum disimpan: `env.audit.redactor.redact(text)` untuk `prompt`, `title`, `content`, dan judul conversation.
- Batas: `prompt`/`content` 1..20 000 karakter sesudah `strip()`; `title` ≤ 200; `context_refs` ≤ 20.
- Envelope API §1, `X-Request-ID`, `Cache-Control: no-store` lewat `_respond` (`app/api/routes/projects.py`). POST lewat CSRF + `Idempotency-Key` (middleware yang ada).
- Di luar scope → 404 `NOT_FOUND`, tidak membocorkan keberadaan.
- Library baru tidak ada.
- Fixture rahasia dibangun dengan konkatenasi string (aturan gitleaks repo).
- Satu proses pytest per DB.
- Perintah verifikasi (dari `backend/`):
  - `uv run ruff check . && uv run ruff format --check .`
  - `uv run pyright`
  - `uv run lint-imports`
  - `uv run pytest -q <file>`

## Review Focus

1. **Gerbang tertutup tidak menulis apa pun.** Dua pengiriman berturut-turut dengan `create_task=true` saat flag `False` tidak menyisakan baris `messages` maupun `tasks`, dan replay `Idempotency-Key` tetap 503. Test di Task 5 (`test_gate_closed_writes_nothing`).
2. **Path ref yang menyelinap.** `../x`, path absolut, `a//b`, `a/./b`, backslash, dan symlink keluar repo → 422, tidak pernah 500. Test di Task 2 (`test_escaping_paths_are_refused`).
3. **Pembuatan task gagal di tengah chat.** Bila validasi task gagal sesudah pesan disiapkan (mis. budget tidak sah), pesan juga tidak tersimpan. Test di Task 5 (`test_message_and_task_are_one_transaction`).
4. **Teks tersembunyi.** NUL atau karakter kontrol/bidi di `prompt`/`content` → 422 (PostgreSQL menolak NUL, dan bidi menyesatkan layar). Newline dan tab tetap boleh. Test di Task 3 (`test_hidden_characters_are_refused`).
5. **Task di project yang sedang dihapus atau diarsipkan.** `archived` → 409 `project_archived`; `deleting_pending_approval` → 409 `project_not_active`. Test di Task 3 (`test_inactive_project_refuses_tasks`).

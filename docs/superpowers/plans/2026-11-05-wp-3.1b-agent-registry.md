# WP-3.1b Registry agent, katalog, dan catatan agent run — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Registry v2 dimuat dan divalidasi saat API start, disinkronkan ke `agent_profiles`, dibaca lewat `GET /agents` dan `GET /agents/{id}`, lalu ditampilkan jujur di layar `/agents`.

**Architecture:** `app/tools/catalog.py` (data tool), `app/agents/registry.py` (loader + aturan), dan `app/agents/readiness.py` (status + alasan) adalah modul murni tanpa DB. `app/services/agents.py` berisi sinkron, list, dan detail. `app/api/routes/agents.py` tipis. Migrasi 0006 membuat `agent_profiles` + `agent_runs`. Frontend `features/agents` + `src/api/agents.ts` (Zod).

**Tech Stack:** Python 3.12, Pydantic 2, PyYAML, SQLAlchemy 2 async, Alembic, FastAPI; React 19, TanStack Query 5, Zod 4, i18next, Vitest + RTL + MSW.

**Spec:** `docs/superpowers/specs/2026-11-05-wp-3.1b-agent-registry-design.md`

## Global Constraints

- Registry: `schema_version: 2`. File repo `agents/registry.v2.yaml` → image `/app/agents/registry.yaml`.
- `approval_grant` hanya `deny`; `deployment ≠ deny` hanya F32; R3 tidak pernah di llm/profile.
- Peta kontrak runtime: A02 Intake, A03 Plan, B14 Implement, C20 Debug, D22 Review, A07 UserProxy (`<X>Input`/`<X>Output`).
- Limits: `max_iterations` 1..40; `timeout_seconds` 30..3600, dan 300..900 untuk llm/profile; `tool_quota` hanya untuk entri v2, kunci ⊆ tools, nilai 1..100.
- Status agent: `planned` | `disabled` | `not_ready` | `ready`. Alasan: `runtime_unavailable`, `provider_readiness_unknown`, `tools_unavailable`.
- Enum DB `VARCHAR + CHECK` `ck_<table>_<rule>`; migrasi lulus upgrade → downgrade -1 → upgrade.
- `recent_runs`/`stats` disaring `visible_projects_filter`.
- Teks UI hanya lewat i18n `id`/`en`; status = teks + ikon.

## Review Focus

1. **Registry mutan** (approval_grant allow, tool tulis di agent read-only, R2 tanpa sandbox, tool disabled di agent aktif, R3 di agent llm) → loader dan validator CI sama-sama menolak. Test di Task 2.
2. **Agent aktif tidak pernah `ready` di 3.1b**, karena semua tool `implemented=False`, runtime belum ada, dan readiness belum ada. Test di Task 2 + Task 5.
3. **Run dari project yang tidak terlihat** tidak ikut di `recent_runs` dan `stats`, termasuk stranger dan pemegang grant di project lain. Test di Task 5.
4. **Dua sinkron bersamaan** → tidak ada error unik ganda; hasil akhir sama dengan satu sinkron. Test di Task 4.
5. **Id hilang dari file** → `in_registry=false`, `enabled=false`, status `disabled`, baris tidak dihapus (FK `agent_runs` RESTRICT). Test di Task 4.

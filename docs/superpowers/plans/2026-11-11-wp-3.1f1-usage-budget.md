   - `workflow → models` diizinkan [Pasti]. BudgetGuard membuka sesi baca singkat per pemeriksaan. Ia tidak memegang lock baris task (ADR-070) dan selalu membaca `budget_limit` yang terbaru.

3. **Harga kasus terburuk** (Keputusan Lead #6, "harga model itu, atau harga tertinggi di tabel"):
   - Plafon per jenis tarif (input, output, cache_write, cache_read) diambil yang tertinggi dari semua tingkat model itu, termasuk `long_prompt`. Untuk model yang tidak dikenal, diambil yang tertinggi dari semua model dan tingkat di tabel.
   - Token input batas atas dihargai `max(input, cache_write)`, karena token itu bisa ditagih sebagai cache write.

4. **Baris yang tidak disebut tabel Keputusan #6** diperlakukan konservatif (Review Focus 2):
   - Baris `ok` tanpa usage dihitung seperti "jenis lain": `input_token_bound + output_token_cap`, dengan biaya kasus terburuk.
   - Baris `ok` dengan token tetapi model di luar tabel: token tercatat, biaya = token tercatat × plafon harga.
5. **Batas** (dibuktikan test batas):

   - Durasi terlampaui bila `elapsed ≥ limit`, karena pada titik itu tidak ada sisa waktu.
   - `elapsed` dihitung dari jam DB (`now() - tasks.started_at`).
   - `started_at` NULL berarti durasi tidak diperiksa. Ini dilaporkan ke Lead (lihat "Temuan").
6. **Presisi simpan.** Biaya dibulatkan **ke atas** (`ROUND_CEILING`) ke 10 desimal sebelum disimpan. Biaya bukan nol tidak pernah menjadi 0, dan pembulatan tidak pernah mengecilkan pemakaian yang dihitung budget.
   - Tarif sekarang punya paling banyak 3 desimal per MTok, jadi estimasinya tetap eksak [Pasti].
7. **Bentuk uang di API.**

**Antarmuka `app/core/money.py`**

```python
COST_QUANTUM: Final = Decimal("1E-10")                       # numeric(20,10)
MONEY_PATTERN: Final = r"^(0|[1-9][0-9]*)(\.[0-9]*[1-9])?$"
def stored_cost(value: Decimal) -> Decimal: ...   # quantize(COST_QUANTUM, ROUND_CEILING); ValueError for negative/NaN/inf
def decimal_str(value: Decimal) -> str: ...       # format(value.normalize(), "f"); ValueError for negative/non-finite
```

**Antarmuka `app/services/usage.py` (writer)**

```python
@dataclass(frozen=True, slots=True)
class UsageCallContext:
    project_id: uuid.UUID
    call_id: uuid.UUID                 # one logical model call; its retries share it
    input_token_bound: int             # >= 0; computed by the caller (3.1f2)
    output_token_cap: int              # > 0; == LLMRequest.max_tokens
    task_id: uuid.UUID | None = None
    agent_run_id: uuid.UUID | None = None
    agent_id: str | None = None
    # __post_init__: ValueError when bounds are out of range, or agent_run_id without task_id/agent_id

class UsageContextError(Exception): ...      # task not in project, run not in task
class UsageRecordConflict(Exception): ...    # (call_id, attempt) already stored with other values

def build_row(ctx: UsageCallContext, attempt: AttemptRecord, pricing: PricingTable) -> dict[str, object]:
    """Pure: estimate(partial=attempt.status != "ok"), stored_cost(), retry_count = attempt - 1,
    request_id[:120], tokens from attempt.usage (all None when usage is None)."""

class UsageLedger:
    def __init__(self, sessions: async_sessionmaker[AsyncSession], pricing: PricingTable) -> None: ...
    async def record(self, ctx: UsageCallContext, attempt: AttemptRecord) -> uuid.UUID:
        """Own transaction. Checks the context, then INSERT ... ON CONFLICT (call_id, attempt) DO NOTHING
        RETURNING id; on conflict compares the stored row (status, error_kind, tokens, request_id, model,
        estimated_cost) and raises UsageRecordConflict when it differs. Never swallows an error."""
    def recorder(self, ctx: UsageCallContext) -> AttemptHandler:
        """``on_attempt`` for create_with_retry, bound to one call context."""
```

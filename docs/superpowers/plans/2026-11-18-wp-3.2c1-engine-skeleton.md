# WP-3.2c1 — kerangka engine: rencana implementasi

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun engine tanpa LLM: job `run_task` meng-claim task `draft|queued`, menjalankan langkah terdaftar secara berurutan dan idempoten lewat checkpoint, menjaga lease, dan mengirim ulang task yang pesan antreannya hilang.

**Architecture:**
- `app/workflow/engine.py`: `TaskEngine` + `WorkflowPorts`.
- `app/workflow/dispatch.py`: `Dispatcher` Protocol dan sweep yatim.
- `app/workflow/lease.py`: `claimable`.
- `app/workflow/states.py`: `fail_task`.
- Perakitan di `app/services/orchestrator.py`; job dan beat di `app/worker/`.
- Produksi belum punya langkah (registry kosong), dan gerbang pembuatan 503 tetap tertutup sampai 3.2d.

**Tech Stack:** Python 3.12 asyncio, SQLAlchemy async, PostgreSQL 16, Celery 5 + Redis.

**Spec:** `docs/superpowers/specs/2026-11-17-wp-3.2-workflow-engine-design.md` §14 (Keputusan #37–#45, §14.4a), ditambah §8 #2–#6.

## Global Constraints

- Import-linter tetap: `app.workflow` tidak mengimpor `app.services`/`app.worker`. `services/job_queue.py` mengimplementasikan Protocol milik workflow. `uv run lint-imports` harus bersih.
- Status hanya lewat `transition()`. `error_code` hanya lewat `fail_task`. `checkpoint` hanya diubah per kunci dengan `jsonb_set`, tidak pernah ditimpa utuh.
- Tidak ada sesi DB yang terbuka selama langkah berjalan. Setiap tulisan engine ada di transaksi pendeknya sendiri + `commit_and_publish`.
- Konstanta:
  - `DISPATCH_GRACE_S = 60`, `DISPATCH_SWEEP_SECONDS = 30` (beat `expires` 25);
  - `MAX_PLANNING_ATTEMPTS = 3`, sehingga claim ke-4 menjadi `failed planning_interrupted`;
  - `visibility_timeout = 7200`;
  - `worker_id` = `f"{hostname}:{pid}:{token_hex(4)}"`, ≤ 120 karakter;
  - pipeline: `draft` → `intake`, `context`, `plan`; `running` → `implement`.
- `StepResult` hanya `done`, `fail(error_code, message)`, atau `transition(to, reason)`. Langkah melempar `LeaseLost` bila lease hilang.
- Kode error task baru: `planning_interrupted`, `step_unavailable`.
- Test hanya lewat `/tmp/claude-0/-home-user-IDEE-Application/daa04f0b-5e7a-50f4-90ad-ee39ea239dff/scratchpad/p32-pytest.sh`, satu proses pytest dalam satu waktu. Test yang sensitif waktu diulang 3×.
- Perintah dari `backend/`: `uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run lint-imports`.

## Review Focus

1. **Dua delivery `run_task` untuk task yang sama secara bersamaan** menghasilkan tepat satu eksekusi langkah. Test di Task 3 (`test_duplicate_delivery_single_execution`).
2. **Worker mati di tengah langkah** (lease habis): delivery berikutnya melanjutkan dari langkah yang belum selesai dan tidak mengulang yang sudah selesai. Test di Task 3 (`test_resume_skips_completed_steps`).
3. **Task yang dibatalkan dari luar saat langkah berjalan** (mis. hapus project): engine tidak menulis transisi apa pun sesudahnya dan melepas lease. Test di Task 3 (`test_external_cancel_between_steps`).
4. **Sweep berjalan bersamaan dengan claim**: task yang sedang di-lease tidak pernah dikirim ulang, dan `SKIP LOCKED` tidak membuat kandidat hilang selamanya. Test di Task 4 (`test_skip_locked_candidate_returns_later`).
5. **Draft lama tanpa `checkpoint.dispatch`** tidak pernah dikirim sweep. Test di Task 4 (`test_never_dispatched_tasks_are_ignored`).

### Task 3: `TaskEngine`

**Files:**
- Create: `backend/app/workflow/engine.py`
- Test: `backend/tests/integration/test_engine.py`

**Interfaces:**
- Consumes: `claim_lease(claimable=...)`, `renew_lease`, `release_lease`, `LeaseLost` (`lease.py`); `transition`, `fail_task`, `Actor` (`states.py`); `emit_task_event`, `commit_and_publish` (`core/events.py`).
- Produces:
  - `StepResult` (`done()`, `fail(error_code, message)`, `transition(to, reason)`);
  - `Step = Callable[[StepContext], Awaitable[StepResult]]`, dengan `StepContext(task_id, project_id, step, checkpoint: Mapping)`;
  - `@dataclass class WorkflowPorts(sessions, bus, audit, worker_id: str, max_active: int, steps: Mapping[str, Step], heartbeat_s: float = HEARTBEAT_SECONDS)`;
  - `PIPELINE: Mapping[str, tuple[str, ...]] = {"draft": ("intake", "context", "plan"), "running": ("implement",)}`;
  - `class TaskEngine: async def run(self, task_id) -> EngineOutcome`. `EngineOutcome` memuat `claim: ClaimResult` dan `ran: list[str]` (langkah yang dijalankan di delivery ini), serta `stopped: str | None` (`lease_lost`, `status_changed`, `planning_interrupted`, …).
- Alur `run`:
  1. Claim dengan `claimable={"draft","queued"}` di satu transaksi: `queued` → `running`; `draft` → `planning_attempts += 1`. Claim ke-4 → `fail_task(planning_interrupted)` dan lepas lease.
  2. Untuk setiap langkah `PIPELINE[status]` yang tidak ada di `completed_steps`:
     - perpanjang lease dan baca ulang status (berubah → lepas lease, berhenti);
     - set `current_step` dan emit `task.step_started`;
     - jalankan langkah dengan heartbeat latar;
     - `done` → tambah `completed_steps`, emit `task.step_finished {step, status:"done"}`;
     - `fail` → `fail_task`;
     - `transition` → `transition()`, lalu berhenti (status baru dibaca delivery berikutnya bila claimable).
     - Langkah yang tidak terdaftar → `fail_task(step_unavailable)`.
  3. Akhir: lepas lease, kecuali lease sudah hilang.
- `LeaseLost` (dari langkah atau dari heartbeat) → batalkan langkah dan berhenti tanpa tulisan lain.

- [ ] **Step 1: Write the failing tests** (langkah palsu, DB nyata, heartbeat kecil)

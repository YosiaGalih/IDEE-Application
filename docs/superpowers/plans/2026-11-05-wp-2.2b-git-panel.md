# WP-2.2b Git Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Panel git di kolom kiri workspace. Isinya: ringkasan repo, daftar perubahan dengan checkbox, diff di dialog, commit dengan path eksplisit, buat branch, dan log commit. Semua dibangun di atas API git 2.1c.

**Architecture:**
- Klien git dengan skema Zod ada di `src/api/git.ts`; hook TanStack ada di `src/api/hooks/useWorkspace.ts`.
- Komponen ada di `src/features/workspace/git/`.
- `WorkspacePage` mendapat toggle Explorer/Git. Kedua tampilan tetap ter-mount dan yang tidak dipilih memakai `hidden`.
- Pemilihan file untuk commit adalah fungsi murni yang bisa dites tanpa layar.

**Tech Stack:** React 19, TypeScript strict, TanStack Query 5, Zod 4, i18next, Vitest + RTL + MSW.

**Spec:** `docs/superpowers/specs/2026-11-05-wp-2.2b-git-panel-design.md`

## Global Constraints

- Teks UI hanya lewat kunci i18n. Kunci `id.json` dan `en.json` harus sama. Kunci diketik (`typecheck` menolak kunci yang tidak ada).
- Isi repo (path, nama branch, pesan, author, baris diff) dirender sebagai teks React; tidak ada HTML atau Markdown.
- Status selalu berupa teks + ikon, tidak cukup warna. Baris diff add/del punya kolom `+`/`−`.
- `POST /git/commit` selalu membawa `paths` eksplisit (≥ 1), tidak pernah `null`. Pesan maksimal 5000 karakter dan tidak boleh kosong atau hanya spasi.
- Log memakai `limit` dengan urutan 20 → 50 → 100 → 200 (maksimal API 200).
- Satu `Idempotency-Key` per niat commit atau branch: tetap setelah hasil tidak pasti, diganti saat input berubah atau setelah berhasil.
- Izin:
  - tampilan Git butuh `git:read`;
  - form commit butuh `canWrite` dari 2.2a (`workspace:write` + project `active` + repository siap);
  - form branch butuh `git:branch` + project `active` + repository siap.
- Check frontend: `npm run format:check && npm run lint && npm run lint:guards && npm run typecheck && npm test`, `npx vite build`, `npm audit --omit=dev --audit-level=high`.

## Review Focus

1. Status dibaca ulang sambil form commit terbuka: file yang dihapus user dari pilihan tetap tidak dipilih, file baru ikut tercentang, file yang hilang keluar dari `paths` → Task 2 `reconcileSelection` dan Task 4 `commits only the files that are listed and ticked`.
2. Commit tanpa jawaban lalu diulang → `Idempotency-Key` yang sama; pesan diubah → key baru → Task 4 `retries an unknown commit with the same key`.
3. Diff berisi `<script>`/markup di baris atau path → tampil sebagai teks → Task 3 `renders diff lines as text`.
4. Diff `truncated` dengan 0 file → "dipotong" dan bukan "tidak ada perubahan" → Task 3 `never calls a cut diff empty`.
5. Branch dengan nama cadangan (`kk/x`) → ditolak di klien dengan teksnya, tanpa request → Task 4 `refuses reserved branch names before asking`.

### Task 1: Klien git dan hook

**Files:**
- Create: `frontend/src/api/git.ts`
- Modify: `frontend/src/api/hooks/useWorkspace.ts`
- Test: `frontend/src/api/__tests__/git.test.ts`

**Interfaces:**
- Produces (git.ts):
  - `type GitDiff = {base: string; head: string | null; files: DiffFile[]; stats: {files: number; additions: number; deletions: number}; truncated: boolean}`
  - `type DiffFile = {path; old_path: string|null; status: "added"|"modified"|"deleted"; additions; deletions; is_binary; hunks: DiffHunk[]}`
  - `type DiffHunk = {header; old_start; old_lines; new_start; new_lines; lines: {type: "context"|"add"|"del"; old_no: number|null; new_no: number|null; text: string}[]}`
  - `type Branch = {name: string; head: string; is_task_branch: boolean}`
  - `type LogEntry = {commit: string; author: string; date: string; message: string}`
  - `getGitDiff(projectId, path: string | null, signal?) → Promise<GitDiff>`: query `?path=` only when non-null
  - `getBranches(projectId, signal?) → Promise<Branch[]>`
  - `getGitLog(projectId, limit: number, signal?) → Promise<LogEntry[]>`
  - `createBranch(projectId, {name, from: string | null}, idempotencyKey: string) → Promise<{name; head}>`: body `{name}` plus `from` only when non-null
  - `commitChanges(projectId, {message, paths: string[]}, idempotencyKey: string) → Promise<{commit: string}>`
  - `isReservedBranch(name: string) → boolean`: `kk`, `HEAD`, `kk/…`, `refs/…` (mirror of the backend `_reserved_branch`)
- Produces (useWorkspace.ts): `gitLogKey(projectId)`, `branchesKey(projectId)`, `useGitDiff(projectId, path|null)` (`staleTime: 0`, `gcTime: 0`: setiap dialog membaca ulang), `useBranches(projectId, enabled)`, `useGitLog(projectId, limit, enabled)`
- Sha/commit hex di-regex `^[0-9a-f]{40}$` (commit) dan memakai skema yang sama untuk `head`.

- [ ] **Step 1: Write the failing tests** `git.test.ts` (MSW):
  - `reads a file's diff and the whole working tree`: `getGitDiff(p, "a b.py")` memanggil `?path=a+b.py`; `getGitDiff(p, null)` tanpa `path`.
  - `refuses a diff whose shape is unknown`: satu baris dengan `type: "weird"` → reject `ApiError` `kind: "bad_response"`.
  - `commits explicit paths with the given key`: request body `{message: "m", paths: ["a.py"]}`, header `Idempotency-Key: k-1`.
  - `creates a branch from a ref, and from HEAD when none is given`: body `{name: "fitur", from: "main"}`, lalu `{name: "fitur2"}` tanpa `from`.
  - `reads branches and the log with its limit`: `?limit=50`.
  - `knows the reserved branch names`: `kk`, `HEAD`, `kk/x`, `refs/x` → true; `fitur/kk` → false.
- [ ] **Step 2:** `npx vitest run src/api/__tests__/git.test.ts` → FAIL (module missing).
- [ ] **Step 3:** Implement git.ts + hooks.
- [ ] **Step 4:** Test hijau.

### Task 4: Panel git

**Files:**
- Create: `frontend/src/features/workspace/git/GitPanel.tsx` (ringkasan, perubahan, commit), `frontend/src/features/workspace/git/GitBranches.tsx`, `frontend/src/features/workspace/git/GitLog.tsx`
- Modify: `frontend/src/i18n/locales/{id,en}.json` (`workspace.gitPanel.*`)
- Test: `frontend/src/features/workspace/git/__tests__/GitPanel.test.tsx`: dirender lewat `renderApp("/", [{ path: "/", element: <GitPanel …/> }])`

**Interfaces:**
- Consumes: Task 1–3; `useGitStatus`, `gitStatusKey`, `workspaceErrorText`, `reasonOf` (2.2a).
- Produces: `GitPanel(props: {projectId: string; canRead: boolean; canCommit: boolean; canBranch: boolean; unsavedPaths: string[]})`.
- Commit berhasil → invalidate `gitStatusKey`, `gitLogKey`, `branchesKey`. Branch berhasil → invalidate `branchesKey`.
- Error: `reasonOf === "nothing_to_commit"` → `gitPanel.commit.nothing`; `"branch_exists"` → `gitPanel.branch.exists`; 422 branch → `gitPanel.branch.invalid`; lainnya `workspaceErrorText(t, e, {unknownOutcome})`.

- [ ] **Step 1: Tests:**
  - `commits only the files that are listed and ticked`: untick `b.py`, status dibaca ulang dengan `c.py` baru → body `paths: ["a.py", "c.py"]`; tampil "Commit 1234567 dibuat"; status dan log dibaca ulang.
  - `retries an unknown commit with the same key`: PUT pertama `HttpResponse.error()` → teks belum pasti; ulang → key sama; pesan diubah → key berbeda.
  - `says when there is nothing to commit`: 409 `nothing_to_commit` → teksnya; tidak ada "dibuat".
  - `warns that unsaved tabs are not in the commit`: `unsavedPaths: ["a.py"]` → peringatan memuat `a.py`.
  - `creates a branch and says the working tree stays where it is`: `from: "main"`; 409 `branch_exists` → teksnya.
  - `refuses reserved branch names before asking`: `kk/x` → teks cadangan, 0 request.
  - `loads more log entries up to the API's limit`: limit 20 → 50 → … → 200, lalu teks batas.
  - `shows only what the user may do`: tanpa `canCommit`/`canBranch` → tidak ada form; `canRead: false` → `permission_denied`.
  - `keeps the change list it read when status cannot be read again, and says so`.
  - `says the tree is clean, with the branch and head`: `clean: true` → teks bersih + `main` + 7 karakter head.
  - `allows a commit only with a message and at least one file`: pesan hanya spasi atau 0 file tercentang → tombol nonaktif.
  - `marks the current branch and task branches`: `status.branch` → "aktif"; `is_task_branch` → "task".
- [ ] **Step 2–4** → **Step 5: Commit** `feat(web): git panel (WP-2.2b)`.

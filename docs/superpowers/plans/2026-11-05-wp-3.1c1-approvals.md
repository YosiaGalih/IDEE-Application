# WP-3.1c1 Approvals Core + Hapus Project — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Approval R3 terikat hash payload, sekali pakai, berkedaluwarsa, dengan handler ADR-024, dan hapus project sebagai aksi R3 pertama dari ujung ke ujung.

**Architecture:** Empat modul service yang tidak saling melingkar: `approval_store` (primitif tanpa otorisasi: hash, buat, supersede, konsumsi, kedaluwarsa), `approval_handlers` (registry + dispatch + sweep), `project_delete` (permintaan, handler, purge), `approvals` (baca + keputusan untuk API). `projects.update_project` hanya memanggil `approval_store`. Worker menjalankan sweep dan purge lewat beat.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, PostgreSQL 16, Celery beat, pytest.

**Spec:** `docs/superpowers/specs/2026-11-05-wp-3.1c-approvals-design.md` (bagian 3.1c1 dan Keputusan Lead).

## Global Constraints

- Migrasi `0007_approvals`, `down_revision = "0006_agents"`.
- `action_type` CHECK: `apply_changes, budget_increase, tool_r3, project_delete, deploy_staging, deploy_production, git_push, waive_criterion`.
- `status` CHECK: `pending, approved, rejected, expired, consumed, superseded`; `handler_status`: `pending, succeeded, failed, not_required`.
- `EXPIRY`: `apply_changes` 7 hari; `budget_increase`, `tool_r3`, `git_push`, `deploy_staging` 24 jam; `deploy_production` 4 jam; `project_delete` 7 hari. `waive_criterion` tidak punya entri (tidak pernah dibuat).
- Payload `project_delete` = `{"project_id": str, "name": str, "previous_status": "active"|"archived"}`; `risk_level` 3.
- `requested_by` pola `^(user:[0-9a-f-]{36}|system:[a-z_]{1,40})$`. `decision_note` ≤ 2000.
- Retry handler: maksimal 5 percobaan, jeda sesudah percobaan ke-n `BACKOFF = (30s, 2m, 10m, 1h)`; dihitung dari `approvals.updated_at`.
- Purge sesudah 7 hari dari `projects.deleted_at`.
- Tanpa kode error baru: 409 `APPROVAL_PAYLOAD_MISMATCH`, 409 `INVALID_TRANSITION` (+ `details[0].reason`), 404 di luar scope, 403 di dalam scope tanpa izin.
- Semua waktu dari parameter `now: datetime | None = None` (default `datetime.now(UTC)`); query membandingkan dengan nilai `now` itu, bukan `now()` SQL. Tanpa dependensi baru.
- Setiap file service/route yang disentuh di `services/projects.py`, `routes/projects.py`, `api/deps.py`, `main.py` → review delta AG-13 (syarat WP-2.1a).

## Review Focus

1. Dua `DELETE` bersamaan untuk project yang sama → tepat satu approval terbuka (index unik parsial), yang kedua mendapat approval yang sama. → Task 4 `test_concurrent_deletes_make_one_approval`.
2. Dua keputusan bersamaan atas approval yang sama → satu berhasil, yang lain 409 `INVALID_TRANSITION`. → Task 5 `test_concurrent_decisions_one_wins`.
3. Handler gagal sesudah keputusan di-commit (mis. DB putus) → keputusan tetap, `handler_status=failed`, sweep menyelesaikannya kemudian. → Task 3 `test_failed_handler_keeps_decision_and_sweep_finishes_it`.
4. Folder workspace berisi symlink ke luar root saat purge → hanya folder project yang hilang, target symlink utuh. → Task 4 `test_purge_does_not_follow_symlinks`.
5. Developer (punya `approval:decide`, tidak punya `project:delete`) mencoba menyetujui hapus project → 403, approval tetap `pending`, dan approval itu tidak muncul di daftar `pending`-nya. → Task 5 `test_developer_cannot_approve_delete`.

### Task 3: `approval_handlers` — registry, dispatch, sweep

**Files:**
- Create: `backend/app/services/approval_handlers.py`, `backend/tests/integration/test_approval_handlers.py`

**Interfaces:**
- Consumes: Task 2; `ProjectEnv`.
- Produces:
  - `class ApprovalHandler(Protocol)`: `async def approved(self, approval_id: uuid.UUID, *, now: datetime) -> None`, `rejected(...)`, `expired(...)`. Masing-masing membuka session sendiri, idempotent, commit sendiri.
  - `Handlers = Mapping[str, ApprovalHandler]`; `MAX_ATTEMPTS = 5`; `BACKOFF: tuple[timedelta, ...]`.
  - `async dispatch(*, sessions, audit, handlers: Handlers, approval_id: uuid.UUID, now=None) -> str` (revisi: hanya butuh sessions dan audit) → `handler_status` akhir. Memilih jalur dari `status`; sukses → `succeeded`; exception → `failed`, `attempts+1`, `handler_error` (tipe exception + pesan dipotong 500, lewat redactor), audit `approval.handler_failed`; percobaan ke-5 gagal → juga audit `approval.handler_gave_up`. Tidak pernah melempar.
  - `async sweep(*, sessions, audit, handlers: Handlers, now=None) -> SweepResult(expired: int, dispatched: int, failed: int)`; percobaan pertama langsung jatuh tempo (dispatch ganda aman karena handler idempotent); superseded → `handler_status='not_required'`: `expire_due`, lalu dispatch setiap baris jatuh tempo (`handler_status ∈ {pending, failed}`, `attempts < MAX_ATTEMPTS`, `updated_at + BACKOFF[attempts-1] <= now` untuk attempts ≥ 1), dikunci `FOR UPDATE SKIP LOCKED` saat diambil.
- [ ] **Step 1: Test gagal** dengan handler palsu (mencatat panggilan, bisa diatur gagal N kali):
  - `test_dispatch_success_marks_succeeded`.
  - `test_failed_handler_keeps_decision_and_sweep_finishes_it`: gagal sekali → status tetap `approved`, `failed`, attempts 1, audit `approval.handler_failed`; sweep sebelum 30 dtk tidak memanggil; sesudahnya → `succeeded`.
  - `test_gives_up_after_five`: gagal terus → attempts 5, audit `approval.handler_gave_up` sekali, sweep berikutnya tidak memanggil lagi.
  - `test_sweep_expires_and_dispatches_expired`: pending lewat waktu → `expired` dan handler `expired` dipanggil.
  - `test_unknown_action_type_fails_visibly`: tanpa handler terdaftar → `failed` dengan error "no handler".

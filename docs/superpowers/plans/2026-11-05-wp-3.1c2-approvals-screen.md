# WP-3.1c2 Layar Persetujuan dan Hapus Project — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Layar `/approvals` (mockup screen-11) tempat orang memutus approval R3 yang terikat hash. Termasuk badge jumlah tertunda di navigasi dan aksi "Hapus project" di `/projects`.

**Architecture:**
- Klien API `src/api/approvals.ts` (zod) dan hook TanStack Query di `src/api/hooks/useApprovals.ts`.
- Fitur baru `src/features/approvals/`. Delete project menambah `deleteProject` di `src/api/projects.ts` dan dialog di `ProjectsPage`.
- Backend hanya menambah `project_name` pada respons `Approval`.

**Tech Stack:** React 19, TypeScript, TanStack Query, zod, Radix Dialog, react-i18next, Vitest + RTL + MSW; backend FastAPI (satu field).

**Spec:** `docs/superpowers/specs/2026-11-05-wp-3.1c-approvals-design.md`, bagian "Goals 3.1c2" dan "Keputusan Lead 3.1c2".

## Global Constraints

- **Teks UI:** hanya lewat kunci i18n `src/i18n/locales/{id,en}.json`, kunci keduanya sama (`lint:guards`).
- **Status:** status dan risiko selalu ikon + teks, tidak pernah warna saja (frontend.md).
- **Konten server:** payload, ringkasan, catatan dan peminta dirender sebagai teks. Tidak ada `dangerouslySetInnerHTML`.
- **`payload_hash` keputusan:** persis milik approval yang ditampilkan di dialog, tidak pernah dihitung ulang di klien.
- **Status layar:** setiap layar punya loading, error (dengan request id + coba lagi), empty, 403 (`StateView`).
- **Perintah:** `npm run format:check && npm run lint && npm run lint:guards && npm run typecheck && npm test`, `npx vite build`; backend `ruff`, `pyright`, `lint-imports`, test yang disentuh.

## Review Focus

1. Approval kedaluwarsa atau di-supersede (rename) selama dialog terbuka: 409 dengan teks per `reason`, dialog tertutup, daftar dimuat ulang. Tidak ada "berhasil" palsu.
2. Klik ganda "Setujui": satu permintaan. Tombol nonaktif selama mengirim.
3. Payload berisi teks mirip HTML atau Unicode panjang: tampil sebagai teks, membungkus, tidak merusak tata letak.
4. Badge saat `GET /approvals` gagal: badge tidak tampil (bukan "0" palsu), layar lain tetap jalan.
5. Disetujui tetapi handler gagal: pesan "akan diulang", bukan "dihapus".

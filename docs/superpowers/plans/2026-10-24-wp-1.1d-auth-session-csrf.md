# WP-1.1d Auth, Sesi, CSRF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Endpoint `/api/v1/auth/*` beserta sesi cookie, CSRF double-submit, rate limit, lockout, dan reset password, persis sesuai API_CONTRACTS §2 dan SECURITY_MODEL §8.

**Architecture:**
- Sesi opaque disimpan di PostgreSQL (sha256). CSRF dicek di middleware ASGI untuk semua mutasi dan diikat ke sesi di dependency `current_user`.
- Rate limit memakai fixed window di Redis; lockout memakai kolom `users`.
- Logika ada di `app/services/auth.py`; route tipis.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, asyncpg, redis.asyncio, argon2-cffi, pytest + httpx `ASGITransport` / `TestClient`.

**Spec:** `docs/superpowers/specs/2026-10-24-wp-1.1d-auth-session-csrf-design.md`

## Global Constraints

- **Cookie:**
  - `kk_session`: HttpOnly, `Secure=settings.cookie_secure`, `SameSite=Lax`, `Path=/`, tanpa `Domain`.
  - `kk_csrf`: atribut sama, tanpa HttpOnly.
- **Header** `X-CSRF-Token`. Satu-satunya pengecualian CSRF: `POST /api/v1/auth/login`.
- **Rate limit:** 10 per 60 detik per IP, untuk login, forgot, dan reset (key terpisah).
- **Lockout:** 5 gagal → `locked_until = now + 15 menit`, counter kembali 0.
- **Sesi:** idle `SESSION_TTL_HOURS` (12), absolut `SESSION_ABSOLUTE_DAYS` (7). `last_seen_at` ditulis paling sering sekali per 60 detik.
- **Token reset:** 30 menit, sekali pakai. Reset mencabut semua sesi; change mencabut sesi lain.
- **Password:** 12–1024 karakter (`validate_new_password`).
- **Kode error:**
  - `UNAUTHENTICATED`, `SESSION_EXPIRED` (401);
  - `CSRF_FAILED`, `FORBIDDEN` (403);
  - `RATE_LIMITED` (429, `Retry-After`);
  - `BAD_REQUEST` (400);
  - `DEPENDENCY_UNAVAILABLE` (503).
- **Pesan login gagal tunggal:** `"Invalid email or password"`. Kode dalam bahasa Inggris; UI menerjemahkan.
- **Audit:** `auth.login` (success/denied, `metadata.reason`), `auth.logout`, `auth.lockout`, `auth.password_reset_requested`, `auth.password_reset`, `auth.password_change`.
- **Tidak boleh muncul** di response, log, atau audit: password, hash, token sesi, token reset. Pengecualian: `reset_path` di log saat `APP_ENV=development`.

## Review Focus

1. **Dua password salah bersamaan saat counter = 4** → terkunci tepat sekali dan counter konsisten (UPDATE atomik). Test: `test_concurrent_failures_lock_once` (Task 3).
2. **Redis mati saat login** → 503 `DEPENDENCY_UNAVAILABLE`; tidak boleh lolos tanpa rate limit dan tidak boleh 500. Test: `test_login_fails_closed_without_redis` (Task 3).
3. **Cookie sesi valid milik user `disabled`** → 401. Test: `test_disabled_user_session_is_rejected` (Task 3).
4. **Email beda huruf/spasi** → akun yang sama. Respons untuk email tak dikenal identik dengan password salah (kecuali `request_id`). Test: `test_failure_responses_are_identical` (Task 5).
5. **Token reset dipakai dua kali bersamaan** → hanya satu yang sukses (`FOR UPDATE`). Test: `test_reset_token_single_use_under_race` (Task 4).

# WP-2.1e Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /api/v1/dashboard` plus the `/` screen: metrics, recent projects and tasks, an attention queue, and quick create, all within the user's scope. Agent activity and usage show as "tidak tersedia".

**Architecture:**
- One read-only service, `services/dashboard.py`, reads one `REPEATABLE READ` snapshot.
- Project visibility comes from one shared filter in `services/projects.py`, used by `list_projects` too.
- A thin route `api/routes/dashboard.py` serves it, and the screen `features/dashboard/DashboardPage.tsx` reads it through `api/dashboard.ts` (Zod) and `api/hooks/useDashboard.ts`.

**Tech Stack:**
- Backend: FastAPI, SQLAlchemy 2 async (PostgreSQL 16).
- Frontend: React 19, TanStack Query 5, Zod, i18next; tests with Vitest + RTL + MSW.

**Spec:** `docs/superpowers/specs/2026-11-04-wp-2.1e-dashboard-design.md` (conflict #70).

## Global Constraints

- **Envelope:** `{request_id, status, data, error, meta}`, with `Cache-Control: no-store`.
- **Visibility:** owner OR project-scoped grant, and `status != 'deleted'`. The rule lives in one function only: `visible_projects_filter(actor)`.
- **Status writes:** the dashboard never writes `tasks.status`; the guard test `tests/unit/test_status_writer_guard.py` stays green.
- **Unavailable data:** never shown as 0. `meta.unavailable == ["agent_activity", "usage"]`; `usage.cost_status == "unavailable"`; tokens and cost are `null`.
- **Limits:**
  - `RECENT_PROJECTS = 5`, `RECENT_TASKS = 10`, `FAILED_QUEUE = 10`;
  - `ATTENTION_STATUSES = ("failed", "interrupted", "needs_changes", "waiting_approval")`;
  - `RUNNING_STATUSES = ("running", "validating")`.
- **Usage period:** the UTC calendar month, `[start, end)`, ISO 8601 with offset.
- **UI text:** i18n keys only (`dashboard.*`, the same keys in `id.json` and `en.json`). Status is always text + icon. Costs are labelled "tidak tersedia".
- **Checks:**
  - backend: ruff, `ruff format --check`, pyright 0, lint-imports, `pytest -q`;
  - frontend: `format:check`, `lint`, `lint:guards`, `typecheck`, `npm test`.

## Review Focus

1. **Another user's tasks inside a visible project's count.** Counts must join tasks to visible projects, never filter by `created_by`. Test: user B creates a task in A's project (via a grant); it counts for A and for B.
2. **A project-scoped role on a deleted project.** It must not count. Test in `test_dashboard_scope.py`.
3. **A Zod mismatch on one field.** The page must show the error state, not an empty dashboard. Test in `DashboardPage.test.tsx`.
4. **The search box filters, never refetches.** No request per keystroke. Test: the request count stays 1.
5. **Month boundary.** `period` for a time on the last second of a month. Unit test of `current_period(now)`.

### Task 2: Dashboard service and route

**Files:**
- Create: `backend/app/services/dashboard.py`, `backend/app/api/routes/dashboard.py`
- Modify: `backend/app/api/router.py` (include the router at prefix `/dashboard`)
- Test: `backend/tests/integration/test_dashboard_api.py`, `backend/tests/unit/test_dashboard_period.py`

**Interfaces:**
- Consumes: `visible_projects_filter`; `projects.list_projects(env, actor, status="active", page_size=RECENT_PROJECTS)`; `ProjectOut.of` (route); `ProjectEnv`.
- Produces:
  - `TaskSummaryView` (frozen dataclass): `id`, `project_id`, `project_name`, `title`, `status`, `status_reason`, `current_step`, `workflow_type`, `priority`, `iteration`, `created_at`, `updated_at`. `has_pending_approval` is derived as `status == "waiting_approval"`.
  - `Dashboard` (frozen dataclass): `metrics: dict[str, int]`, `recent_projects: list[ProjectView]`, `recent_tasks: list[TaskSummaryView]`, `failed_queue: list[TaskSummaryView]`, `failed_queue_total: int`, `period: tuple[datetime, datetime]`.
  - `current_period(now: datetime) -> tuple[datetime, datetime]`.
  - `async def load_dashboard(env: ProjectEnv, actor: Actor) -> Dashboard`.
  - Route `GET /api/v1/dashboard` (`CurrentActor`). Its `data` follows the spec §1 and `meta = {"unavailable": ["agent_activity", "usage"], "failed_queue_total": n}`.

- [ ] **Step 1:** Write the tests.
  - `test_current_period_is_the_utc_month`:
    - `2026-11-30T23:59:59Z` → `(2026-11-01T00:00Z, 2026-12-01T00:00Z)`;
    - `2026-12-15` → `(2026-12-01, 2027-01-01)`;
    - a non-UTC input is converted first.
  - `test_dashboard_counts_tasks_by_status`: tasks walked with `workflow.states.transition` (helper `walk` as in `test_task_transition.py`) to running, validating, completed, failed, waiting_approval, interrupted, needs_changes, draft. Assert:
    - metrics `{active_projects: 1, running_tasks: 2, completed_tasks: 1, failed_tasks: 1, waiting_approval: 1}`;
    - `failed_queue` statuses = {failed, interrupted, needs_changes, waiting_approval};
    - `meta.failed_queue_total == 4`;
    - `has_pending_approval` true only for waiting_approval;
    - each item's `project_name` and `usage == {"input_tokens": None, "output_tokens": None, "estimated_cost": None, "cost_status": "unavailable"}`.
  - `test_dashboard_lists_are_ordered_and_capped`: 12 tasks → 10 recent, ordered by `updated_at` desc; 6 projects → 5 recent; an archived project's task is counted, but the project is not in `recent_projects`.
  - `test_dashboard_marks_what_is_not_recorded`:
    - `agent_activity == []`;
    - `meta.unavailable == ["agent_activity", "usage"]`;
    - usage tokens and cost are `None`;
    - `period` is the current month;
    - `Cache-Control: no-store`.
  - `test_dashboard_needs_a_session`: no cookie → 401.
  - `test_dashboard_for_a_new_user_is_empty`: all metrics 0, empty lists, still 200.
- [ ] **Step 2:** Run the tests. Expected: FAIL (route 404 / module missing).
- [ ] **Step 3:** Implement `load_dashboard`.
  - One session started with `REPEATABLE READ, READ ONLY` (as `_search_symbols` in `repo_index.py`).
  - Queries:
    - the project count;
    - one `GROUP BY tasks.status` joined to `projects` under the filter;
    - recent tasks: join, order by `(updated_at desc, id)`, limit 10;
    - queue: status in the attention statuses, limit 10, plus its count.
  - `recent_projects` comes from `list_projects` (its own session; it may be a moment newer, which is acceptable and noted in a comment).
  - The route: `TaskSummaryOut`/`DashboardOut` pydantic models, plus `_respond` with `no-store`.
- [ ] **Step 4:** Run the tests. Expected: PASS. Also run `tests/unit/test_status_writer_guard.py`.

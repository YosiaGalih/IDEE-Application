# WP-3.2c2c1: pagar engine sebelum pemanggil pertama (rencana implementasi)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Engine harus terpagar sebelum `build_agent_runtime` mendapat pemanggil produksi pertama (3.2c2c2). Yang dikerjakan:
- langkah tahu fase pipeline-nya (`StepContext.pipeline`);
- owner lease delivery dapat dicabut per proses, sehingga tidak ada perpanjangan lease sesudah overrun pembersihan atau heartbeat menyerah;
- cancel dari luar ditahan sampai langkah selesai: langkah tidak pernah dibatalkan dua kali, dan lease tidak pernah dilepas selama langkah hidup;
- server memutus transaksi yang diam > 30 dtk (`idle_in_transaction_session_timeout`);
- guard statis memastikan hanya modul allowlist yang menyebut `transition`/`fail_task` dan penanda `kk.status_writer`;
- `RunStore.finish` hanya menutup baris dengan token start run itu.

**Architecture:** Perubahan kode ada di:
- `app/workflow/lease.py`: `revoke_lease_owner`, pemeriksaan di `renew_lease`;
- `app/workflow/engine.py`: `Pipeline`, `StepContext.pipeline`, pencabutan di overrun dan `_give_up`, loop tahan `_settle`;
- `app/core/db.py`: GUC ketiga di `bound_transaction`;
- port `RunStore.finish` di `app/agents/runtime.py`, `AgentRunWriter.finish` di `app/services/agent_runtime.py`.

Ditambah fixture autouse di `tests/conftest.py` dan guard di `tests/unit/test_status_writer_guard.py`. Tidak ada migrasi, env, dependensi, maupun kontrak import-linter baru.

**Tech Stack:** Python 3.12 asyncio, SQLAlchemy async + asyncpg, PostgreSQL 16, Celery 5 (prefork).

**Spec:** `docs/superpowers/specs/2026-11-17-wp-3.2-workflow-engine-design.md` §16.6.1–§16.6.3 (Keputusan #82–#88). Engine yang sudah dibangun: §16.5, §16.5a, §16.5b. ## Review Focus

1. **Pencabutan owner.** Sesudah overrun pembersihan atau heartbeat menyerah dan cancel luar (BC-7, R-C1), keempat jalur perpanjangan melempar `LeaseLost`/`LeaseLostError` tanpa `UPDATE tasks`: `LeaseGuard.hold`, `_locked`, heartbeat engine, dan `LeaseHeartbeat` runtime. Langkah yang terus `hold` di pembersihan tidak menahan lease: lease kedaluwarsa, recovery mengambil task, dan engine menulis nol baris. Test di Task 2.
2. **Cancel luar ditahan.** Di jendela `notice`, `gather`, dan jalur normal:
   - lease tidak dilepas selama langkah hidup;
   - langkah menerima tepat satu `CancelledError`;
   - `run()` melempar `CancelledError` sesudah langkah selesai;
   - `uncancel()` tidak dipanggil.
   - Test di Task 3.
3. **Idle timeout.** Black hole sesudah `LeaseGuard.hold` dan sesudah `_locked`: baris dapat di-lock lagi dalam ≤ batas + toleransi, sementara klien masih macet. Kontrol `"0"` tetap terkunci. Test di Task 4.
4. **Guard statis.** Alias, ekspor ulang lewat `app.workflow.engine`, akses atribut modul, `getattr` literal, `import *`, dan penanda hasil konkatenasi tertangkap. `StepResult.transition` tidak ditandai. Allowlist sama persis dengan perujuk hari ini. Test di Task 5.
5. **`finish` terikat token.** Token, task, atau agent lain (juga token `None`) tidak menutup baris dan tidak meng-emit event. Payload dan kolom pada token yang benar tidak berubah (karakterisasi). Test di Task 5.

## Keputusan Lead 3.1e2

1. **Izin di klien hanya untuk tampilan.** `GET /auth/me` sudah mengembalikan izin efektif dari role global. Sidebar dan landing membacanya lewat satu helper (`hasPermission`); server tetap satu-satunya penegak (403 → state `permission_denied`).
2. **"Pemegang `settings:*`"** = pemegang salah satu izin global halaman pengaturan: `settings:providers` (Provider), `usage:read_all` (Usage), `admin:users` (Users), `admin:policies` (Policies), `audit:read` (Audit). Item sidebar "Pengaturan" mengarah ke `/settings` dan hanya tampil bagi mereka. Landing menampilkan bagian yang boleh dibuka; tanpa satu pun → `permission_denied`.
3. **Warna readiness dari `effective`**, bukan `report_ready` (syarat 3.1e1): siap = hijau; `not_ready` = merah; `disabled` dan `unknown` = abu/kuning dengan alasan dari kunci i18n. `readiness_not_required` tampil sebagai peringatan jelas.
4. **Smoke test:** mutasi tanpa retry, batas klien 60 dtk (`timeoutMs`).
   - `200` → laporan.
   - `202` → "masih berjalan", lalu readiness dibaca ulang tiap 3 dtk sampai `job_id` laporan = job ini (selesai), atau `running_job_id` bukan job ini lagi (berakhir tanpa laporan; lihat audit).
   - `409` → smoke lain berjalan.
   - `429` → batas per jam.
   - `503` dan timeout klien → state yang sesuai, tanpa klaim hasil.
5. **Label check dari kunci i18n** (`providers.checks.<key>`). `detail` adalah data server (sudah diredaksi) dan ditampilkan apa adanya, tidak pernah sebagai HTML.
6. **Kalimat penutup pernyataan data flow.**
   - SECURITY_MODEL §7: "Anda dapat menonaktifkan pemanggilan provider per project di Settings."
   - Belum ada layar pengaturan project (non-goal 3.1e). Layar ini memang punya sakelar `enabled` untuk seluruh platform.
   - Teks di layar menyebut apa yang ada: sakelar platform di halaman ini, dan penghentian per project lewat pengaturan project (API; layarnya menyusul).
   - Dilaporkan ke konflik #72.

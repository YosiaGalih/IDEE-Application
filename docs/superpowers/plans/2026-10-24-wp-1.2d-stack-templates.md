# WP-1.2d Stack detection + templates — Implementation Plan (written alongside the code)

> Process note: this plan was written together with the implementation, not before it; tests followed the code and were then proven by mutation (tracker §12, WP-1.2d). Recorded as a process deviation.

**Goal:** `detect_stack(workspace) -> Stack` (FR-022, API_CONTRACTS `Stack`) and six project templates that pass their own tests offline (FR-014).

**Spec:** `docs/superpowers/specs/2026-10-24-wp-1.2-workspace-git-design.md` (section 1.2d).

## Decisions fixed here

- **Detection.**
  - Scans the root and one folder level (tree depth 3) through `Workspace` with `AGENT_READ`, so the denylist and the 256 KiB limit apply.
  - Executes nothing.
  - Ignores markers that fail to parse.
  - Outputs sorted lists.
- **Python.**
  - Markers: `pyproject.toml`, `setup.py`, `setup.cfg`, `Pipfile`, `requirements*.txt`, or `.py` files.
  - Package manager comes from the lockfile. `pip` is used only for a folder that has a marker, or for the root.
  - Framework is fastapi, flask or django (django also via `manage.py`).
  - `python.pytest` is set when one of these is true: pytest is a dependency, `[tool.pytest]` exists, or the repo uses the `tests/`, `test_*.py`, `conftest.py` or `pytest.ini` layout.
- **Node.**
  - Marker: `package.json`. Package manager comes from the lockfile or `packageManager`; the default is npm.
  - Framework is express, next, react, vite or vue.
  - TypeScript is detected from `tsconfig.json` or the `typescript` dependency.
  - `node.npm_test` is set when `scripts.test` exists and is not npm's default placeholder.
- **Others.** Go, Rust and Java are recorded as languages only, with no profiles; packs arrive in v2.2.
- **Templates.**
  - Each lives in `app/workspace/templates/<id>/` with `template.toml`.
  - Materialising is a copy plus `str.replace` of `{{project_slug}}` everywhere and `{{project_name}}` in `.md`/`.html` only.
  - The slug must match `^[a-z0-9][a-z0-9-]{0,62}$`. The name is 1–120 characters with no CR, LF or NUL.
  - `templates/` is excluded from backend ruff and pyright; `test_templates.py` lints it as the generated project.

## Tests

- `tests/unit/test_stack.py`
- `tests/integration/test_templates.py`. Every template is materialised and its tests run offline: pytest + ruff for Python, `npm test` for Node.

# WP-2.1b Archive Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user creates a project from a zip/tar/tar.gz archive; the archive is streamed to disk, extracted safely by a worker into a fresh git repository, and the UI shows upload progress and the import outcome.

**Architecture:** `POST /projects` gains `source: upload` (project in `importing`, no folder). `POST /projects/{id}/imports` streams one multipart file to `<id>/uploads/<job_id>.archive` under a per-project Redis lock and enqueues `platform_jobs.import_archive` through a `JobQueue` port. The worker runs `services.project_imports.run_import` (WP-1.2b `import_archive` → `git init` + commit → stack → `ready`, or `error` with a code). Reads report an `importing` project without a lock as `import_incomplete`.

**Tech Stack:** FastAPI + `python-multipart` 0.0.32 (streaming `MultipartParser`), SQLAlchemy async, Redis, Celery (`send_task`), React 19 + TanStack Query, XHR for upload progress.

**Spec:** `docs/superpowers/specs/2026-11-02-wp-2.1b-archive-import-design.md`

## Global Constraints

- Archive ≤ 200 MiB (`IMPORT_MAX_BYTES = 200 * 1024 * 1024`); extraction limits are `ArchiveLimits()` defaults (ADR-005). Caddy already allows 210 MB on `^/api/v1/projects/[^/]+/imports$`.
- No body buffering for `/imports`: not in memory, not in `/tmp`. Other routes keep the 10 MB idempotency buffer.
- `repository.error` holds codes only: `archive_rejected:<reason>`, `import_git_failed`, `import_failed`, `import_not_started`, `import_incomplete`.
- 409 `CONFLICT` reasons: `repository_not_empty`, `not_an_upload_project`, `import_running`, `project_archived`.
- Lock: Redis `kk:import:<project_id>`, value `job_id`, `SET NX EX 2700`; released only by its owner (compare-and-delete).
- Import rate limit: 10 per user per 3600 s, key `kk:rl:project-import:<user_id>`, fail closed (503).
- Audit actions: `project.import_requested` (route), `project.import` success|error (worker); every event carries `ip` where a request exists.
- `app.api` and `app.services` never import `app.worker` (lint-imports layers); services never import fastapi/starlette.
- UI text only via i18n keys in both `id.json` and `en.json`; `XMLHttpRequest` only under `src/api/`.

## Review Focus

- A client that disconnects mid-upload: no `.part` file and no lock left; the next upload is accepted (test in Task 3).
- Two uploads to the same project at once: exactly one 202, the other 409 `import_running`, one job (Task 3).
- A worker job delivered twice (acks_late redelivery after success): the second run changes nothing (Task 4).
- A filename with path separators, NUL, bidi characters or 1 000 characters: stored sanitized, never part of a path (Task 3).
- An upload whose multipart has the file part after a large text field, or two file parts: 422, nothing stored (Task 3).

### Task 2: Upload acceptance service (lock, sink, finish, abort)

**Files:**
- Create: `backend/app/services/project_imports.py`, `backend/app/services/job_queue.py`
- Modify: `backend/app/services/health.py` (`Dependencies.jobs: JobQueue`)
- Test: `backend/tests/integration/test_project_imports.py`

**Interfaces:**
- Consumes: `projects.authorize`, `projects.Actor`, `projects.ProjectEnv`, `import_lock.lock_key`, `workspace.archive._detect` semantics (zip `PK\x03\x04`/`PK\x05\x06`, gzip `\x1f\x8b`, tar `ustar` at 257).
- Produces:
  - `job_queue.JobQueue` (Protocol): `async def enqueue_import(self, *, project_id: UUID, job_id: UUID, user_id: UUID) -> None`.
  - `job_queue.CeleryJobQueue(redis_url: str)`: `send_task("app.worker.platform_jobs.import_archive", kwargs={...str ids}, queue="ide")` in `asyncio.to_thread`.
  - `project_imports.ImportEnv(projects: ProjectEnv, redis: Redis, jobs: JobQueue, limiter: FixedWindowLimiter | None)`.
  - `async begin_import(env, actor, project_id) -> ImportSlot`. It authorizes `project:write`, applies the rate limit, runs the precheck (409 reasons above), takes the lock with `SET NX`, and creates `<root>/uploads` (0o700). `ImportSlot(project_id, job_id, part: Path, archive: Path)`.
  - `class ArchiveSink`: constructed with `(slot, max_bytes=IMPORT_MAX_BYTES)`. `async write(chunk: bytes) -> None` writes in 1 MiB batches via `to_thread`; past the limit → `AppError("PAYLOAD_TOO_LARGE", http_status=413)`. `async close(filename: str | None) -> UploadInfo` checks magic bytes (→ 400 `UNSUPPORTED_FILE_TYPE` with `details=[{"detected_mime": ...}]`), renames `.part` → `.archive`, and returns `UploadInfo(filename: str, size: int, sha256: str)`.
  - `async finish_import(env, actor, slot, upload) -> ImportAccepted(repository: Repository, job_id: UUID, upload: UploadInfo)`. Under the row lock: recheck, set `sync_state="importing"` and `error=None`, audit `project.import_requested`, commit, then `jobs.enqueue_import`. If the enqueue fails → `sync_state="error"`, `error="import_not_started"`, release, delete, 503 `DEPENDENCY_UNAVAILABLE`.
  - `async abort_import(env, slot) -> None` (idempotent): delete `.part`/`.archive`, compare-and-delete the lock.
  - `clean_filename(raw: str | None) -> str`: basename only (split on `/` and `\`); drop Cc/Cf/Zl/Zp; ≤ 255 code points; empty → `"archive"`.

### Task 3: Route `POST /projects/{id}/imports` and the idempotency stream mode

**Files:**
- Create: `backend/app/api/routes/project_imports.py`
- Modify: `backend/app/api/router.py`, `backend/app/core/idempotency.py` (`stream_paths: re.Pattern[str] | None`), `backend/app/main.py` (pass the pattern), `backend/tests/security/test_cross_project.py` (`ENDPOINTS`, `WRITES`)
- Test: `backend/tests/integration/test_project_imports.py`, `backend/tests/unit/test_idempotency*.py` (existing file for the middleware; add cases)

**Interfaces:**
- Consumes: Task 2 service functions; `require_project_permission("project:write")`.
- Produces: route `POST /projects/{project_id}/imports` → 202 `_respond(..., status="accepted")` with `{repository, job_id, upload:{filename,size,sha256}}`. `_respond` gains a `status` parameter.
- Multipart handling:
  - Content-Type must be `multipart/form-data` with a boundary → else 422.
  - Exactly one part named `file` with a filename; any other part → 422 `VALIDATION_ERROR`, `loc ["body","file"]`.
  - Data of the `file` part goes to the sink.
  - The body is read with `request.stream()` only after `begin_import` succeeded.
  - Any exception, including `ClientDisconnect` and cancellation → `abort_import`, then re-raise.
- Idempotency stream mode: for a path matching `stream_paths`:
  - `Content-Length` is required (else 400 `BAD_REQUEST`) and must be ≤ `IMPORT_MAX_BYTES + 1 MiB` (else 413).
  - Fingerprint = sha256(query ∥ `b"stream"` ∥ content-length).
  - Execute with the original `receive`; never read the body in the middleware.

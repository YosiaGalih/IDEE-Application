# WP-1.2c (🔒) Hardened GitAdapter — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `app/gitops/adapter.py`, the only place the backend runs a process. It runs `git` with:
- a fixed argv;
- a clean env;
- hooks off;
- protocols restricted;
- an **explicit `--git-dir`/`--work-tree`**, so nothing a sandbox can write in a worktree is ever read as git configuration.

It covers the local Git needs of FR-113–116, ADR-016 and AC-09.

**Architecture:**
- **`GitTarget(repo, worktree=None)`** names the tree: the main working tree, or a task worktree.
  - The trusted git dir of a worktree is found by scanning `<repo>/.git/worktrees/*/gitdir`, never by reading `<worktree>/.git`.
- **`_run`** is the single `asyncio.create_subprocess_exec` call site. It has:
  - a timeout (kills the whole process group);
  - a stdout cap;
  - error codes that never contain absolute paths.
- **`diffparse.py`** turns `git diff --raw -z -p` output into the API_CONTRACTS `Diff` shape.
  - Raw entries give exact paths and status; patch blocks follow in the same order.
  - Working-tree diffs use a **temporary index** (a copy of the real one plus `git add -A`). Untracked files appear as `added`, and the user's index is never touched.

**Tech Stack:** git ≥ 2.28 CLI (container: 2.43), asyncio subprocess. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-24-wp-1.2-workspace-git-design.md` (section 1.2c).

## Global Constraints

- **Env** (exactly these keys):
  - `PATH=/usr/bin:/bin`, `HOME=/nonexistent`, `LC_ALL=C`;
  - `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_ATTR_NOSYSTEM=1`;
  - `GIT_OPTIONAL_LOCKS=0`, `GIT_ASKPASS=/bin/false`, `GIT_EDITOR=/bin/false`, `GIT_LITERAL_PATHSPECS=1`;
  - plus per-call `GIT_AUTHOR_*` / `GIT_COMMITTER_*` / `GIT_INDEX_FILE`.
- **`-c` flags on every call:**
  - `core.hooksPath=/dev/null`;
  - `protocol.allow=never`, `protocol.https.allow=always`;
  - `core.fsmonitor=false`, `core.pager=cat`, `core.quotePath=false`;
  - `credential.helper=`;
  - `submodule.recurse=false`;
  - `commit.gpgSign=false`, `tag.gpgSign=false`.
- **Diff/log flags:** `--no-ext-diff --no-textconv --no-color`; commit and merge use `--no-verify`.
- **Limits** [Menebak]: timeout 60 s, stdout ≤ 16 MiB, stderr kept ≤ 2 KiB (logged redacted, never returned).
- **Errors:**
  - `GitError(reason)` → 409 `GIT_ERROR`, `details=[{"reason": reason}]`;
  - `GitInputError(reason)` → 400 `BAD_REQUEST`.
- **Input validation:**
  - Branch: `^[A-Za-z0-9][A-Za-z0-9._/-]{0,199}$`, with no `..`, `//`, `@{`, and no `.lock` / `/` / `.` at the end. Task branches are `kk/task-<8 hex>`.
  - Ref: a branch name or `^[0-9a-f]{7,40}$`.
  - Message: 1–5000 chars, no NUL.
  - Author name: 1–200 chars, no `<>\n\0`. Author email: 3–254 chars, the same characters forbidden.
  - Pathspec: validated like `split_rel`, and always placed after `--`.
- **Never present:** `push`, `fetch`, `clone`, `reset`, `clean`, `--force`. The only exception is `worktree remove --force`.

## Review Focus

1. **Unborn repo** (no commits): `status` gives `head=None`; `diff` of the working tree uses the empty tree as base.
2. **Non-ASCII and space paths** (`docs/café note.md`) appear unquoted in status and diff.
3. **A merge into a working tree with untracked files that the merge would overwrite** → reason `dirty`, nothing changed.
4. **A worktree path whose `.git` file was replaced** by sandboxed code → git still uses the trusted git dir.
5. **A git binary that hangs** → `GitError("timeout")` and the process group is killed (no orphan).

- [ ] **Step 2: Run the tests and see them fail.**
- [ ] **Step 3: Implement.** The diff parser is not fully fixed by the signatures, so it works as follows:
  1. Split stdout on NUL. Pairs `(":<meta>", path)` repeat until an empty token; the rest, joined, is the patch text.
  2. Split the patch text into blocks at lines starting with `diff --git `; block i belongs to raw entry i.
  3. A block containing `Binary files ` or `GIT binary patch` gets `is_binary=True` and no hunks.
  4. In hunks, ` `/`-`/`+` lines advance old/new counters from the `@@` header; `\` lines are skipped.
  5. Counts are taken from the full parse. Hunk lines are emitted while the running text size ≤ `max_bytes`; after that, `truncated=True` and later hunks are dropped.

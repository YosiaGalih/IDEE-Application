# WP-3.2b — SSE dan riwayat event task: rencana implementasi

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /tasks/{id}/events` (SSE) dan `GET /tasks/{id}/events/history` mengirim event task tanpa celah dan tanpa duplikat. Stream harus tahan reconnect, berhenti di status akhir, dan dibatasi. Klien frontend mengenal akhir stream dan membatasi memori.

**Architecture:**
- Satu `TaskEventHub` per proses api (pubsub Redis `kk:task:*`) menyebar pesan ke antrean per stream.
- Generator frame tanpa FastAPI di `app/services/task_events.py` bekerja dengan urutan: listener dulu, replay DB per halaman dengan sesi pendek, merge live dengan dedupe dan gap-fill, cek DB setiap ping, lalu akhir/umur/izin.
- Route di `app/api/routes/tasks.py` membungkus generator dengan `StreamingResponse` dan gerbang slot.

**Tech Stack:** FastAPI/Starlette `StreamingResponse`, SQLAlchemy async, redis-py 8 asyncio pubsub, React 19 + Vitest.

**Spec:** `docs/superpowers/specs/2026-11-17-wp-3.2-workflow-engine-design.md` §13. Ikatannya: Keputusan Lead #27–#36 di §13.2 dan jawaban builder check di §13.5. API §5.1 dan ARCHITECTURE §9 sebagai kontrak.

## Global Constraints

- Lapisan import-linter tetap: `app.api` hanya memanggil `app.services`. Services tanpa FastAPI/Starlette. `app.api` tidak boleh mengimpor `app.workflow` (`FINISHED` diekspor ulang lewat service).
- Tidak ada sesi DB yang dipegang selama stream hidup: setiap query di sesinya sendiri.
- Frame:
  - `id: <seq>\n` hanya untuk event persisten;
  - `event: <type>\n`;
  - `data: <JSON satu baris>\n\n`, isinya `{task_id, seq, type, ts, payload}`, dibangun oleh satu fungsi untuk event dari DB maupun dari Redis;
  - `type` harus cocok `^[a-z][a-z0-9_.]{0,59}$`.
- Ping `: ping\n\n` setiap `PING_INTERVAL_S = 15`.
- Cek izin setiap `AUTH_RECHECK_S = 60`.
- Umur koneksi `MAX_STREAM_S = 3300` (55 menit).
- Replay per halaman `REPLAY_PAGE = 500`.
- Antrean hub `HUB_QUEUE_MAX = 1000`.
- Slot `MAX_STREAMS_PER_USER = 8`, `MAX_STREAMS_TOTAL = 256`. Semua konstanta dapat diganti di test (atribut modul atau parameter).
- Akhir stream: status ∈ `FINISHED` (`completed`, `failed`, `cancelled`, `rejected`) **dan** `cursor == tasks.event_seq` → `event: stream.end` (tanpa `id`), `data: {"task_id": "...", "status": "<status>"}`. Task hilang → `status: null`.
- Header SSE: `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-store`, `X-Accel-Buffering: no`, `X-Request-ID`. Galat sebelum stream memakai envelope JSON.
- Test hanya lewat `/tmp/claude-0/-home-user-IDEE-Application/daa04f0b-5e7a-50f4-90ad-ee39ea239dff/scratchpad/p32-pytest.sh` (DB `kodekantor_test_32`, Redis 14). Satu proses pytest dalam satu waktu.
- Frontend dari `frontend/`: `npm run format:check && npm run lint && npm run lint:guards && npm run typecheck && npm test`.

## Review Focus

1. **Event yang di-commit tanpa publish dan menjadi event terakhir** (penulis `tool_r3`/`project_delete`) tetap sampai ke klien dalam ≤ 1 ping. Test di Task 3 (`test_unpublished_last_event_arrives_on_ping`).
2. **Publish live yang tiba saat replay berjalan** tidak menghasilkan seq ganda maupun lubang. Test di Task 3 (`test_no_duplicate_seq`).
3. **Klien yang putus sebelum byte pertama** tetap melepas slotnya, sehingga user tidak terkunci di 429. Test di Task 4 (`test_slot_released_when_client_never_reads`).
4. **Payload yang memuat `\n`/`\r`** tidak dapat memecah frame atau menyuntik `event:`/`id:` palsu. Ini karena data dikirim sebagai JSON satu baris, dan `type` yang tidak sah tidak dikirim. Test di Task 3 (`test_frame_cannot_be_split`).
5. **Task yang diselesaikan saat stream terbuka.** `stream.end` baru dikirim sesudah `task.status_changed` ke status akhir terkirim. Test di Task 3 (`test_end_after_live_terminal_transition`).

- Produces:
  - `@dataclass(frozen=True) class StreamTimings: ping_s: float = 15; auth_recheck_s: float = 60; max_stream_s: float = 3300`;
  - `async def open_stream(env, actor, task_id) -> None`: pemeriksaan awal (`task:read`) dengan `not_found()`. Dipakai route sebelum respons dimulai.
  - `async def stream_frames(env, settings, hub: TaskEventHub | None, *, session_token: str, actor: Actor, task_id: UUID, after_seq: int, timings: StreamTimings = StreamTimings(), clock=time.monotonic) -> AsyncIterator[str]`. Urutannya:

  - `STREAM_END: Final = "stream.end"`.

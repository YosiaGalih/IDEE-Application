# WP-1.2a (🔒) Safe paths, file operations, atomic patch — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One library layer (`app/workspace`) through which every file read, write, delete, tree listing and patch apply passes, enforcing T2 (workspace escape) and T9 (data loss).

**Architecture:**
- `policy.py` decides what an access may touch.
- `paths.py` validates a relative path, checks `realpath` containment, and opens it component by component from a root fd with `O_NOFOLLOW`.
- `fs.py` (`Workspace`) runs the blocking work in `asyncio.to_thread` under an `flock` on the root dir fd.
- `patches.py` is pure: it parses a unified diff and applies hunks to text.

**Tech Stack:** Python 3.12 stdlib (`os` dir_fd APIs, `fcntl`, `hashlib`, `re`), pytest + pytest-asyncio. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-24-wp-1.2-workspace-git-design.md` (section 1.2a).

## Global Constraints

- **Layering.** `import-linter`: new layer `app.workspace | app.gitops` between `app.workflow` and `app.core`. `app/workspace` imports only stdlib, `app.core.*`.
- **No processes.** No `subprocess`/`asyncio.create_subprocess_*` outside `app/gitops/` (static test).
- **Error codes** (API_CONTRACTS §1):

  | Status | Code |
  |---|---|
  | 400 | `PATH_VIOLATION` |
  | 400 | `BAD_REQUEST` (malformed/unsupported patch) |
  | 404 | `NOT_FOUND` |
  | 409 | `VERSION_CONFLICT` |
  | 409 | `CONFLICT` (patch conflict; `details=[{path, hunk, reason}]`; also `AlreadyExists`) |
  | 413 | `PAYLOAD_TOO_LARGE` |

  Error messages and details never contain absolute paths.
- **Limits:**

  | Limit | Value |
  |---|---|
  | path segment | ≤ 255 bytes |
  | path total | ≤ 4096 bytes |
  | user read | 1 MiB |
  | agent read | 256 KiB |
  | write | 5 MiB per file |
  | diff | ≤ 1 MiB, ≤ 200 files |
  | tree | depth 1–10 (default 3), entries 1–5000 (default 500) |
- **File modes.** New files 0644, new dirs 0755. An existing file keeps `mode & 0o777` (setuid/setgid/sticky dropped).

## Review Focus

1. **Non-ASCII file names** (`docs/café.md`) must read, write and list like ASCII names.
2. **CRLF files** must stay CRLF after a patch.
3. **Empty files** (size 0) have sha256 `e3b0c442…b855`, and a write with `expected_sha256` equal to it succeeds.
4. **Trailing slash** in a path (`src/`) is normalised away, so `tree("src/")` equals `tree("src")`.
5. **Writing where a directory exists** is a `PathViolation` (reason `not_regular`), never a 500.

### Task 2: Safe path resolution and component-wise open

**Files:**
- Create: `backend/app/workspace/paths.py`
- Test: `backend/tests/unit/test_paths.py` (resolution part)

**Interfaces:**
- Consumes: `Access`, `Policy`, `PathViolation`, `WorkspaceNotFound`.
- Produces:
  - `split_rel(rel: str) -> tuple[str, ...]`: validates the string, normalises `.`, empty segments and the trailing `/`, and returns `()` for the root.
  - `resolve(root_real: str, rel: str, access: Access, policy: Policy) -> tuple[str, ...]`: returns the resolved parts. It applies the denylist to both the requested and the resolved parts. `*_WRITE` requires resolved == requested, otherwise `PathViolation("symlink")`.
  - `open_root(root: Path) -> tuple[int, str]`: returns the fd and the realpath of the root.
  - `open_parent(root_fd: int, parts: tuple[str, ...], *, create: bool) -> int`: walks `parts[:-1]` with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` via `dir_fd`.
    - It creates missing dirs with mode 0o755 when `create` is true.
    - `ELOOP`/`ENOTDIR` on a symlink → `PathViolation("symlink")`.
    - A missing component without `create` → `WorkspaceNotFound`.

- [ ] **Step 2: Run the tests and see them fail.** Run `uv run pytest tests/unit/test_patches.py -q`. Expected: ImportError.

- [ ] **Step 3: Implement.** Hunk placement algorithm (not fixed by the signature):
  1. `expected` = the context and `-` lines; `replacement` = the context and `+` lines (EOL-less).
  2. Try `pos = old_start - 1 + delta` (for `old_count == 0`, `pos = old_start`).
  3. If that misses, collect every `i ≥ end_of_previous_hunk` where `old[i:i+len(expected)] == expected`:
     - exactly one → use it;
     - more than one → `ambiguous`;
     - none → `context_mismatch`.
  4. A hunk reaching EOF sets the result's trailing newline to `not hunk.new_no_eol`; otherwise the original flag is kept.
  5. The EOL used is `\r\n` when CRLF count > LF-only count, else `\n`.

  `apply_patch` then works in two phases:
  1. Under the root `flock`, compute every new content. Collect all conflicts and raise them together.
  2. Write all temp files, `os.replace` in order, and on error restore the originals from memory.

## Commands

```bash
cd sandbox_manager
uv sync --locked
uv run ruff check . && uv run ruff format --check . && uv run pyright
uv run pytest -q                    # unit, no Docker
# needs dockerd and the two images (see sandbox-images/*/Dockerfile):
docker build -t kodekantor/sandbox-python:1 ../sandbox-images/python
docker build -t kodekantor/sandbox-node:1 ../sandbox-images/node
KK_REQUIRE_DOCKER=1 uv run pytest -q -m docker
```

Behind a TLS-intercepting proxy: `--network host --build-arg HTTPS_PROXY --secret id=extra_ca,src=<ca.pem>`, and `--build-arg BASE_IMAGE=<mirror>@<same digest>` if Docker Hub is rate-limited.

## Found while executing (fixed, each with a regression test)

- The run reached its final status before the container was removed. Fix: the status is written after cleanup (`test_successful_run` checks the artefact folder is gone).
- A kill that arrived while the container was being created was lost, so the container ran to its timeout. Found by `test_isolation_docker.py::test_kill_task`. Regressions: `test_kill_before_container_exists`, `test_kill_before_create`.
- `/home/sandbox` tmpfs was root-owned, so HOME was not writable. Found by `test_readonly_rootfs`; fixed with `uid=10001,gid=10001,mode=0700`.
- `wait=true` past its slack returned 500. Now it returns the run as it stands (`test_wait_past_slack_returns_the_run_as_it_stands`).
- `/health/ready` called the manager without the Bearer token (WP-1.1 code), so a real manager would always look down.
- certifi 2026.7.22 (PYSEC-2026-4320) in the manager lock and the image: same recorded exception as the backend.

# WP-1.1e Task State Machine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Satu-satunya penulis `tasks.status` (`workflow.states.transition`), tabel task inti, dan event task bernomor urut.

**Architecture:**
- `transition` memvalidasi edge terhadap `ALLOWED`, lalu menjalankan `UPDATE` dengan optimistic lock (`version`), menulis audit, dan memanggil `emit_task_event` di transaksi pemanggil.
- Event non-ephemeral disimpan dengan seq dari `tasks.event_seq`, lalu dipublish ke Redis setelah commit lewat `publish_pending`.

**Tech Stack:** SQLAlchemy 2 async, Alembic, redis.asyncio, pytest.

**Spec:** `docs/superpowers/specs/2026-10-24-wp-1.1e-task-state-machine-design.md`

## Global Constraints

- **Enum** sebagai VARCHAR + CHECK dengan nama `ck_<table>_<rule>` (ADR-018). Status task berjumlah 13 nilai (spec §`workflow/states.py`).
- **Tipe `tasks`:**
  - `status` varchar(32);
  - `workflow_type` ∈ {create, modify, debug, test, review, docs};
  - `priority` ∈ {low, normal, high}, default `normal`;
  - `current_step` ∈ {intake, context, plan, implement, test, debug, review, user_proxy, gate, apply} atau NULL.
- **Default `tasks`:**
  - `checkpoint` `{}`, `budget_limit` `{}`;
  - `iteration` 1, `debug_attempts` 0, `event_seq` 0, `version` 1;
  - `cancel_requested` dan `pause_requested` false.
- **`projects.status`** ∈ {active, archived, deleting_pending_approval, deleted}, default `active`.
- **Event:** channel Redis `kk:task:{task_id}`. Pesan berbentuk `{task_id, seq, type, ts, payload}` (API_CONTRACTS §5.1). `type` ≤ 60 karakter.
- **Error:** `INVALID_TRANSITION` dan `VERSION_CONFLICT`, keduanya HTTP 409.
- **Layer:** `app.main > app.api > app.services > app.workflow > app.core > app.models`.

## Review Focus

1. **Emit paralel di satu task** → seq unik dan berurutan tanpa celah. Test: `test_parallel_emits_have_gapless_seq`.
2. **Transisi dari objek `task` basi** (status lokal ≠ DB) → `VERSION_CONFLICT`, bukan transisi dari status yang salah. Test: `test_stale_task_object_conflicts`.
3. **Rollback setelah emit** → tidak ada publish. Test: `test_rollback_discards_pending_events`.
4. **Payload event berisi secret** → tersimpan dan terpublish dalam keadaan teredaksi. Test: `test_event_payload_is_redacted`.
5. **Status liar lewat SQL langsung** → ditolak CHECK. Test: `test_status_check_rejects_unknown_value`.

## Intent

Dashboard adalah halaman pertama setelah login. User melihat keadaan project yang boleh ia lihat: berapa project aktif, berapa task berjalan, selesai, gagal, atau menunggu persetujuan. Ia juga melihat project dan task terbaru, task yang perlu perhatian, serta pintu ke project baru.

Bagian yang datanya belum direkam platform tampil jujur sebagai **tidak tersedia**, bukan nol. Contohnya aktivitas agent dan usage/biaya. Ini prinsip "evidence over claims" (CLAUDE.md #1) dan AC-16.

## Goals

### 1. `GET /api/v1/dashboard`

- **Akses:** user mana pun yang sudah masuk (`auth`); tidak butuh izin project. Isinya hanya mencakup project yang terlihat oleh user itu (FR-007, AC-01).
- **Visibilitas:** aturan yang sama persis dengan `GET /projects`: owner, atau role berscope project itu; project `deleted` tidak pernah ikut. Aturan ini diekstrak menjadi satu fungsi di `services/projects.py` (`visible_projects_filter(actor)`) dan dipakai oleh `list_projects` serta dashboard. Dengan begitu kedua aturan tidak bisa menyimpang.
- **Respons `data`** (bentuk API_CONTRACTS §3, ditambah yang ditandai ➕; lihat konflik #70):

```text
metrics:
  active_projects     project terlihat dengan status active
  running_tasks       task berstatus running atau validating
  completed_tasks     task berstatus completed
  failed_tasks        task berstatus failed
  waiting_approval    task berstatus waiting_approval
recent_projects:  [Project] maks 5, status active, urut updated_at desc (sama dengan GET /projects?page_size=5)
recent_tasks:     [TaskSummary] maks 10, urut updated_at desc, id
➕ failed_queue:  [TaskSummary] maks 10, status ∈ {failed, interrupted, needs_changes, waiting_approval}, urut updated_at desc, id
agent_activity:   []                           (tidak tersedia: lihat meta.unavailable)
usage:            {period:{start, end}, input_tokens:null, output_tokens:null, estimated_cost:null, cost_status:"unavailable"}
```

- **Cakupan metrik task:** task dari semua project yang terlihat dan tidak `deleted`, termasuk yang `archived`, karena task gagal di project yang diarsipkan tetap pernah terjadi. Metrik dihitung dari seluruh data tersimpan, tanpa periode.
- **`TaskSummary`** sesuai §11 #2: `{id, project_id, title, status, status_reason, current_step, workflow_type, priority, iteration, usage, has_pending_approval, created_at, updated_at}`, ditambah:
  - ➕ `project_name`, karena layar menampilkan nama project di bawah setiap task (mockup) dan `project_id` saja tidak cukup;
  - `usage` = `{input_tokens:null, output_tokens:null, estimated_cost:null, cost_status:"unavailable"}` sampai ledger usage ada;
  - `has_pending_approval` = `status == "waiting_approval"` sampai tabel approval ada (WP-3.1 menggantinya dengan baris approval `pending`).
- **`meta`:**
  - ➕ `unavailable: ["agent_activity", "usage"]`: daftar bagian yang belum punya sumber data. Layar menampilkannya sebagai "tidak tersedia", tidak pernah sebagai 0 atau daftar kosong.
  - ➕ `failed_queue_total`: jumlah seluruh task di antrean perhatian, bukan hanya 10 yang ditampilkan.
- **`usage.period`:** bulan kalender berjalan dalam UTC, `{start, end}` sebagai ISO 8601, setengah terbuka `[start, end)`. Alasannya: `cost_budgets.period = monthly` (DATA_MODEL) [keputusan Lead].
- **Konsistensi:** satu sesi DB, `REPEATABLE READ`, `READ ONLY`, sehingga metrik dan daftar berasal dari snapshot yang sama. Ini pola yang sama dengan pencarian simbol WP-2.1d.
- **Header:** `Cache-Control: no-store`, karena respons memuat izin dan data per user.
- **Batas:**
  - jumlah query tetap: hitung project, hitung task per status (satu `GROUP BY`), recent tasks, failed queue, total queue, plus `list_projects` untuk recent projects;
  - tidak ada parameter dari user, jadi tidak ada validasi input;
  - tanpa rate limit khusus [keputusan Lead]: biayanya setara `GET /projects`, yang juga tidak dibatasi.
- **Tidak diaudit:** ini bacaan, sama dengan `GET /projects`.

### 2. Layar dashboard (`/`, `features/dashboard/`)

Mengikuti mockup screen-02 sejauh datanya ada:

- **Header:** "Selamat datang, {display_name}" dan satu kalimat ringkasan.
- **Quick create (FR-011):**
  - tombol **Project baru** → `/projects/new`;
  - tombol **Task baru** dinonaktifkan, dengan keterangan bahwa pembuatan task belum tersedia (state `capability_disabled`).
- **Metrik utama:** lima kartu (`active_projects` … `waiting_approval`), masing-masing ikon + teks + angka.
- **Task terbaru (FR-008):** judul, nama project, badge status (teks + ikon), dan waktu `updated_at`. Judul membuka `/tasks/:id`.
- **Antrean perhatian (FR-010):** task `failed`, `interrupted`, `needs_changes`, `waiting_approval`, dengan status, `status_reason`, nama project, dan aksi **Buka** → `/tasks/:id`. Bila `failed_queue_total` lebih dari jumlah yang tampil, layar menulis "N lainnya". Aksi resume/retry/putuskan approval belum ada.
- **Aktivitas agent (FR-009):** kartu berstatus "tidak tersedia", dengan alasan bahwa run agent belum direkam.
- **Penggunaan model (FR-011, AC-16):** periode bulan berjalan; token input, token output, dan biaya masing-masing berlabel **tidak tersedia**.
- **Project terbaru (FR-008):** nama, slug, stack, badge status, dan tautan ke workspace (tujuan yang sama dengan daftar project). Ditambah tautan **Lihat semua** → `/projects`.
- **Filter (FR-008):** satu kotak cari yang menyaring project terbaru (nama, slug) dan task terbaru/antrean (judul, nama project) di sisi klien. Pencarian penuh tetap di halaman Projects.
- **State wajib (frontend.md):**
  - loading (skeleton);
  - error, timeout, disconnected, provider_degraded (`StateView` + coba lagi);
  - empty: belum ada project, dengan ajakan membuat project pertama;
  - empty per bagian: tidak ada task, antrean kosong;
  - tidak tersedia per bagian: aktivitas agent, usage;
  - `unauthenticated` diurus penjaga sesi.
- **Teks:** semua lewat kunci i18n `dashboard.*` (id dan en, kunci sama); judul task dan nama project ditampilkan sebagai teks biasa.

## Non-goals

- Membuat task, resume/retry, dan memutuskan approval dari dashboard (WP-3.1: API task dan approval).
- Aktivitas agent nyata dan ledger usage/biaya/budget (WP-3.1 dan WP-INT: `agent_runs`, `usage_records`, `cost_budgets`).
- Pembaruan langsung lewat SSE; layar memuat ulang saat dibuka atau saat tombol coba lagi ditekan.
- Elemen mockup yang tidak ada di kontrak:
  - kartu keenam "Dalam antrean";
  - kartu "Platform";
  - "Mulai demo" dan pemilih skenario (alat demo mockup).

## Anti-goals

- Angka 0 atau daftar kosong untuk data yang tidak direkam. "Tidak tersedia" ≠ 0 (AC-16).
- Data project atau task user lain ikut terhitung atau tampil (AC-01): dashboard adalah agregasi lintas project, jadi kebocoran di sini membocorkan semua project.
- Aturan visibilitas kedua yang berbeda dari `GET /projects`.

## Approaches

1. **Satu endpoint agregat `GET /dashboard` (dipilih).** Endpoint ini sudah ditetapkan kontrak. Satu snapshot, satu request dari layar, dan aturan scope di satu tempat.
2. **Layar merangkai dari endpoint yang ada** (`GET /projects` + per-project tasks). Ditolak: route task belum ada, jumlah request bertambah per project, dan metrik tidak bisa konsisten.
3. **Tabel ringkasan materialized yang diperbarui job.** Ditolak: biaya dan risiko data basi tanpa kebutuhan skala. Prinsip #8: single-node dulu.

## Keputusan Lead (dicatat; konflik #70)

- `failed_queue` dan `meta.failed_queue_total` ditambahkan ke respons, karena FR-010 meminta antrean di dashboard sedangkan bentuk §3 tidak memuatnya.
- `TaskSummary.project_name` ditambahkan.
- `meta.unavailable` menandai bagian tanpa sumber data; `agent_activity` tetap berupa daftar (kosong) agar bentuk kontrak terjaga.
- Bentuk `usage.period` = `{start, end}` bulan UTC.
- `running_tasks` = `running` + `validating`. `validating` adalah eksekusi yang masih berjalan; `queued` belum berjalan.
- `has_pending_approval` dan `waiting_approval` diturunkan dari `tasks.status` sampai tabel approval ada.
- Quick create task dinonaktifkan dan aksi antrean hanya **Buka**, sampai WP-3.1.
- Kartu keenam mockup ("Dalam antrean") tidak dibuat; kontrak hanya memuat lima metrik.

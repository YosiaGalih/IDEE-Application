## Yang dibangun

1. **`app/models/base.py`.** `DeclarativeBase` dengan naming convention, termasuk CHECK `ck_<table>_<name>` sesuai konvensi DATA_MODEL. Mixin UUID-pk dan timestamp disiapkan untuk tabel berikutnya.
2. **`app/models/audit.py` → tabel `audit_events`**, persis kolom DATA_MODEL:
   - `id` bigserial, `ts` timestamptz default now();
   - `actor_type` dengan CHECK (`user`/`agent`/`system`), `actor_id`, `action`;
   - `resource_type`, `resource_id`, `project_id` uuid null;
   - `result` dengan CHECK (`success`/`denied`/`error`);
   - `metadata` jsonb, `correlation_id`, `ip`.

   Kolom identitas, aksi, hasil, dan waktu `NOT NULL`; `metadata` default `'{}'`.
3. **Migrasi `0001_core_audit`.** Tabel, indeks (`ts`, `(resource_type, resource_id)`, `project_id`, `correlation_id`), fungsi dan trigger `audit_events_no_mutation` (BEFORE UPDATE OR DELETE per baris), serta trigger BEFORE TRUNCATE. `downgrade()` menghapus semuanya.
4. **`app/core/db.py`.** Pembuat engine dan session async; dipakai health dan audit.
5. **`app/core/audit.py`.** `AuditWriter.write(session, …)`:
   - `metadata` diredaksi lebih dulu;
   - `correlation_id` default ke request id aktif;
   - menolak `actor_type`/`result` di luar daftar sebelum menyentuh DB.

## Keputusan saya (cek)

- **Nama file migrasi `0001_core_audit`, bukan `0001_initial` berisi 28 tabel.** Dasarnya PRD §9.3 ("nama file Alembic final mengikuti urutan landing"). Tabel v1 lain masuk sebagai revisi berikutnya, satu WP satu revisi.
- **Purge retensi audit 365 hari tidak dibuat sekarang.** Mekanismenya bertentangan dengan trigger append-only dan belum diputuskan (spec sistem pengembangan §8 #17). Trigger juga memblokir TRUNCATE.

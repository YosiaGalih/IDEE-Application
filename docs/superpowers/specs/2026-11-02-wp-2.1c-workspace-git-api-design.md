## Intent

User yang boleh menyunting project membaca dan mengubah file di repository project, melihat perubahan git, membuat branch, dan membuat commit lokal, semuanya lewat HTTP API. API ini dipakai layar IDE di WP-2.2.

Edit manual user menulis ke working tree `repo/` pada default branch (ARCHITECTURE §11.3). Agent tidak memakai API ini; agent menulis ke worktree task lewat ToolGateway (WP-3.x).

## Goals

Semua route berada di bawah `/api/v1/projects/{id}`, memakai pintu `require_project_permission`, dan mengembalikan 404 untuk project di luar scope (SECURITY_MODEL §8).

**Prasyarat repository.** Project harus punya repository yang siap: `repositories.sync_state = ready` dan `repo/.git` berupa folder sungguhan (bukan symlink).
- `importing`/`indexing` → 409 `CONFLICT` `reason = repository_not_ready`.
- `error` (mis. import gagal) → 409 `CONFLICT` `reason = repository_error` dengan kode tersimpan di `details.error`.
- Folder atau `.git` hilang → 409 `CONFLICT` `reason = repository_missing`, plus log error (sinyal T9).
- Baris `repositories` tidak ada → 500 + log error (invarian 2.1a rusak).
- Tidak ada yang menulis status apa pun ke DB (sama dengan 2.1a; syarat masuk AG-13).

**Prasyarat tulis.** Operasi tulis hanya untuk project `active`; `archived` → 409 `project_archived`, status lain → 409 `project_not_active`. Baca tetap boleh.

1. **`GET /tree?path=&depth=`** (workspace:read) → `[{path, name, type, size, children?}]` dari `Workspace.tree`.
   - `depth` default 3, dibatasi `MAX_TREE_DEPTH`.
   - Jumlah entri dibatasi `MAX_TREE_ENTRIES`. Bila terpotong, `meta.truncated = true`.
2. **`GET /files/{path}?ref=`** (workspace:read) → `{path, content, encoding, size, sha256, language, too_large}`.
   - Binary atau terlalu besar → `content = null` (FR-032).
   - `language` diturunkan dari ekstensi file (untuk syntax highlight, FR-027), `null` bila tidak dikenal.
   - `ref` kosong atau `main` → working tree `repo/`.
   - `ref = task:<uuid>` → 404 `NOT_FOUND` sampai worktree task ada (WP-3.1).
   - Format `ref` lain → 422.
3. **`PUT /files/{path}`** (workspace:write) `{content, expected_sha256: string|null}` → `{path, sha256}`.
   - `null` berarti file belum boleh ada.
   - Sha yang berbeda → 409 `VERSION_CONFLICT` dengan sha saat ini di `details` (FR-029). Tidak ada penulisan "menang terakhir".
   - Konten melebihi batas tulis `Workspace` → 413 `PAYLOAD_TOO_LARGE`.
4. **`POST /files`** (workspace:write) `{path, content?, type: "file"|"dir"}` → `{path}` (201). Path yang sudah ada → 409 `CONFLICT`.
5. **`DELETE /files/{path}?expected_sha256=`** (workspace:write) → `{}`.
   - Hanya file, dan `expected_sha256` wajib.
   - Folder → 400 `PATH_VIOLATION` `reason = not_regular` (pemeriksaan `Workspace` yang sudah ada); hapus folder adalah fitur v2.1 (§13.3, `recursive`).
6. **`POST /patches`** (workspace:write) `{diff, target: "main"}` → `{applied: [FileChange], rejected: []}`.
   - Diterapkan **semua atau tidak sama sekali** (`Workspace.apply_patch`).
   - Satu hunk konflik → 409 `CONFLICT` dengan daftar hunk yang ditolak di `details`, dan tidak ada file yang berubah (FR-031, R-07).
   - `target` selain `main` → 422.
7. **`GET /git/status`** (git:read) → `{branch, head, clean, changes: [{path, status}]}` (FR-113).
8. **`GET /git/diff?base=&path=`** (git:read) → `Diff` (§4) dengan `truncated`.
   - `base` default `HEAD`; `head = null` artinya working tree, termasuk file untracked.
   - Keluaran dibatasi 1 MiB.
9. **`GET /git/branches`** (git:read) → `[{name, head, is_task_branch}]`. `is_task_branch` = nama berawalan `kk/task-`.
10. **`GET /git/log?limit=`** (git:read) → `[{commit, author, date, message}]`. `limit` default 20, maks 200.
11. **`POST /git/branch`** (git:branch) `{name, from?}` → `{name, head}` (201).
    - Hanya membuat ref; tidak ada checkout, jadi working tree tidak berubah.
    - `kk`, `kk/...`, `refs/...`, dan `HEAD` dicadangkan → 422 (`kk` sendiri memblokir semua `kk/task-*`).
    - Branch yang sudah ada → 409 `CONFLICT`.
12. **`POST /git/commit`** (workspace:write) `{message, paths?}` → `{commit}` (201).
    - Commit dibuat di branch yang sedang aktif di `repo/`. Author = user yang membuat commit (aturan `commit_author` 2.1a).
    - `paths` membatasi isi commit; path dilewatkan sebagai pathspec literal (`GIT_LITERAL_PATHSPECS=1` sudah aktif di adapter). Maks 500 path dan 128 KiB total; pesan kosong/spasi → 422.
    - **Index selalu mulai dari HEAD** (dan dikembalikan ke HEAD bila commit gagal): commit hanya berisi apa yang di-stage panggilan ini, bukan sisa panggilan yang gagal (temuan BLOCK review).
    - **`.kk/` tidak pernah ikut di-stage** (SECURITY_MODEL §4), termasuk bila sudah ter-track; `.kk/` masuk `info/exclude`, dan `status`/`diff` tidak menampilkannya (sehingga `clean` berarti "tidak ada yang bisa di-commit"). Path `.kk/...` yang dipilih eksplisit → 422 `path_excluded`.
    - Berlaku juga untuk commit pertama template dan import (`commit_all`): `.kk/` dari arsip tetap di disk tetapi tidak ter-commit.
    - Tidak ada yang di-commit → 409 `CONFLICT` `reason = nothing_to_commit`.
13. **Audit** (T10), satu event per operasi tulis yang berhasil, berisi path (relatif) dan sha, tanpa isi file. Patch yang gagal dikembalikan (`PatchRollbackFailed`) diaudit `result=error` dengan path yang setengah ditulis. `git.commit` mencatat file yang benar-benar ada di commit (`diff-tree`), bukan hanya yang diminta:
    - `workspace.file_written`, `workspace.file_created`, `workspace.file_deleted`;
    - `workspace.patch_applied` (jumlah file);
    - `git.branch_created`;
    - `git.commit` (sha, jumlah path). Bila daftar file gagal dibaca (misalnya melewati batas output git), event tetap ditulis dengan `files: null` dan `files_error: <reason>`; request tetap 201.
    Nama mengikuti §13.3 (`workspace.file_*`). Pembacaan tidak diaudit.
    - **Tulis berjalan sampai selesai** (AG-13 M1). Perubahan sampai di disk atau git sebelum event-nya ditulis, jadi setiap operasi tulis beserta audit-nya dijalankan sebagai satu task yang tidak ikut berhenti bila request dibatalkan. Cancel hanya menghentikan request yang menunggu. Kegagalan task yang tidak lagi ditunggu ditulis ke log (`workspace_write_failed_after_cancel`). Commit mengambil kunci workspace di dalam task itu, sehingga kunci tidak lepas selama git masih berjalan. Shutdown menunggu tulis yang masih berjalan (`drain_writes`, 30 s) sebelum loop membatalkan semua task; yang belum selesai ditulis ke log dengan nama aksi dan project.
    - **Commit yang sudah masuk adalah jawaban.** Bila langkah `git commit` gagal atau dihentikan tetapi HEAD sudah maju, adapter mengembalikan sha baru, dan request mendapat 201 beserta audit-nya, bukan 409. Syaratnya, HEAD baru terbukti commit ini: parent-nya HEAD sebelumnya (tanpa parent untuk commit pertama), author-nya user ini, dan pesannya sama. Bila tidak, error asli tetap berlaku dan log error `git_head_moved_by_another_writer` menandai pelanggaran aturan satu penulis.
14. **Konkurensi.** Mutasi dalam satu project diserialkan oleh kunci workspace yang sudah ada (`<project>/.kk-locks`). Commit mengambil kunci yang sama lewat `Workspace.exclusive()` (menunggu di event loop, tanpa memarkir thread), sehingga `add` dan `commit` melihat satu snapshot. Kunci yang dipegang terlalu lama → 409 `CONFLICT` `reason = busy` dengan `Retry-After`.
15. **Jawaban sementara tidak disimpan idempotency.** Respons yang membawa `Retry-After` (workspace sibuk, timeout git) tidak disimpan, sehingga retry dengan key yang sama berjalan lagi. Git yang dibunuh adapter tidak meninggalkan `index.lock`. Ini berlaku untuk timeout, output yang melewati batas, dan cancel, termasuk saat reset index di awal dan setelah commit gagal (AG-13 L1). Penghapusan ini aman karena setiap penulis index memegang kunci workspace; syarat itu juga berlaku untuk pemanggil berikutnya (commit worktree task, `merge_branch`).

## Non-goals

- **Layar IDE** (explorer, Monaco, tab, status simpan: FR-026, FR-027, FR-030). Itu WP-2.2; WP-2.1c hanya menyediakan API dan bentuk datanya.
- **Worktree task** (`ref = task:<id>`, FR-114, FR-116). Ikut task di WP-3.1.
- **Workspace v2.1** (§13.3: `target`, `editor_session`, rename, merge3, undo, hapus folder). M26, P5+.
- **Remote** (push, pull, PR, FR-119/120). P2 remote, setelah G4.
- **Hapus atau reset branch, checkout, `reset --hard`, `clean`** (FR-118). Tidak disediakan sama sekali.
- **Menyimpan `sync_state = error` secara persisten.** Catatan review 2.1a mengusulkannya. Ditolak karena syarat masuk AG-13 dari WP-2.1b: hanya `_complete` yang boleh membawa project upload dari `importing` ke `ready`, dan penulis status baru tidak boleh mengubah arti status bagi import. Masalah repo tetap dihitung di jalur baca.
- **Penyapu folder yatim** (project terhapus, sisa `uploads/` project `ready`, INFO I3 AG-13 WP-2.1b). Menghapus data adalah T9 dan butuh desain sendiri. Dicatat sebagai tindak lanjut terpisah di tracker; tidak dikerjakan diam-diam di sini.

## Anti-goals

- Penulisan yang menimpa perubahan orang lain tanpa `VERSION_CONFLICT`.
- Patch yang diterapkan sebagian.
- Path dari user yang keluar dari `repo/`, menyentuh `.git/`, atau mengikuti symlink keluar root, termasuk lewat encoding URL (`%2e%2e`, `%2f`, NUL).
- Argumen git dari user yang dibaca sebagai opsi (`-x`, `--upload-pack=…`) atau magic pathspec.
- Commit yang membawa `.kk/` atau isi file di audit atau log.
- Menghapus atau mengubah `repo/` project upload yang belum `ready` (sapu import tetap pemiliknya).

## Pendekatan

| Pendekatan | Untung | Rugi |
|---|---|---|
| **A. Service tipis di atas `Workspace` dan `GitAdapter`** (dipilih) | Validasi path dan hardening git sudah teruji di WP-1.2 (T2, T3). Service hanya menambah otorisasi, prasyarat, kunci, dan audit | Kunci workspace perlu dibuka sebagai helper publik untuk commit |
| B. Lewat ToolGateway seperti agent | Satu pintu side effect | ToolGateway untuk aksi runtime agent (CLAUDE.md #2), bukan untuk user lewat HTTP; menambah lapisan tanpa kontrol baru |
| C. Service workspace terpisah (proses lain) | Isolasi | Tier S satu node; tidak ada kebutuhan; menambah jaringan dan deploy |

## Keputusan

| Topik | Keputusan | Alasan |
|---|---|---|
| Bentuk respons patch | Atomik: 200 `{applied, rejected: []}` atau 409 dengan hunk yang ditolak di `details` | FR-031 "apply yang aman", R-07; `Workspace.apply_patch` atomik. Kontrak tidak mewajibkan penerapan sebagian |
| `ref = task:<id>` | 404 sampai worktree task ada | Tidak ada worktree task sebelum WP-3.1; 404 jujur dan tidak membocorkan apa pun |
| Batas tree | `meta.truncated` | Envelope §1 punya `meta`; kontrak tree tidak punya field terpotong |
| Hapus folder | Ditolak 400 `PATH_VIOLATION` `not_regular` | v1 hanya file; folder rekursif adalah fitur v2.1 dengan `recursive=true`. Pemeriksaan `Workspace` sudah menolaknya; tidak perlu kode baru |
| Commit kosong | 409 `nothing_to_commit` | Jawaban yang jelas; tidak mengarang sha |
| `kk/` di nama branch | Dicadangkan | Branch task/user milik platform (FR-114, §13.3) |
| `.kk/` di commit | Selalu di-unstage setelah `add` | SECURITY_MODEL §4; berlaku juga untuk file yang sudah ter-track dari arsip |
| Status error persisten | Tidak ditulis | Syarat masuk AG-13 WP-2.1b |

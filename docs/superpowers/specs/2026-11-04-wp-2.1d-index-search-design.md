## Intent

User mencari di project dari IDE (WP-2.2): teks (string atau regex) di working tree yang sedang disunting, dan simbol (fungsi, kelas, …) dari indeks repository. Indeks yang sama nanti dibaca agent A04 lewat `repo.search_symbol` (WP-3.x), jadi isi indeks harus jujur: setiap baris membawa commit sumbernya, dan status "terindeks" hanya ditulis oleh job yang benar-benar membaca commit itu (CLAUDE.md #1).

## Goals

1. **Tabel `repo_index_entries`** sesuai DATA_MODEL: `id bigserial pk`, `project_id` fk `projects` `ON DELETE CASCADE`, `path varchar(1000)`, `kind` `CHECK in ('file','symbol')` (`ck_repo_index_entries_kind`), `symbol varchar(300) null`, `symbol_kind varchar(40) null`, `line int null`, `language varchar(40) null`, `size_bytes int null`, `sha256 char(64) null`, `commit varchar(64) not null`. Index `(project_id, kind)` dan `(project_id, symbol)`. Tanpa trigram (opsional di DATA_MODEL). Migrasi 0005 lulus `upgrade → downgrade -1 → upgrade`.
2. **Indeks = isi satu commit, bukan working tree.** Job membaca HEAD branch aktif `repo/` dari object database git:
   - file: `git ls-tree -r -z --long --full-tree <sha>`. Hanya blob biasa (mode `100644`/`100755`); symlink, submodule, dan path `.kk/…` tidak diindeks. `size_bytes` dari ls-tree, `language` dari ekstensi (`language_for`, dipindah ke `workspace/index.py`), `sha256` **null** (lihat Keputusan).
   - simbol: satu `git grep -z -n -o -I -E -e <pola>… <sha> --` dengan pola definisi semua bahasa sekaligus. `-o` hanya mencetak bagian yang cocok, jadi baris raksasa (file minified) tidak membesarkan output. Setiap kecocokan diklasifikasikan di Python menurut ekstensi file; kecocokan pola bahasa lain dibuang.
   - Karena dibaca dari object database, job tidak menyentuh filesystem working tree: tidak ada symlink yang diikuti dan tidak ada balapan dengan simpan user (T2).
3. **Bahasa dan jenis simbol (v1, heuristik baris).** Python (`def`, `async def` → `function`; `class` → `class`), JavaScript/TypeScript (`function`, `class`, `interface`, `type X =`, `enum`, `const X = (…) =>`/`function`), Java (`class`, `interface`, `enum`, `record`), Go (`func`, termasuk method receiver → `function`; `type` → `type`), Rust (`fn`, `struct`, `enum`, `trait`), Ruby (`def`, `class`, `module`), PHP (`function`, `class`, `interface`, `trait`). Bahasa lain: file terindeks, tanpa simbol. Parser AST/ctags adalah v2.1 (`index.symbols_incremental`, sandbox).
4. **Job indeks** (`platform_jobs.index_repository`, antrean `ide`):
   - **Satu job per project:** kunci Redis `kk:index:<project_id>` berisi `job_id` (`SET NX`, TTL 30 menit). Job hanya jalan bila kunci masih miliknya, dan melepasnya di akhir (compare-and-delete).
   - HEAD = `index_commit` → tidak ada yang ditulis ulang; hanya `last_indexed_at` diperbarui, audit `unchanged: true`.
   - **Ganti seluruh isi dalam satu transaksi:** kunci baris `projects` (`FOR NO KEY UPDATE`, urutan sama dengan import: projects lalu repositories) → `DELETE` entri project → `INSERT` berkelompok → `UPDATE repositories SET index_commit, last_indexed_at` → audit `project.index` (sukses), lalu COMMIT. Pembaca melihat indeks lama sampai COMMIT.
   - **Tidak menulis `repositories.sync_state` atau `repositories.error`** (syarat masuk AG-13 WP-2.1b). Status `indexing` di DATA_MODEL tidak dipakai: memakainya akan menutup IDE (409 `repository_not_ready`) selama indeks berjalan.
   - **Batas** [Menebak]: 50 000 file (= `ArchiveLimits.max_entries`), 200 000 simbol, 2 000 simbol per file, path > 1000 karakter dilewati, nama simbol > 300 karakter dipotong, output git simbol maks 64 MiB, timeout 300 s per perintah git. Batas yang tercapai → indeks tetap ditulis, ditandai `truncated: true` di audit, dan dicatat di log warning.
   - **Gagal** (git, DB): audit `project.index result=error` + `reason` (detached, di luar transaksi yang gagal), kunci dilepas, indeks lama utuh. Tidak ada retry otomatis; user meminta ulang.
5. **`POST /projects/{id}/index`** (`workspace:write`):
   - Prasyarat `open_repo(write=True)` dari 2.1c: repo `ready`, `.git` folder asli, project `active`.
   - Kunci sudah dipegang job lain → 202 dengan `job_id` job itu dan `meta.reused = true`, tanpa enqueue kedua.
   - Kirim job gagal → kunci dilepas → 503 `DEPENDENCY_UNAVAILABLE`. Redis tidak ada → 503.
   - Rate limit 10 permintaan/jam per user [Menebak] (pola `enforce_rate`).
6. **Indeks otomatis** (UC-02 "import → … → index"):
   - setelah project blank/template dibuat (route `POST /projects`, setelah commit) dan setelah import `ready` (job import, setelah `_complete`);
   - best effort: gagal mengirim job dicatat di log error dan tidak mengubah jawaban create maupun hasil import. User tetap bisa `POST /index`.
   - Melewati rate limit user (ini permintaan sistem), tetapi tetap memakai kunci per project.
7. **`GET /projects/{id}/search`** (`workspace:read`, `open_repo(write=False)`). Parameter:
   - `q` wajib, 1–500 karakter, tanpa karakter kontrol (`\0`, `\n`, `\r`) → selain itu 422;
   - `mode` `text` (default) | `symbol`;
   - `glob` opsional, ≤ 256 karakter, ≤ 8 `*`;
   - tambahan di luar kontrak (konflik #69): `regex` (bool, default false; hanya mode text), `ignore_case` (bool, default true), `kind` (mode symbol), `limit` (1–200, default 200).
   - Jawaban `data`: `[{path, line, preview, symbol?, kind?}]`; `meta`: `{truncated, index_commit, indexed_at}` (dua yang terakhir hanya mode symbol).
8. **Cari teks = working tree saat ini** (yang disunting user, termasuk file yang belum di-commit):
   - `git grep -z -n --column -I --untracked [-i] (-F|-E) -e <q> --` di `repo/`. Menghormati `.gitignore`; `.git` tidak pernah dibaca; symlink tidak diikuti (terbukti git 2.43, test T2); `GIT_OPTIONAL_LOCKS=0` sehingga index git tidak ditulis (aturan satu penulis, AG-13 I-b).
   - Hasil disaring di Python: `glob` (tanpa `/` dicocokkan ke nama file, dengan `/` ke path penuh; `fnmatchcase`), denylist `policy.denied(path, access)`, dan `.kk/`.
   - `preview` = baris yang cocok, dipotong 200 karakter di sekitar kolom kecocokan pertama.
   - Timeout 10 s, output maks 4 MiB (`truncate=True` → `meta.truncated`). Timeout → 409 `GIT_ERROR` `reason = timeout` + `Retry-After` (bentuk dari 2.1c).
   - Regex = POSIX ERE (`git grep -E`); regex tidak valid (rc 128, `fatal: -e option`) → 422 `invalid_regex`.
   - Rate limit 60 pencarian teks per menit per user [Menebak]: setiap pencarian teks menjalankan satu proses git.
9. **Cari simbol = indeks** (`repo_index_entries kind = symbol`):
   - cocok tanpa membedakan huruf besar/kecil; urutan: sama persis, lalu awalan, lalu mengandung; dalam tiap kelompok urut path lalu baris. `%` dan `_` dari `q` di-escape.
   - `glob` disaring di Python setelah query; diambil hingga 5 000 kandidat. Lebih dari itu → `meta.truncated`.
   - `preview` = `"<kind> <symbol>"`. Denylist diterapkan saat baca (path yang ditolak untuk akses pemanggil dibuang), sehingga perubahan `.agentignore` setelah indeks tetap berlaku.
   - Belum pernah diindeks → `[]` dengan `meta.index_commit = null`.
10. **`stats.files`** di `Project` (§11 #14) = jumlah entri `kind = file`; `null` bila belum pernah diindeks (`last_indexed_at` null).
11. **Audit (T10):** satu event `project.index` per job yang berjalan, dengan actor user yang meminta (atau pembuat/pengunggah untuk indeks otomatis). Metadata: `{commit, files, symbols, truncated, unchanged, trigger: "user"|"create"|"import"}`. Bila gagal: `{reason}` dengan `result=error`. Pencarian (baca) tidak diaudit.

## Non-goals

- Indeks inkremental, ctags/tree-sitter, sandbox indexer: v2.1 (`index.symbols_incremental`, WP-13.9).
- Embedding atau vector search (ADR-046).
- Tool agent `repo.search_text`/`repo.search_symbol` dan pemfilteran AGENT_READ di ToolGateway: WP-3.x. Service menerima parameter `access`, jadi tool nanti tidak butuh jalur baru.
- Event SSE progres indeks. Klien membaca `repository.last_indexed_at` (polling, sama dengan import).
- Layar pencarian IDE: WP-2.2.
- Pencarian di worktree task (`ref=task:…`): WP-3.1.

## Anti-goals

- Indeks yang menyatakan commit yang tidak pernah dibacanya, atau `last_indexed_at` yang maju padahal job gagal.
- Pencarian yang mengikuti symlink keluar repo, membaca `.git`, atau menulis index git.
- Regex user yang bisa memacetkan event loop atau thread pool (ReDoS). Regex hanya berjalan di proses git yang dibunuh saat timeout.
- Penulis baru `repositories.sync_state`.

| Pendekatan | Untung | Rugi | Pilihan |
|---|---|---|---|
| **A. Indeks dari commit lewat `git ls-tree` + `git grep -o`; cari teks lewat `git grep` di working tree** | Semua parsing konten berjalan di proses git: dibatasi timeout dan output, dan dibunuh bila macet. Tidak menyentuh working tree untuk indeks (T2), dan `commit` di setiap baris jujur. Tanpa dependensi baru. | Simbol heuristik per baris, bukan AST. | C. Parse file working tree di worker (Python `ast` + `re`) | Simbol Python akurat | `re` Python atas konten untrusted tidak bisa dihentikan (thread tidak bisa dibunuh). Membaca filesystem membuka risiko balapan symlink. Commit sumber tidak jelas bila ada suntingan yang belum di-commit. | ditolak |

## Keputusan

| Topik | Keputusan | Alasan |
|---|---|---|
| Sumber indeks | HEAD branch aktif, dari object database | Kolom `commit` harus benar (evidence over claims); bebas balapan dengan simpan user |
| Sumber cari teks | working tree | User mencari teks yang baru saja ia ketik (FR-020 "di workspace project") |
| `sha256` entri file | null | ls-tree hanya memberi id objek git (SHA-1, atau SHA-256 git yang bukan sha256 isi). Menghitung sha256 isi berarti membaca setiap blob; nilainya baru dibutuhkan saat ada pembanding (v2.1) |
| `sync_state = indexing` | tidak dipakai | IDE tetap terbuka selama indeks berjalan; syarat masuk AG-13 (tidak ada penulis `sync_state` baru) |
| Kegagalan indeks | audit error + log; `repositories.error` tidak disentuh | `error` milik status repository (import). Indeks lama tetap berlaku |
| Permintaan saat job berjalan | 202 dengan `job_id` yang sedang berjalan (`meta.reused`) | Tujuan klien (indeks segera diperbarui) sudah terpenuhi; tidak ada antrean ganda |
| Denylist | Disaring saat baca dengan `access` pemanggil (USER_READ untuk API) | Satu indeks untuk user dan agent; `.agentignore` yang berubah langsung berlaku |
| Glob | Disaring di Python (`fnmatchcase`), bukan pathspec git | `GIT_LITERAL_PATHSPECS=1` tetap berlaku untuk semua input user (T3) |
| Dialek regex | POSIX ERE (`git grep -E`) | PCRE (`-P`) bisa backtracking eksponensial; ERE di proses git tetap dibatasi timeout |

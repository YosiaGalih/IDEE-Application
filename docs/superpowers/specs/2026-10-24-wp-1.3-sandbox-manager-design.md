## Intent

**Masalahnya.** Kode project dan test-nya tidak boleh berjalan di control plane (CLAUDE.md #3). Satu-satunya jalan eksekusi adalah sandbox-manager: layanan kecil yang menerima `profile_id` dari daftar tetap, membangun HostConfig sendiri, dan berbicara dengan Docker lewat socket proxy.

**Yang dibangun WP ini:**
- sandbox-manager;
- dua image sandbox (python, node), uid 10001;
- file profil;
- klien HTTP di backend beserta parser junit/coverage.

**Goals**
1. **Service `sandbox_manager/`** (pyproject sendiri) dengan API §10:
   - `/healthz`, `/v1/profiles`;
   - `/v1/runs` (POST/GET), `/v1/runs/{id}/logs`, `/v1/runs/{id}/kill`, `/v1/tasks/{id}/kill`;
   - auth Bearer constant-time.
2. **Validasi request** sesuai §10:
   - regex subpath + `realpath` di bawah `WORKSPACE_ROOT`;
   - profil wajib ada;
   - `args` cocok `args_pattern`;
   - `timeout_s ≤ max_timeout_s`;
   - aturan egress;
   - field asing → 422.
3. **`build_host_config` sebagai satu-satunya pembangun spec container.**
   - Identitas dan hak: non-root 10001, `cap_drop ALL`, `no-new-privileges`.
   - Filesystem: rootfs read-only, tmpfs `/tmp` + `/home/sandbox`.
   - Network: `none`.
   - Limit: pids, memori (tanpa swap), CPU, ulimit nofile.
   - Mount: satu bind workspace, `.git` disembunyikan.
   - Env: allowlist saja; label `kk.*`; runtime opsional.
4. **Driver `docker`.** Docker Engine API lewat `httpx`, via unix socket atau tcp proxy:
   - tanpa pull;
   - timeout → kill;
   - output dibatasi `SANDBOX_MAX_OUTPUT_BYTES`;
   - artefak `/workspace/.kk/{junit,coverage}.xml` dibaca dari folder bind per run `<project>/.kk-runs/<run_id>` (konflik #36), sebelum container dihapus;
   - pertumbuhan disk diukur.
5. **Driver `fake`** untuk test.
6. **Image dan profil.** `sandbox-images/python` dan `node` dengan uid 10001, plus `sandbox-profiles.yaml` berisi `python.pytest`, `python.ruff`, `node.npm_test`. Dependensi test template WP-1.2d (pytest, fastapi, httpx, ruff) ada di image, sehingga test berjalan **tanpa network** (ADR-007).
7. **Backend `app/sandbox/`:**
   - `SandboxClient` protocol + `HttpSandboxClient` + `FakeSandboxClient`;
   - `junit.py` (parser JUnit XML berbatas);
   - `coverage.py` (Cobertura line-rate).

**Non-goals**
- Runner test, `test_runs`, `failure_kind` (WP-4.x).
- Egress proxy dan compose (WP-1.5).
- Preview (ADR-008, P1).
- gVisor di CI: runc saja; runsc hanya divalidasi lewat konfigurasi.

**Anti-goals**
- **Caller mana pun mempengaruhi HostConfig**: image, mount, privileged, network, user, env.
- **docker.sock di-mount ke container sandbox.**
- **Image di-pull otomatis.**
- **Secret proses manager masuk env container.**
- **Container tertinggal** setelah run, timeout, atau error.
- **Hasil run dinyatakan `succeeded` tanpa exit code 0** dari container nyata (CLAUDE.md #1).

## Approaches

| | Pendekatan | Trade-off | Status |
|---|---|---|---|
| A | Docker Engine API langsung lewat `httpx` async (uds atau tcp ke socket proxy) | Tanpa dependensi baru (`httpx` sudah dipakai). Endpoint yang dipakai terlihat eksplisit, cocok dengan allowlist proxy. Parser stream log multiplexed ditulis sendiri. | **dipilih** |
| B | SDK `docker` (docker-py) | Sync dan menarik `requests` (dilarang aturan backend), lebih banyak permukaan | ditolak |
| C | CLI `docker` lewat subprocess | Perlu binary dan socket di manager, parsing teks, rawan argumen | ditolak |

## Desain

### Layout

```
sandbox_manager/                 # service terpisah (pyproject + uv.lock sendiri)
  sandbox_manager/
    config.py        # Settings dari env SANDBOX_*; token ≥ 32 → gagal start
    profiles.py      # load sandbox-profiles.yaml (extra=forbid), sekali saat start
    validation.py    # RunRequest (extra=forbid) → ValidatedRun
    hostconfig.py    # build_container_spec(): satu-satunya pembangun body create container
    docker_driver.py # DockerEngine (httpx) + DockerDriver
    fake_driver.py
    runs.py          # RunRegistry: siklus run, semaphore, buffer log, kill
    app.py           # FastAPI, auth
  tests/
sandbox-images/
  python/Dockerfile, node/Dockerfile, sandbox-profiles.yaml
backend/app/sandbox/
  client.py (SandboxClient, HttpSandboxClient, FakeSandboxClient), junit.py, coverage.py
```

### Profil (`sandbox-profiles.yaml`)

```yaml
version: 1
profiles:
  - profile_id: python.pytest
    image: python              # alias → SANDBOX_IMAGE_PYTHON
    suite: test
    argv: [python, -m, pytest, -q, -p, no:cacheprovider, --junitxml=/workspace/.kk/junit.xml]
    args_pattern: '^[A-Za-z0-9_./:\[\]-]{1,200}$'   # tiap arg tambahan (path test / node id)
    max_args: 20
    timeout_s: 300
    max_timeout_s: 900
    network: none              # none | egress-allowed
```

Aturan profil:
- **Image.** `image` adalah alias (`python`, `node`) yang dipetakan dari Settings. Caller tidak pernah menyebut image.
- **Argumen tambahan** wajib cocok `args_pattern` dan tidak boleh diawali `-`. Opsi selalu datang dari profil, bukan dari caller.

### Spec container (`build_container_spec`)

```text
Image: <alias → settings>            Cmd: argv + args          WorkingDir: /workspace
User: "10001:10001"                  Env: HOME, PATH, LANG=C.UTF-8, CI=1 (tidak lebih)
Labels: kk.managed=1, kk.run_id, kk.task_id, kk.project_id
HostConfig:
  NetworkMode: none | <SANDBOX_EGRESS_NETWORK>
  ReadonlyRootfs: true   Privileged: false   CapDrop: [ALL]   SecurityOpt: [no-new-privileges]
  PidsLimit, Memory, MemorySwap=Memory, NanoCpus, Ulimits: nofile 1024/1024
  Tmpfs: /tmp (noexec,nosuid,size=256m,mode=1777), /home/sandbox (nosuid,size=64m,uid=10001,gid=10001,mode=0700)
  Mounts: bind WORKSPACE_ROOT/<subpath> → /workspace (ReadOnly = read_only)
          bind <WORKSPACE_ROOT>/<project>/.kk-runs/<run_id> → /workspace/.kk (rw, folder baru per run; konflik #36)
  LogConfig: json-file, max-size max(8 × SANDBOX_MAX_OUTPUT_BYTES, 64 MiB), max-file 2
          .git dir → tmpfs ReadOnly di /workspace/.git ; .git file → bind <empty> ReadOnly
  Runtime: runsc bila SANDBOX_RUNTIME=runsc
  (tidak ada: Binds bebas, PidMode, IpcMode=host, Devices, CapAdd, ExtraHosts)
```

### Siklus run

```text
POST /v1/runs → validate (+ client_request_id: ulangan → run yang sama) → RunRecord(queued) → task:
  semaphore(SANDBOX_MAX_CONCURRENT_RUNS); kill saat queued → killed seketika
  status running
  image ada? (GET /images/{name}/json) tidak → error IMAGE_MISSING
  folder artefak <project>/.kk-runs/<run_id> (dir fd, O_NOFOLLOW)
  disk_before = ukuran workspace (bila writable; folder tak terbaca → WORKSPACE_UNSAFE)
  create → start (started_at) → baca log ∥ wait(timeout) ∥ watchdog folder artefak tiap 1 dtk
  watchdog: > 8 MiB → kill → DISK_LIMIT; tak terukur → DISK_UNMEASURABLE
  timeout → kill → timeout | exit 0 → succeeded | kill diminta dan exit ≠ 0 → killed | lain → failed
  inspect: State.OOMKilled → OOM_KILLED; Image → image_digest
  artefak: {junit,coverage}.xml dengan O_NOFOLLOW, file reguler ≤ 1 MiB → artifact_status
  pertumbuhan (workspace + folder artefak) > batas → DISK_LIMIT; tak terukur → DISK_UNMEASURABLE
  succeeded tetapi artefak wajib profil tidak ok → ARTIFACT_MISSING / ARTIFACT_REJECTED
  finally: remove container (by id, atau by name bila create gagal; 3×)
           berhasil → hapus folder artefak (berbasis fd, tanpa path panjang; gagal → ARTIFACTS_NOT_REMOVED)
           gagal → CONTAINER_NOT_REMOVED, folder dibiarkan untuk sapuan start
  baru setelah itu status final ditulis (record.finish; status final pertama yang berlaku)
```

- **Status final ditulis setelah container dihapus.** Caller yang melihat status final dapat yakin tidak ada proses yang masih menulis ke workspace.
- **Kill sebelum container ada** (status `running`, container sedang dibuat): dicek lagi setelah `start`, lalu container di-kill. Ditemukan oleh `test_isolation_docker.py::test_kill_task`; regresi di `test_docker_driver.py::test_kill_before_container_exists`.

- **`wait=true`** menunggu hasil final, dengan batas `timeout_s + 30` dtk. Lewat batas itu, respons berisi run apa adanya (bukan 500) dan caller melanjutkan dengan polling.
- **Log** disimpan sebagai chunk `{stream, data}` sampai `SANDBOX_MAX_OUTPUT_BYTES`, lalu `truncated=true` dan sisanya dibuang. Frame berurutan satu stream digabung sampai dibaca reader; `/logs` berhalaman (±256 KiB) dan memuat `status`; `done` baru true setelah semua chunk terkirim. `stdout_tail`/`stderr_tail` = 64 KiB terakhir dari seluruh output (juga setelah terpotong). Stream log putus → `log_incomplete=true`.
- **Kill.** `POST /containers/{id}/kill`; `/v1/tasks/{id}/kill` mematikan semua run aktif yang berlabel task itu.
- **Registry run** ada di memori dan hilang saat restart; recovery adalah tanggung jawab worker lewat lease (WP-1.1f). Run final disimpan ≤ 1 jam dan ≤ 500 [Menebak].
- **Container yang hilang kendali.** Satu manager per daemon Docker. Saat start, manager menghapus semua container `kk.managed=1` dan semua `<project>/.kk-runs/*`. Selama berjalan, reaper tiap 60 dtk menghapus container berlabel `kk.manager=<instance>` miliknya yang tidak punya run aktif (cocok dengan RUNBOOK "reaper tiap 60 dtk").

### Backend

- **`HttpSandboxClient(base_url, token, timeout)`:**
  - `run(req, on_log=None) -> SandboxRunResult`: `POST /v1/runs` (`wait=false`), lalu polling `/logs?offset=` (memberi `on_log`) sampai `done`, lalu `GET /v1/runs/{id}`. Alasan: `on_log` di kontrak ARCHITECTURE §4.2 butuh log berjalan;
  - status non-final atau tak dikenal dari manager → `SandboxUnavailable`, tidak pernah dianggap hasil;
  - batas waktu klien `timeout_s + 60` dtk hanya menjaga manager yang macet: run di-kill lalu `SandboxUnavailable`;
  - `kill(run_id)`, `kill_task(task_id)`, `health()`;
  - 401/403 → `SandboxAuthError`, 422 → `SandboxRequestError` (kode dari manager), 404 (run hilang setelah restart), 5xx, jaringan, dan respons tak terbaca → `SandboxUnavailable`.
- **`/health/ready`** (WP-1.1) kini memanggil `HttpSandboxClient.health()`: dengan token Bearer, dan `ok` hanya bila `docker == "ok"`. Sebelumnya tanpa token, sehingga manager asli selalu menjawab 401.
- **`FakeSandboxClient`:** hasil terprogram untuk test.
- **`parse_junit(xml_bytes)`** → `JUnitSummary{tests, failures, errors, skipped, cases[]}`.
  - Batas 1 MiB.
  - DTD dan deklarasi entity ditolak lewat handler expat (`app/sandbox/safexml.py`), tanpa dependensi baru.
  - Jumlah dihitung dari elemen `<testcase>`, bukan atribut ringkasan (ringkasan = klaim, kasus = bukti).
  - XML rusak → `JUnitError`.
- **`parse_coverage(xml_bytes)`** → line-rate 0..1 atau `None`. "Coverage hanya dari file" (TEST_STRATEGY AC-08).

## Keputusan saya (cek)

1. **Docker Engine API lewat `httpx`**, bukan docker-py.
2. **Alias image** di profil (`python`, `node`) dipetakan dari Settings. Image tidak ditulis langsung di YAML, supaya tag/digest dikendalikan konfigurasi.
3. **Argumen tambahan tidak boleh diawali `-`.** Opsi hanya dari profil [Menebak; kontrak hanya menyebut `args_pattern`].
4. **Registry run di memori.** Saat start, manager membersihkan container `kk.managed=1` yang tertinggal.
5. **Batas waktu dan artefak:** `wait=true` dibatasi `timeout_s + 30` dtk; artefak ≤ 1 MiB masing-masing [Menebak].
6. **Tmpfs:** `/tmp` 256 MiB noexec, `/home/sandbox` 64 MiB [Menebak].
7. **Uji isolasi** memakai image produk (`sandbox-python`, `sandbox-node`) dengan profil uji `probe.python` yang hanya ada di test: probe Python ditulis ke workspace dan melaporkan JSON. Profil nyata dari `sandbox-profiles.yaml` juga dijalankan.
8. **Artefak lewat bind folder per run** di `<project>/.kk-runs/<run_id>` (konflik #36): di dalam folder project agar kuota per project mencakupnya, di luar semua workspace yang bisa di-mount run. Dibaca dengan `O_NOFOLLOW` sebagai file reguler ≤ 1 MiB. Folder 0700 milik 10001. Di production manager wajib uid 10001 atau root (`check_process_user`); 0777 hanya di luar production [Menebak].
9. **Base image dipin digest**; `BASE_IMAGE` boleh menunjuk mirror dengan digest yang sama. CA proxy build opsional lewat build secret `extra_ca`, tidak pernah masuk layer.
10. **Dependensi image** dipin dengan hash (`sandbox-images/lock.sh`, `pip install --require-hashes`); bit setuid/setgid dihapus dari rootfs.
11. **`KK_REQUIRE_DOCKER=1`** di CI: daemon atau image yang hilang membuat test gagal, bukan skip.
12. **Profil `node.npm_test` tanpa JUnit** [Menebak]: reporter JUnit `node --test` bergantung pada skrip test project. Bukti hasil = exit code, artinya "skrip `test` project keluar 0"; ringkasan per kasus menyusul di WP-4.x.
13. **Watchdog folder artefak** tiap 1 dtk, batas 8 MiB [Menebak]. Workspace sendiri dibatasi kuota per project di production dan diukur setelah run; pengukuran gagal-tertutup.
14. **Kode error yang menandai bukti tidak lengkap:** `DISK_LIMIT`, `DISK_UNMEASURABLE`, `WORKSPACE_UNSAFE`, `OOM_KILLED`, `ARTIFACT_MISSING`, `ARTIFACT_REJECTED`, `CONTAINER_NOT_REMOVED`, `DOCKER_ERROR` (dengan log status dan pesan Docker), `DOCKER_UNAVAILABLE`, `IMAGE_MISSING`, `MANAGER_ERROR`; flag `log_incomplete`. Profil menyatakan artefak wajibnya (`artifacts: [junit]`).
15. **JUnit adalah klaim project, bukan bukti.** Kode test tak tepercaya dapat menulis laporan apa pun dan keluar 0. Exit code dari manager adalah bukti; laporan hanya memperinci dan tidak pernah membalik exit non-zero. Mitigasi (plugin pytest milik image, jalur hasil terpisah) diserahkan ke WP-4.x.
16. **`client_request_id`** (opsional, ≤ 64 karakter) membuat POST yang diulang setelah respons hilang tidak menjalankan run kedua. Ulangan harus identik (project, task, workspace, profil, args, timeout, network, read_only); bila tidak → `IDEMPOTENCY_CONFLICT`.
17. **Penghapusan pohon tak tepercaya berbasis descriptor folder.** Isi sub-folder diangkat ke folder teratas dengan `rename` antar-descriptor, sehingga kedalaman melewati PATH_MAX dan folder terkunci tetap terhapus. Pengukurannya gagal-tertutup (`DISK_UNMEASURABLE`).
18. **Sisa risiko log (review keamanan N4)** [Kemungkinan Besar]: banjir baris sangat pendek dapat membuat rotasi json-file membuang entri sebelum terbaca, tanpa flag. Batasnya dibuat longgar (64 MiB × 2). Status run tidak pernah bergantung pada log.

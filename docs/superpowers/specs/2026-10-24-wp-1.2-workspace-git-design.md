## Intent

WP-2.1 (Projects, workspace & git API) dan WP-3.1 (tool `repo.*`, `code.*`, `git.*`) butuh satu lapisan library yang aman untuk menyentuh file dan Git. Semua kontrol T2 (workspace escape) dan T9 (data loss) ditegakkan di sini, sekali, sehingga route dan tool tidak bisa lupa menegakkannya.

**Goals**
1. Satu resolver path: semua akses file lewat sini. Resolver menolak path absolut, `..`, NUL, symlink yang keluar root, dan path di denylist sesuai *siapa* yang mengakses (user/agent, baca/tulis).
2. Operasi file:
   - baca (biner/terlalu besar → metadata saja);
   - tulis atomik dengan version check `expected_sha256` (409);
   - hapus dan buat folder;
   - tree dengan batas kedalaman dan jumlah entri.
3. Apply unified diff yang **semua-atau-tidak-sama-sekali**: konflik → tidak ada file yang berubah, dan error memuat detail per hunk.
4. Import zip/tar/tar.gz yang menolak:
   - traversal, path absolut;
   - symlink, hardlink, device;
   - bomb (rasio, jumlah file, ukuran);
   - duplikat atau overwrite, `.git`.
5. GitAdapter dengan argumen list (tanpa shell), env bersih, hook mati, protokol dibatasi, dan **tanpa discovery repo**. Isinya:
   - init, status;
   - diff terstruktur;
   - log, branch;
   - worktree per task;
   - commit, merge dengan deteksi konflik.
6. Deteksi stack deterministik dari file penanda, tanpa eksekusi.
7. Enam template Python/Node yang lulus test **tanpa network**.

**Non-goals**
- Route HTTP, tabel DB, dan service project (WP-2.1). `Envelope[T]`/`response_model` dan `require_permission(project_id)` ditunda dari WP-1.1 dan **diteruskan ke WP-2.1**, karena WP-1.2 tidak punya route.
- Pencarian teks/simbol dan indeks (FR-020/021/023). Di WBS, keduanya bagian WP-2.1, meskipun ROADMAP R2.2 memasukkannya ke Workspace & Git. Lihat Konflik.
- `clone_https` / import remote (FR-016, P1): ditunda ke WP yang mengerjakan `git_https`. Bendera protokol tetap dipasang di setiap panggilan git sekarang.
- Kuota 2 GB per project saat menulis (ADR-005): butuh pencatatan pemakaian di service (WP-2.1). WP-1.2 menyediakan `disk_usage()` dan batas per file/arsip.
- Context builder untuk LLM, secret scan isi file (FR-024/025 bagian isi): WP-3.1. WP-1.2 hanya menyediakan keputusan "path ini boleh dikirim ke LLM".

**Anti-goals**
- **Byte apa pun ditulis di luar root**, atau dibaca lewat symlink yang keluar root, termasuk lewat race (TOCTOU) antara cek dan buka.
- **Agent atau user menulis ke `.git`**, ke file secret, atau ke path `.agentignore`.
- **Perintah dari isi repo (config/hook/filter/fsmonitor) berjalan di control plane** ketika backend memanggil git (temuan snapshot ".git/config → eksekusi host").
- **Patch setengah jadi**, atau perubahan user tertimpa diam-diam.
- **Arsip yang ditolak meninggalkan file** di workspace.

## Approaches

| | Pendekatan | Trade-off | Status |
|---|---|---|---|
| A | Library murni (`app/workspace`, `app/gitops`) tanpa DB. Operasi blocking jalan di `asyncio.to_thread`; git lewat `asyncio.create_subprocess_exec` | Mudah diuji tanpa DB dan bisa dipakai bersama route (WP-2.1) dan tool (WP-3.1). Async wrapper menambah sedikit boilerplate. | **dipilih** |
| B | Service + route sekaligus di WP ini | Melompati batas WBS (WP-2.1) dan memperbesar diff 🔒 yang harus di-review | ditolak |
| C | Library Git (pygit2/dulwich) menggantikan CLI | Tanpa subprocess, tetapi ARCHITECTURE §4.2/§7 menetapkan git CLI berargumen tetap. Dependensi native baru juga butuh review supply-chain. | ditolak |

Untuk safe path, ada dua cara:
- **`realpath` saja**, lalu `is_relative_to(root)`. Ini rentan race: komponen bisa ditukar menjadi symlink antara cek dan `open`.
- **`realpath` + buka per komponen** dengan `O_NOFOLLOW` dari fd root (gaya `openat`). **Dipilih.** Path hasil `realpath` tidak mengandung symlink, jadi bila saat dibuka ternyata ada symlink, berarti path ditukar dan operasi ditolak.

### 1.2a — `paths.py`, `fs.py`, `patches.py`

**Akses.** `Access = USER_READ | USER_WRITE | AGENT_READ | AGENT_WRITE`. Keputusan denylist bergantung pada akses:

| Kelompok | USER_READ | USER_WRITE | AGENT_READ (= kirim ke LLM) | AGENT_WRITE |
|---|---|---|---|---|
| segmen `.git` di kedalaman mana pun | tolak | tolak | tolak | tolak |
| file secret: `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_dsa*`, `id_ecdsa*`, `id_ed25519*`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `.netrc`, `.git-credentials`, `.npmrc`, `.pypirc` | boleh (file milik user) | tolak | tolak | tolak |
| pola di `.agentignore` (sintaks gitignore, tanpa `!`) | boleh | tolak | tolak | tolak |
| file `.agentignore` itu sendiri | boleh | boleh | boleh | tolak |
| folder dependensi/build: `node_modules`, `dist`, `build`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`, `.tox`, `coverage`, `.next`, `target` | boleh | boleh | tolak | boleh |

- **USER_READ hanya menolak `.git`.** `.env` milik user boleh dibuka di IDE miliknya sendiri. AC-15 adalah soal secret *provider*, dan file ini tidak pernah dikirim ke LLM karena AGENT_READ menolaknya.
- Denylist dicek pada **path yang diminta dan path hasil resolve**. Contoh: symlink `notes -> .env` tetap ditolak untuk AGENT_READ.

**Resolve.**
- **Validasi string.**
  - Tolak: string kosong, NUL, `\`, path absolut, segmen `..`, segmen > 255 byte, total > 4096 byte.
  - `.` dan segmen kosong dinormalisasi.
- **`resolve(root, rel, access)`** menjalankan langkah berikut:
  1. `realpath` path tersebut;
  2. hasilnya wajib `is_relative_to(realpath(root))`;
  3. cek denylist pada path diminta dan path hasil resolve;
  4. untuk `*_WRITE`, tolak bila path diminta ≠ path hasil resolve. **Penulisan tidak pernah melewati symlink.**
- **Pembukaan file.** File dibuka dengan berjalan komponen demi komponen dari fd root (`O_NOFOLLOW`, `O_DIRECTORY` untuk folder). Symlink yang muncul di tengah → `PathViolation`.
- **Error:** `PathViolation` → `AppError(400, "PATH_VIOLATION")`. Pesannya tidak memuat path absolut.

**Baca.** `read_file(root, rel, access, *, max_bytes, start_line=None, end_line=None) → FileContent{path, content|None, encoding: "utf-8"|"binary", size, sha256, too_large}`.
- Biner bila ada NUL di 8 KB pertama atau isinya bukan UTF-8 valid.
- `too_large` bila `size > max_bytes`. Defaultnya: USER 1 MiB [Menebak], AGENT 256 KB (ARCHITECTURE §7).
- `sha256` selalu dihitung dari isi penuh.

**Tulis.** `write_file(root, rel, content, access, *, expected_sha256)`. Nilai `expected_sha256` menentukan perilaku:

| `expected_sha256` | Perilaku |
|---|---|
| string | isi saat ini wajib ber-sha itu, selain itu → `VersionConflict` (409 `VERSION_CONFLICT`) |
| `None` | file wajib belum ada (API `expected_sha256: null` = buat baru) |
| `ANY_VERSION` | tanpa cek; untuk agent di worktree-nya sendiri |

- **Atomik:**
  1. tulis ke file sementara di folder yang sama (`O_EXCL|O_NOFOLLOW`);
  2. `fsync`;
  3. cek versi dan `os.replace` di bawah `flock` pada fd folder root (lintas proses `uvicorn`/worker).
- **Batas:** 5 MiB per file [Menebak].
- **Mode file:** file baru 0644; file lama mempertahankan mode-nya, tanpa setuid/setgid.
- **Folder induk** yang belum ada dibuat (0755) lewat jalur `O_NOFOLLOW` yang sama.
- `delete_file(..., expected_sha256)` dan `make_dir(...)` mengikuti aturan yang sama. Hapus folder rekursif adalah v2.
- Hasil: `FileChange{path, change: created|modified|deleted, old_sha256, new_sha256, size}`.

**Tree.** `tree(root, rel=".", access, depth=3, max_entries=500) → TreeResult{entries, truncated}`.
- `entries` sesuai bentuk API: `{path, name, type: file|dir, size, children?}`.
- Folder didahulukan, lalu urut nama.
- `.git` disembunyikan. Untuk AGENT_READ, path yang ditolak juga disembunyikan.
- Symlink yang keluar root atau menggantung tidak ditampilkan.
- Symlink ke folder di dalam root ditampilkan tanpa diturunkan, sehingga tidak ada loop.

**`disk_usage(root)`**: total byte file reguler. Dipakai service untuk kuota (WP-2.1).

**Patch.** `apply_unified_diff(root, diff, access) → list[FileChange]`.
- **Parse** format git/unified:
  - `diff --git` opsional, `---`/`+++`, `/dev/null` untuk tambah/hapus, `@@` hunk;
  - `\ No newline at end of file`.
- **Ditolak** dengan 400 `BAD_REQUEST`: rename, copy, mode change, patch biner, path ganda, diff > 1 MiB, > 200 file.
- **Penerapan** dilakukan ke salinan di memori:
  - konteks wajib sama persis di posisi yang tertulis, atau di satu-satunya posisi lain (offset, **tanpa fuzz**);
  - perbandingan baris mengabaikan `\r\n` vs `\n`;
  - baris baru memakai EOL dominan file.
- **Konflik** → `PatchConflict` (409 `CONFLICT`, `details: [{path, hunk, reason}]`), dan **tidak ada file yang disentuh**.
- **Fase tulis** berjalan di bawah `flock` yang sama:
  1. semua file sementara ditulis dulu;
  2. lalu `os.replace` berurutan;
  3. bila satu replace gagal, isi lama dipulihkan (best effort). Kegagalan pemulihan dicatat di log error.

### 1.2b — `archive.py`

`import_archive(archive_path, dest, *, limits=ArchiveLimits()) → ImportReport{files, bytes, stripped_prefix}`, dengan `on_progress(files, bytes)` opsional (FR-015).

- **Format** ditentukan dari magic byte (bukan dari ekstensi):
  - zip;
  - tar.gz (gzip + tar);
  - tar polos.

  Selain itu → `ARCHIVE_REJECTED`.
- **`dest` wajib belum ada.** Ekstraksi masuk ke folder staging di sebelah `dest`, lalu di-`rename`. Gagal → staging dihapus. Tidak ada overwrite.
- **Batas** (ADR-005):

  | Batas | Nilai |
  |---|---|
  | ukuran arsip | 200 MB |
  | total ekstraksi | 1 GB, dihitung dari **byte nyata** yang keluar, bukan ukuran yang diklaim header |
  | jumlah entri | 50.000 |
  | rasio kompresi | total ekstraksi / ukuran arsip > 100 → tolak |
  | rasio per entri zip | > 100 untuk entri > 1 MiB → tolak [Menebak, ambang per entri] |

  Rasio dicek **sambil streaming**, sehingga bomb berhenti sebelum disk penuh.
- **Validasi entri.** Seluruh arsip ditolak, bukan entri dilewati, bila ada:
  - nama yang gagal validasi string 1.2a;
  - symlink, hardlink, device, atau FIFO (hanya file reguler dan folder yang diterima);
  - path ganda, atau konflik file vs folder;
  - segmen `.git`.
- **Satu folder pembungkus di puncak dikupas.** Contoh: semua entri di bawah `proj-main/` → `proj-main/` dihapus dari path.
- **Mode file:** 0644, atau 0755 bila arsip menandai executable. Folder 0755. setuid/setgid tidak pernah dipertahankan.
- **Error:** `ArchiveRejected(reason)` → 400 `ARCHIVE_REJECTED`, `details.reason` ∈ {`format`, `oversize`, `too_many_files`, `ratio`, `traversal`, `absolute`, `link`, `device`, `duplicate`, `git_dir`, `invalid_name`}.
- **Fixture** dibangkitkan oleh `conftest.py` (TEST_STRATEGY §4), bukan biner di repo.

### 1.2c — `gitops/adapter.py`

- **`_run`** memanggil `asyncio.create_subprocess_exec("git", *args)`:
  - **Tanpa shell.** `start_new_session=True`; timeout → `killpg`.
  - **stdout dibatasi 16 MiB** [Menebak] → `GitError("GIT_OUTPUT_TOO_LARGE")`.
  - **Env dibangun dari nol:**
    - `PATH=/usr/bin:/bin`, `HOME=<folder kosong>`, `LANG=C.UTF-8`;
    - `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_ATTR_NOSYSTEM=1`;
    - `GIT_OPTIONAL_LOCKS=0`, `GIT_ASKPASS=/bin/false`, `GIT_EDITOR=/bin/false`.
  - **Prefix `-c` di setiap panggilan:**
    - `core.hooksPath=/dev/null`;
    - `protocol.allow=never`, `protocol.https.allow=always`;
    - `core.fsmonitor=false`, `core.pager=cat`;
    - `credential.helper=` (mengosongkan daftar);
    - `submodule.recurse=false`;
    - `commit.gpgSign=false`, `tag.gpgSign=false`.
- **Tanpa discovery.** Setiap panggilan memakai `--git-dir` dan `--work-tree` eksplisit:
  - untuk repo utama, `--git-dir=<repo>/.git`;
  - untuk worktree task, `--git-dir=<repo>/.git/worktrees/<nama>`.

  File `.git` di dalam worktree, yang bisa ditulis ulang oleh kode di sandbox, **tidak pernah dibaca**. Ini menutup temuan snapshot: `.git` palsu → `core.fsmonitor`/filter berjalan di control plane. Lapisan pertahanan tambahan:
  - `diff`/`log`: `--no-ext-diff --no-textconv --no-color`;
  - `commit`: `--no-verify`;
  - `merge`: `--no-verify`.
- **Validasi input:**
  - nama branch: `^[A-Za-z0-9][A-Za-z0-9._/-]{0,199}$`, tanpa `..`, `@{`, `//`, akhiran `.lock`/`/`/`.`;
  - ref: sha hex 7–40 atau nama branch valid;
  - pesan commit: 1–5000 karakter, tanpa NUL;
  - path: lewat validasi string 1.2a, dan selalu diletakkan setelah `--`.
- **API.** Bentuknya mengikuti ARCHITECTURE §4.2 + API_CONTRACTS §3:

  | Method | Hasil |
  |---|---|
  | `init(path, default_branch)` | — |
  | `status(repo)` | `GitStatus{branch, head, clean, changes[{path, status}]}`, dari `--porcelain=v2 -z --branch --untracked-files=all --no-renames` |
  | `diff(repo, base=None, head=None, paths=None, max_bytes)` | `Diff` sesuai API_CONTRACTS, termasuk file untracked sebagai `added` |
  | `log(repo, limit)` | — |
  | `branches(repo)` | — |
  | `create_branch(repo, name, from_ref)` | — |
  | `current_commit(repo)` | — |
  | `create_worktree(repo, path, branch, base)` | worktree `kk/task-<8hex>` (ADR-016) |
  | `remove_worktree(repo, path)` | `--force`: task yang dibatalkan boleh kotor |
  | `commit_all(target, message, author)` | sha |
  | `merge_branch(repo, branch, message)` | `MergeResult{merged, commit, conflicts[]}` |

  Detail `merge_branch`:
  - konflik → `git merge --abort` dan working tree kembali bersih;
  - working tree repo yang kotor → `MergeResult(conflicts=…, reason="dirty")` **tanpa** mencoba merge;
  - tidak ada fast-forward diam-diam, karena `--no-ff` menyimpan jejak merge per task.
- **Force:** tidak ada `push`, `--force`, `reset --hard`, atau `clean` di adapter. `remove_worktree --force` adalah satu-satunya pengecualian dan hanya menyentuh `tasks/<id>`.
- **Error:** `GitError(code, message)` → 409 `GIT_ERROR`. stderr dipotong 2 KB dan diredaksi. Path absolut root workspace diganti `<workspace>`.

### 1.2d — `stack.py`, template

- **`detect_stack(root) → Stack`** {languages, frameworks, package_managers, test_profiles, entrypoints}, terurut dan deterministik.
  - Sumbernya hanya file penanda kecil (≤ 256 KB) di root dan folder level 1, dibaca lewat resolver dengan AGENT_READ.
  - Tidak ada eksekusi.
  - Python:
    - `pyproject.toml` dibaca dengan `tomllib`, `requirements*.txt`, `setup.cfg`/`setup.py`;
    - package manager dari lockfile (`uv.lock` → uv, `poetry.lock` → poetry, `Pipfile.lock` → pipenv, selain itu pip);
    - framework fastapi/flask/django dari dependensi;
    - `python.pytest` bila pytest ada di dependensi atau ada `tests/`/`test_*.py`.
  - Node:
    - `package.json` (`json`), lockfile npm/pnpm/yarn/bun;
    - framework express/react/vite/next/vue;
    - `node.npm_test` bila `scripts.test` ada;
    - TypeScript bila ada `tsconfig.json` atau dependensi `typescript`.
  - Go/Rust/Java hanya dicatat sebagai bahasa, tanpa profil (pack = v2.2).
  - Entrypoint dicari dari daftar kandidat tetap, misalnya `main.py`, `app/main.py`, `manage.py`, field `main`, `index.js`, `src/index.ts`, `server.js`.
- **Template.** Ada di `app/workspace/templates/<id>/` dengan `template.toml` {id, name, description, stack, icon}.
  - `materialize(template_id, dest, project_name, project_slug)` menyalin file. Substitusinya hanya `{{project_name}}` (README) dan `{{project_slug}}` (TOML/JSON), memakai `str.replace` tanpa engine template. Slug divalidasi `^[a-z0-9][a-z0-9-]{0,62}$`.
  - Enam template, semuanya **tanpa dependensi network** untuk test-nya. Masing-masing berisi `README.md` dengan cara menjalankan (FR-014) dan `.gitignore`:

    | id | Isi | Test (profil) |
    |---|---|---|
    | `python-basic` | paket + modul contoh | `pytest` (`python.pytest`) |
    | `python-cli` | CLI `argparse` | `pytest` |
    | `python-fastapi` | app FastAPI + endpoint health | `pytest` + `TestClient` (butuh fastapi/httpx di image sandbox) |
    | `node-basic` | modul ESM | `npm test` → `node --test` (`node.npm_test`) |
    | `node-http-api` | server `node:http` tanpa dependensi | `npm test` → `node --test` |
    | `static-site` | HTML/CSS/JS + modul logika | `npm test` → `node --test` |

  - Template diuji di CI kita: materialize → jalankan test-nya, ditambah `ruff check` untuk template Python. Ini kode kita sendiri yang diuji di CI, bukan kode project user di control plane.

## Keputusan saya (cek)

1. **USER_READ boleh membuka `.env`** milik project. AGENT_READ, USER_WRITE, dan AGENT_WRITE menolaknya. ARCHITECTURE §7 menyebut denylist tulis dan denylist kirim-ke-LLM, tidak menyebut baca oleh user.
2. **`.env.example` ikut ditolak untuk ditulis** karena kontraknya `.env*`. Akibatnya user tidak bisa mengedit `.env.example` lewat IDE (template tetap bisa membuatnya). Perlu keputusan PO bila ini mengganggu.
3. **Ada daftar file kredensial tambahan** di luar kontrak: `.npmrc`, `.pypirc`, `.netrc`, `.git-credentials`, keystore, dan varian kunci SSH.
4. **`.agentignore` tanpa negasi `!`.** Dengan begitu pola user tidak bisa membuka kembali denylist bawaan.

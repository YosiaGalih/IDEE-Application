## Intent dan perubahan cakupan

Rencana lanjutan (U10) dan WBS WP-1.4 menyebut layar login, dashboard, projects, agents, dan approvals. Backend di repo saat ini hanya punya route `auth` dan `health` [Pasti, `backend/app/api/routes/`]. Endpoint `/dashboard`, `/projects`, `/agents`, dan `/approvals` belum ada; masing-masing milik WP-2.1, WP-3.1, dan WP-INT-03. Layar untuk endpoint itu hanya bisa dibangun di atas mock MSW. Mock itu tidak bisa diverifikasi ke backend nyata, dan berisiko dikerjakan ulang ketika kontrak berubah di WP tersebut.

**Keputusan Lead (konflik #63):**
- 1.4b mencakup semua yang API-nya sudah ada: login, logout, lupa dan reset password, ganti password, penjaga sesi, dan menu pengguna.
- Layar dashboard, projects, agents, dan approvals dikerjakan bersama WP backend masing-masing, sehingga satu PR berisi API dan layarnya.

**Goals**
1. **`/login`:**
   - email, password, "ingat saya";
   - validasi lokal (Zod) sebelum kirim;
   - 401 tampil sebagai satu pesan generik (tidak membedakan email salah, password salah, atau akun terkunci);
   - 429 menampilkan waktu tunggu dari `Retry-After`;
   - 503 dan jaringan putus menampilkan state yang sesuai;
   - tombol nonaktif saat mengirim.
2. Setelah login, pengguna diarahkan ke `?next=` bila nilainya path internal yang aman, selain itu ke `/`. Tidak ada open redirect.
3. **Penjaga sesi:** semua route di dalam layout aplikasi memanggil `useMe`.
   - Saat memuat, tampil state loading.
   - 401 mengarahkan ke `/login?next=<path sekarang>`.
   - Error lain tampil lewat `StateView` dengan aksi coba lagi.
   - Halaman publik (`/login`, `/forgot-password`, `/reset-password/:token`) tidak dijaga, dan handler 401 global tidak memantulkannya.
4. **Menu pengguna** di top bar: nama tampilan, ganti password, keluar. Keluar memanggil `useLogout` (cache dikosongkan) lalu ke `/login`, termasuk bila logout gagal di server.
5. **`/forgot-password`:** setelah 200 selalu menampilkan pesan generik yang sama, terdaftar atau tidak (tidak ada enumerasi email). Isinya "permintaan diterima; bila email terdaftar, tautan sudah dibuat; bila tidak sampai, hubungi admin", karena email baru ada di P1 (konflik #64). 429 ditampilkan sebagai batas percobaan beserta waktu tunggunya: batasnya per IP (`kk:rl:forgot:{ip}`), jadi tidak membocorkan apa pun, sedangkan "sudah dikirim" pada 429 adalah klaim palsu.
6. **`/reset-password/:token?`** (satu route, sehingga state halaman bertahan saat URL diganti):
   - token dibaca ke state, lalu URL diganti menjadi `/reset-password` (`navigate(..., { replace: true })`) agar token tidak tersimpan di riwayat. Muat ulang setelah itu menampilkan "buka lagi tautan dari email";
   - password baru dan konfirmasi divalidasi lokal (12–1024 karakter dihitung per code point seperti `len` Python, sama persis);
   - 400 tampil sebagai "tautan tidak valid atau kedaluwarsa";
   - setelah sukses, pengguna diarahkan ke `/login` dengan pesan.
7. **Ganti password:** dialog dari menu pengguna (password lama, password baru, konfirmasi).
   - 403 = password lama salah;
   - 409 = password berubah di tempat lain, pengguna diminta masuk ulang;
   - sukses berarti sesi lain dicabut oleh server (backend `change_password`).

**Anti-goals**
- Pesan yang membedakan "email tidak terdaftar" dari "password salah".
- `next` yang mengarah ke origin lain, ke `//host`, atau ke `javascript:`.
- Token reset tertinggal di URL atau riwayat.
- Password di log, state global, atau storage.

## Konflik baru

- **#63.** WBS WP-1.4 dan rencana lanjutan U10 memasukkan layar dashboard, projects, agents, dan approvals ke WP-1.4. API-nya belum ada di backend repo. Keputusan Lead: layar dibangun bersama WP backend masing-masing (WP-2.1, WP-3.1, WP-INT-03). WP-1.4b berisi auth, sesi, dan menu pengguna.
- **#64.** PRD/API_CONTRACTS memuat alur lupa password lewat email, tetapi pengiriman email dijadwalkan di P1: backend hanya mencetak tautan reset ke log pada `APP_ENV=development`, dan produksi tidak mengirim apa pun [Pasti, `backend/app/api/routes/auth.py` `forgot_password`]. Layar 1.4b tidak mengklaim "terkirim"; pesannya menyuruh menghubungi admin bila tautan tidak sampai. Sampai email ada, reset di produksi hanya bisa lewat admin. Perlu keputusan PO: majukan email ke P0, atau sediakan reset oleh admin/CLI.

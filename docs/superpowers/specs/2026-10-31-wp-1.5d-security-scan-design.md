## Intent

Tracker WP-1.5a, 1.5b, dan 1.5c mencatat utang yang sama: Semgrep dan Trivy belum pernah berjalan. SECURITY_MODEL §11 mewajibkan keduanya sebelum rilis, dan G1 menuntut CI yang lengkap. Unit ini menambahkan keduanya ke `security-scan` dengan gate yang:
- deterministik;
- gagal dengan keras bila scan tidak benar-benar berjalan;
- tidak merah permanen karena temuan yang belum bisa diperbaiki siapa pun.

**Goals**
1. `security-scan` menjalankan gitleaks, pip-audit, Semgrep, dan Trivy pada setiap PR, push ke `main`, dan nightly (DB CVE berubah setiap hari walau kode tidak berubah).
2. Setiap image yang berjalan di stack di-scan. Daftarnya diambil dari `docker compose config --format json` (profil `egress`): `image` setiap service ditambah nilai `SANDBOX_IMAGE_*` sandbox-manager, sehingga service baru otomatis ikut. Service tanpa nama image ditolak.
3. Setiap temuan yang diabaikan punya baris di DECISIONS (ID `EX-nn`, siapa, alasan, mitigasi, kedaluwarsa). Setelah tanggal kedaluwarsa, gate merah lagi.

**Anti-goals**
- Gate yang hijau karena scanner tidak menemukan image, gagal memuat ruleset, atau tidak mengenali OS.
- `--ignore-unfixed` menyeluruh yang ikut menyembunyikan CRITICAL dan tidak pernah kedaluwarsa.
- Exception tanpa tanggal atau tanpa baris DECISIONS.

## Approaches

| | Cara | Masalah |
|---|---|---|
| A | Trivy literal per kontrak, `--exit-code 1` | Merah permanen. Setiap PR merah, orang berhenti membaca hasilnya |
| B | `--ignore-unfixed` untuk semua | CRITICAL tanpa perbaikan ikut tersembunyi, tidak ada kedaluwarsa, dan tidak ada baris DECISIONS. Pelemahan diam-diam |
| **C (dipilih)** | Satu JSON per image, lalu gate stdlib `infra/security/scan_gate.py` dengan aturan eksplisit dan exception berkedaluwarsa | Kode tambahan sekitar 200 baris, diuji unit test dan mutan |

## Keputusan

### Trivy

- **Versi.** `aquasec/trivy:0.75.0@sha256:af6acf9a6b85dfe389a1941505c0ce9efef52a4719635e1a962f022a3d855daa`. Dirilis 1 Okt, lolos batas umur repo (`exclude-newer` 10 Okt). Dijalankan sebagai container dengan socket Docker runner untuk membaca image lokal (runner sekali pakai). DB dari repositori bawaan Trivy (`mirror.gcr.io`, lalu `ghcr.io`).
- **Scan.** `--scanners vuln --severity HIGH,CRITICAL --format json --ignorefile ''`. Exception tidak memakai `.trivyignore`; semuanya ada di gate supaya satu tempat, teruji, dan bertanggal.
- **Aturan gate** per temuan:

  | Temuan | Hasil |
  |---|---|
  | CRITICAL, dengan atau tanpa perbaikan | blok |
  | HIGH dengan `FixedVersion` | blok |
  | HIGH tanpa perbaikan | dicetak; tidak memblokir selama **EX-02** berlaku, setelah itu blok |
  | OS image sudah EOSL (`Metadata.OS.EOSL`) | blok |
  | Severity selain HIGH/CRITICAL atau tanpa severity (skema berubah) | blok |
  | Image tanpa laporan, lebih dari satu laporan untuk satu image, laporan tanpa OS atau tanpa hasil `os-pkgs`, atau JSON rusak | blok |
  | DB kerentanan lebih tua dari 2 hari (`trivy version --format json`, dicetak di setiap run) | blok |
  | Cocok dengan exception yang berlaku di `infra/security/scan-exceptions.toml` | dicetak sebagai "dikecualikan EX-nn sampai <tanggal>" |
  | Exception yang kedaluwarsa, tidak terpakai, ID-nya tidak ada di DECISIONS, atau baris DECISIONS-nya ditutup (sel kedaluwarsa bukan tanggal polos) | blok |

  Exception yang tidak cocok dengan temuan apa pun juga memblokir. Begitu upstream memperbaiki, exception harus dihapus, jadi daftar tidak membengkak diam-diam.
- **Cakupan image** (keputusan Lead, lebih ketat dari kontrak):
  - semua image di `docker compose config --images` dengan `COMPOSE_PROFILES=egress`;
  - ditambah `kodekantor/sandbox-python:1` dan `kodekantor/sandbox-node:1`.

  Kontrak hanya menyebut api/worker/web/sandbox-manager/sandbox-python/sandbox-node. Caddy (publik), postgres, redis, socket-proxy, dan egress-proxy juga berjalan di produksi, jadi ikut di-scan (konflik #57).
- **Perubahan image:**
  - `web` placeholder → `nginxinc/nginx-unprivileged:1.30-alpine@sha256:f5116ed4606f3eb015dd4a8e28cb9b351476dc0ad4bc6e9f93b19cec130cdf03` (stable). Ini menghapus 44 temuan yang sudah punya perbaikan.
  - `sandbox-node` → base `node:22-trixie-slim@sha256:2117f713a417f3aff682ac8f5bc2ebbdf1beed51f36e67ab1e0fd3866b6d2d8f`. Debian 13 sama dengan image Python; CRITICAL zlib hilang; Node tetap 22.23.4. Suite `sandbox-isolation` membuktikan profil node tetap berjalan.
  - Digest baru dibuat setelah batas umur 10 Okt. Perbaikan keamanan mengalahkan aturan umur (preseden certifi dan uv 0.13.4 / EX-01).

### Exception (DECISIONS, bagian "Pengecualian keamanan")

| ID | Cakupan | Alasan | Mitigasi | Kedaluwarsa |
|---|---|---|---|---|
| EX-02 | HIGH tanpa perbaikan di semua image | Belum ada versi perbaikan dari distro/upstream; memblokir tidak memperbaiki apa pun | Semua container non-root, `cap_drop: ALL`, `no-new-privileges`, rootfs read-only (kecuali postgres/redis yang punya volume data); sandbox `network_mode: none`. Paket terbanyak (util-linux, mount, login) butuh CAP_SYS_ADMIN/setuid yang tidak ada (bit setuid dihapus di image sandbox). Begitu Debian merilis perbaikan, temuan berubah menjadi "punya perbaikan" dan nightly memblokir, sehingga base digest harus dinaikkan | 2027-01-31 |
| EX-03 | Temuan yang punya perbaikan, tetapi hanya upstream yang bisa membangun ulang: caddy, web placeholder, socket-proxy, dependensi npm bawaan Node di sandbox-node; dicatat per CVE | Kita memakai image upstream apa adanya (dipin digest); belum ada digest yang lebih baru dengan perbaikan | caddy dan nginx: brotli/curl hanya dipakai `curl`, yang tidak dijalankan (healthcheck memakai `wget` busybox); Go stdlib caddy menunggu rilis Caddy. socket-proxy hanya di network `exec` privat, config HAProxy tetap. npm berjalan di sandbox tanpa network, dan sandbox memang menjalankan kode tak tepercaya, jadi bug npm tidak menembus batas isolasi | 2026-11-30 (30 hari; dicek ulang setiap bulan) |
| EX-04 | Seluruh temuan di `usr/local/bin/gosu` image postgres | `gosu` hanya dipanggil `docker-entrypoint.sh` saat container berjalan sebagai root. Compose menjalankan postgres sebagai `70:70`, jadi gosu tidak pernah dieksekusi | Test kebijakan compose memastikan `postgres.user` tetap `70:70` selama EX-04 ada | 2027-01-31 |
| EX-05 | Semgrep `avoid-sqlalchemy-text` di `grant_runtime_role` | False positive: identifier DDL tidak bisa di-bind; nama role divalidasi allowlist dan harus ada | Test `test_db_roles.py`; fungsi hanya dipanggil CLI migrate | 2027-01-31 |
| EX-06 | `redis:7.4.11-alpine` di Alpine 3.21, end of life 1 Nov 2026 | Image redis 7.4 terbaru masih Alpine 3.21; jalan keluarnya (Redis 8 berlisensi AGPL/SSPL/RSAL, atau Valkey) keputusan PO (konflik #58) | Network privat `app`, `requirepass`, data dapat dibuang | 2026-11-30 |

Format `scan-exceptions.toml`: satu tabel per exception dengan `id`, `until`, dan `image` (referensi persis; digest `@sha256:…` boleh menyusul). Isinya tepat satu dari tiga bentuk: `vulns` + `pkgs` (CVE hanya di paket itu), `pkg_path` (semua temuan di satu biner), atau `eosl = true` (OS end of life; boleh belum terpakai). Status persetujuan baris DECISIONS ("menunggu persetujuan PO") dicetak di setiap baris yang dikecualikan. Test kebijakan memastikan:
- setiap `id` ada di DECISIONS dengan tanggal kedaluwarsa yang sama;
- `until` tidak lebih dari 92 hari dari hari ini;
- `image` cocok dengan salah satu image dalam cakupan.

### Semgrep

- **Versi.** `semgrep==1.180.0` (7 Okt) lewat `uvx --exclude-newer 2026-10-10T00:00:00Z`, sama seperti pip-audit. `--metrics=off`.
- **Ruleset.** `p/python`, `p/secrets`, `p/docker-compose` (SECURITY_MODEL §11). `p/typescript` dan `p/react` ditambahkan di WP-1.4.
- **Target.** Seluruh repo. `.semgrepignore` mengecualikan:
  - `docs/`;
  - folder test (`backend/tests/`, `sandbox_manager/tests/`, `infra/tests/`), karena fixture keamanan sengaja memuat pola berbahaya;
  - file lock.
- **Gate.** Hasil JSON dibaca `scan_gate.py semgrep`:
  - blok bila ada temuan dengan severity selain `WARNING`/`INFO`, termasuk severity kosong atau tidak dikenal (fail closed);
  - blok bila ada error scan apa pun, berapa pun level-nya; `--timeout 30` mengurangi timeout per rule;
  - blok bila file penanda (`backend/app/main.py`, `sandbox_manager/sandbox_manager/app.py`, `infra/compose.yml`) tidak ada di `paths.scanned`, atau bila file yang di-scan kurang dari `--min-files 150` (186 pada 31 Okt);
  - temuan `WARNING`/`INFO` dicetak, tidak memblokir.
- **Exception.** Exception Semgrep ditulis sebagai `# nosemgrep: <rule-id> (EX-nn)` di baris temuan atau baris tepat di atasnya. `<rule-id>` harus `check_id` lengkap; ID registry mengulang bagian terakhirnya, misalnya `…audit.avoid-sqlalchemy-text.avoid-sqlalchemy-text`. Prefix tanpa bagian terakhir tidak dikenali, dan ini terbukti di run CI kedua. Test kebijakan memeriksa bahwa `EX-nn` ada di DECISIONS dengan kedaluwarsa di masa depan dan paling lama 92 hari, aturan yang sama dengan exception Trivy.
- **Hasil run CI pertama** (31 Okt, 199 rule, 186 file):
  - 1 ERROR: `avoid-sqlalchemy-text` di `backend/app/core/db_roles.py`, loop GRANT/REVOKE. DDL tidak bisa memakai bind parameter untuk identifier; satu-satunya nilai variabel adalah nama role yang lolos regex allowlist dan harus ada di `pg_roles`. Dicatat sebagai false positive **EX-05**.
  - 6 WARNING `insecure-file-permissions` untuk `chmod 0o700/0o755/0o777`. Semuanya disengaja dan sudah dijelaskan di kodenya, dan tidak memblokir.

### Penempatan job

- `security-scan` dipindah dari `backend.yml` ke `.github/workflows/security.yml`, dengan trigger `pull_request`, push `main`, nightly `cron`, dan `workflow_dispatch`. `backend.yml` tidak punya jadwal; Trivy butuh nightly.
- Urutan langkah:
  1. gitleaks;
  2. pip-audit backend (pip-audit sandbox_manager dan image sandbox-python tetap di `sandbox.yml`);
  3. Semgrep dan gate-nya;
  4. build image sendiri (`compose build`, `make sandbox-images`) dan pull image pihak ketiga (`compose pull --ignore-buildable`);
  5. Trivy per image;
  6. gate Trivy.
- Gate Trivy menerima daftar image yang diharapkan dan folder laporan. Image yang tidak punya laporan berarti merah.

## Konflik untuk AG-00 / PO

- **#56.** SECURITY_MODEL §11 menulis perintah Trivy literal dengan `--exit-code 1` dan kriteria "0 critical/high tanpa exception". Faktanya 44+ HIGH di setiap image Debian tidak punya perbaikan. Unit ini memakai exception EX-02 (HIGH tanpa perbaikan, berkedaluwarsa) dan EX-04 (gosu tidak dieksekusi). Usul: §11 merujuk aturan gate di spec ini, bukan perintah literal.
- **#57.** Cakupan image §11 tidak memuat image pihak ketiga yang berjalan di produksi (caddy, postgres, redis, socket-proxy) maupun egress-proxy. Unit ini men-scan semuanya, dengan exception EX-03 berkedaluwarsa 30 hari untuk temuan yang hanya bisa diperbaiki upstream. Biayanya: setiap bulan ada pekerjaan cek ulang, dan CVE baru di image upstream membuat PR merah sampai exception ditulis atau digest dinaikkan.

## Yang diserahkan ke builder

Nama langkah CI, format cetakan gate, dan pembagian fungsi di `scan_gate.py` (stdlib saja: `json`, `tomllib`, `argparse`, `datetime`).

## Intent

Sesi manusia adalah satu-satunya pintu ke otoritas R3 (CLAUDE.md #5). Kalau pintu ini lemah, seluruh kontrol berikutnya ikut lemah. WP ini membangun pintu itu persis seperti kontrak, tanpa menambah fitur. SSO, email reset, dan MFA = P1.

**Goals**
- `/auth/login`, `/auth/logout`, `/auth/me`, `/auth/password/{forgot,reset,change}` sesuai tabel API_CONTRACTS §2.
- Cookie `kk_session` dan `kk_csrf`, CSRF double-submit, rate limit 10/menit/IP, lockout 15 menit setelah 5 gagal.
- Event audit `auth.*` dan dependency `current_user` / `require_permission` untuk route berikutnya.

**Non-goals**
- Endpoint admin reset-token (WP admin).
- Idempotency-Key: middleware umum, WP terpisah. Endpoint auth dikecualikan dari replay.
- Header keamanan Caddy (WP-1.5).
- `require_project_permission`: menunggu tabel `projects` (WP-2.1).

**Anti-goals** (gagal walau "jalan"):
- respons yang membedakan "email tidak ada", "akun terkunci", dan "password salah";
- token sesi, token reset, atau hash password muncul di log, audit, atau response;
- route mutasi yang lolos tanpa CSRF.

## Approaches

| | Pendekatan | Trade-off | Status |
|---|---|---|---|
| A | Sesi opaque di PostgreSQL (`sessions`, sha256 token), cookie HttpOnly | Satu query per request. Revokasi langsung. Sesuai kontrak dan CLAUDE.md #4. | **dipilih** |
| B | JWT stateless | Tidak bisa dicabut saat logout atau reset tanpa denylist. Bertentangan dengan `sessions` di DATA_MODEL. | ditolak |
| C | Sesi di Redis | Dua sumber kebenaran. Redis bukan source of truth. | ditolak |

Penempatan CSRF:
- **Middleware ASGI** untuk semua POST/PUT/PATCH/DELETE. Ini fail-safe: route baru otomatis terlindungi.
- Ditambah **pengikatan ke sesi** di dependency `current_user`: header harus sama dengan `sessions.csrf_token`.
- Alternatif "dependency per route" ditolak karena satu route yang lupa diberi dependency = celah.

## Desain

### Modul
- `app/core/ratelimit.py`: `FixedWindowLimiter(redis)`, dengan `hit(key, limit, window_s) -> RateDecision(allowed, retry_after)`. Implementasinya `INCR` + `EXPIRE NX` dalam satu pipeline.
- `app/core/csrf.py`: `CsrfMiddleware`.
- `app/services/auth.py`: logika `login`, `logout`, `resolve_session`, `request_password_reset`, `reset_password`, `change_password`. Tidak mengimpor FastAPI.
- `app/services/users.py`: `validate_new_password` (12–1024 karakter) dipakai bersama `create_owner`.
- `app/api/deps.py`: `db_session`, `current_user` → `AuthContext(user, session, grants)`, `require_permission(perm)`.
- `app/api/routes/auth.py`: route tipis + skema Pydantic `UserOut`, `LoginIn`, dan seterusnya. Response tidak pernah memuat hash atau token.

### Cookie
- **`kk_session`**:
  - atribut: `HttpOnly`, `Secure=COOKIE_SECURE`, `SameSite=Lax`, `Path=/`, tanpa `Domain`;
  - `remember_me=true` → `Max-Age` = sisa umur absolut;
  - `false` → cookie sesi browser.
- **`kk_csrf`**: atribut sama, tetapi tanpa `HttpOnly`.
- **Logout** menghapus keduanya (`Max-Age=0`).

### CSRF
- Request mutasi wajib punya cookie `kk_csrf` dan header `X-CSRF-Token`. Keduanya harus sama dan tidak kosong, dibandingkan dengan `hmac.compare_digest`. Kalau tidak → 403 `CSRF_FAILED`.
- Satu-satunya pengecualian: `POST /api/v1/auth/login`.
- Request tanpa cookie `kk_csrf` mendapat cookie CSRF *pra-sesi* acak di response. Dengan begitu endpoint publik `forgot`/`reset` tetap bisa memenuhi double-submit.
- Middleware tidak menimpa `kk_csrf` yang sudah diset route. Login menggantinya dengan token milik sesi.
- Untuk request terautentikasi, `current_user` juga mewajibkan header sama dengan `sessions.csrf_token`. Cookie pra-sesi tidak berlaku untuk sesi.

### Sesi
- **Token**: `new_token()` (256 bit). Yang disimpan hanya `hash_token`.
- **Batas umur**:
  - `expires_at = created_at + SESSION_ABSOLUTE_DAYS`;
  - idle habis bila `now > last_seen_at + SESSION_TTL_HOURS`.
- **Status error**:
  - cookie tidak ada, token tidak dikenal, sesi dicabut, atau user `disabled` → 401 `UNAUTHENTICATED`;
  - lewat idle atau absolut → 401 `SESSION_EXPIRED`, dan sesi dicabut.
- `last_seen_at` diperbarui paling sering sekali per 60 detik.

### Login
1. **Rate limit IP**: `kk:rl:login:<ip>`, 10 per 60 detik. Lebih dari itu → 429 `RATE_LIMITED` + `Retry-After`. Percobaan yang ditolak di sini hanya di-log, tidak diaudit, supaya audit tidak bisa dibanjiri.
2. **Email**: di-`strip().lower()`, lalu user dicari.
3. **Satu respons untuk semua kegagalan**: email tidak ada, akun terkunci, user `disabled`, atau password salah → 401 `UNAUTHENTICATED` "Email atau password salah". Untuk email yang tidak ada, `verify_password` tetap dijalankan terhadap hash dummy supaya waktu respons setara.
4. **Password salah**: `UPDATE … SET failed_login_count = failed_login_count + 1 RETURNING`, atomik.
   - Bila mencapai 5: `locked_until = now + 15 menit`, counter kembali 0, audit `auth.lockout`.
   - Counter di-commit walau request gagal.
5. **Sukses**:
   - counter dan `locked_until` di-reset, `last_login_at` diisi;
   - hash di-rehash bila parameternya usang;
   - sesi lama dari cookie (bila ada) dicabut, lalu sesi baru dibuat (rotasi);
   - audit `auth.login` success.
6. **Audit `auth.login` denied** ditulis `write_detached` dengan `metadata.reason` ∈ {`unknown_email`, `locked`, `disabled`, `bad_password`}.
   - Untuk email tak dikenal: `actor_id="anonymous"`, dan email tidak disimpan.
   - Reason hanya ada di audit, tidak pernah di respons.

### Password
- **forgot**: publik, kena CSRF dan rate limit IP terpisah (`kk:rl:forgot:<ip>`, 10 per 60 detik). Selalu 200 `{}`. Bila user ada dan `active`:
  - token reset lama yang belum dipakai dihapus;
  - token baru dibuat dengan kedaluwarsa 30 menit;
  - audit `auth.password_reset_requested`.
  - Token hanya dikembalikan ke pemanggil service. Route mencatatnya ke log hanya bila `APP_ENV=development` (field `reset_path=/reset-password/<token>`). Di production token tidak pernah ditulis ke mana pun; admin reset-token menyusul di WP admin.
- **reset**: publik, CSRF, rate limit `kk:rl:reset:<ip>`.
  - Token dicari lewat hash dengan `FOR UPDATE`, dan harus belum dipakai dan belum kedaluwarsa.
  - Token tidak sah → 400 `BAD_REQUEST` generik.
  - Bila sah: hash baru disimpan, `used_at` diisi, **semua sesi user dicabut**, counter lockout di-reset, audit `auth.password_reset`.
- **change**: perlu auth dan CSRF.
  - `current_password` salah → 403 `FORBIDDEN`, dan kegagalan ini ikut menambah counter lockout. Ini mencegah brute force lewat sesi curian.
  - Bila sukses: hash baru disimpan, **sesi lain dicabut**, sesi ini tetap, audit `auth.password_change`.

### `/auth/me` dan RBAC
- `/auth/me` mengembalikan `{user, roles:[{role, scope}], permissions}`. `permissions` berasal dari `effective_permissions(grants, project_id=None)`.
- `require_permission(perm)` hanya menerima permission global-only. Permission project memicu `ValueError` saat route dibangun. Ini menutup temuan LOW (a) WP-1.1c: route project wajib memakai `require_project_permission` (WP-2.1), yang menyertakan `project_id`.

## Keputusan saya (cek)

| # | Keputusan | Dasar / label |
|---|---|---|
| 1 | Lockout dan email tak dikenal → 401 generik | API_CONTRACTS §11 #17 [Pasti] |
| 2 | Redis tidak tersedia saat rate limit → 503 `DEPENDENCY_UNAVAILABLE` (fail closed) | SECURITY_MODEL §8 mewajibkan rate limit [Kemungkinan Besar] |
| 3 | Token reset berlaku 30 menit dan hanya muncul di log development | Dokumen tidak menetapkan TTL [Menebak]. "Dicatat di audit/log dev" saya tafsirkan sebagai log dev saja: menyimpan token hidup di audit 365 hari melanggar SECURITY_MODEL §6.2. **Konflik dokumen, dilaporkan.** |
| 4 | Panjang password maksimum 1024 | Mencegah DoS argon2 [Kemungkinan Besar] |
| 5 | `remember_me` hanya mengatur `Max-Age` cookie, bukan umur sesi di server | Kontrak tidak menjelaskan [Menebak] |
| 6 | Salah `current_password` menambah counter lockout | [Kemungkinan Besar] |
| 7 | IP klien = `request.client.host`. Header proxy dipercaya hanya lewat `uvicorn --forwarded-allow-ips` ke Caddy (WP-1.5). Aplikasi tidak membaca `X-Forwarded-For` sendiri. | Mencegah spoofing XFF [Kemungkinan Besar] |
| 8 | Nama aksi audit baru `auth.password_reset_requested` | Daftar SECURITY_MODEL §8 tidak punya event "permintaan reset" |

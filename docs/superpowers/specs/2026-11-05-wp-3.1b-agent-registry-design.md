## Intent

Server tahu persis agent apa saja yang ada dan apa yang boleh dilakukan masing-masing. Server menolak start bila registry memberi agent izin di luar profilnya. User melihat katalog yang jujur: untuk apa agent itu, apa yang boleh disentuhnya, dan apakah ia benar-benar bisa berjalan hari ini.

## Keadaan awal

- Repo hanya punya `agents/registry.v2.yaml` (skema 2, 53 entri, 20 aktif). `AGENT_REGISTRY_PATH` default `/app/agents/registry.yaml` merujuk file skema 1 yang tidak ada, dan image backend tidak menyalin `agents/` sama sekali.
- Belum ada loader, tabel `agent_profiles`/`agent_runs`, endpoint agent, atau layar katalog (`/agents` masih placeholder).
- Agent aktif mengizinkan tool yang belum dibangun: semua builtin baru dibangun di 3.1d, dan `tests.run`, `review.*`, `acceptance.*`, `memory.*`, `security.scan_secrets`, `env.inspect_runtime` bahkan di WP yang lebih jauh.

## Goals

1. **Registry di image.** `agents/registry.v2.yaml` disalin ke `/app/agents/registry.yaml`. `AGENT_REGISTRY_PATH` tidak berubah, dan nama file di image sudah sesuai rencana WP-9.0 ("registry.v2.yaml → registry.yaml"). Test dan dev menyetel path ke file di repo.
2. **Loader `app/agents/registry.py`:** `load_registry(path) -> AgentRegistry`, memakai `yaml.safe_load` dan model Pydantic (`extra="forbid"`).
   - **Registry tidak valid → `RegistryError`** berisi daftar masalah: id agent + aturan, tanpa isi file lain. API gagal start (FR-041).
   - **Aturan yang ditegakkan saat runtime:**
     - struktur dan enum skema 2, termasuk field opsional v2;
     - id/slug unik;
     - `enabled` ⇔ `mvp_mode != planned`;
     - `runtime_agent` ada tepat untuk mode profile dan menunjuk agent llm, dengan kontrak profil = kontrak agent runtime-nya;
     - kontrak: llm sama dengan peta runtime (A02, A03, B14, C20, D22, A07); tool dan planned tanpa target `null`; planned dengan target memakai `contract_status: planned`;
     - izin: 6 atau 8 field (default v2 untuk entri lama), enum, **`approval_grant` selalu `deny`** (FR-043), `deployment ≠ deny` hanya F32;
     - tool: unik, ⊆ katalog tool, prasyarat izin terpenuhi (mis. reviewer read-only tidak boleh tool tulis), R2 butuh `sandbox: allow`, tool `disabled`/`planned` tidak pernah di agent aktif, R3 tidak pernah di agent llm/profile, pemilik R3 v2 (J48, K51);
     - aturan `submit_result`;
     - rentang `limits` dan `tool_quota`.
   - **Hanya di CI** (`scripts/validate_registry.py`): kecocokan teks dengan PRD/K2 (nama, grup, capability), izin yang dipin per agent, dan jumlah tepat 53 id. Ini kesetiaan dokumen, bukan keamanan runtime; menolak start karena teks dokumen bergeser tidak menambah keamanan.
   - **Paritas dibuktikan test:** registry asli lolos di keduanya, dan setiap registry mutan yang melanggar satu aturan keamanan ditolak keduanya.
3. **Katalog tool `app/tools/catalog.py`:** `ToolInfo(name, risk, executor, preconditions, status, implemented)`.
   - Isinya sama dengan `TOOL_CATALOG` di validator (dibuktikan test).
   - `implemented` bernilai `False` untuk semua tool di 3.1b; 3.1d mengubahnya per tool yang dibangun.
   - Data murni: ToolGateway 3.1d memakainya.
4. **Status agent (FR-045, perluasan Lead):** `planned` | `disabled` | `not_ready` | `ready`, ditambah `status_reasons`.
   - **Alasan untuk agent aktif:**
     - `runtime_unavailable`: AgentRuntime (3.1f) untuk llm/profile, dan workflow engine (WP-3.2) untuk ORCH;
     - `provider_readiness_unknown`: readiness gate (3.1e), untuk llm/profile;
     - `tools_unavailable`: ada tool di allowlist yang belum dibangun; nama tool-nya ada di `unavailable_tools`.
   - `ready` hanya bila tidak ada alasan sama sekali. Di 3.1b semua agent aktif berstatus `not_ready`, karena itu kenyataannya.
   - Status dihitung saat dibaca dari keadaan kode dan readiness, tidak disimpan.
5. **Tabel (migrasi 0006_agents):**
   - **`agent_profiles`:**
     - kolom DATA_MODEL ditambah yang diminta FR-042 dan v2: `purpose`, `triggers`, `input_contract`, `output_contract`, `target_mode`, `phase`, `contract_status`, `notes`;
     - `permission_profile` (8 field efektif);
     - `registry_hash` (sha256 entri kanonik, untuk mendeteksi pergeseran) dan `in_registry`;
     - `created_at`/`updated_at`;
     - CHECK untuk `mvp_mode`, `priority`, `model_tier`, dan `group`.
   - **`agent_runs`:**
     - kolom DATA_MODEL dengan status 6 nilai, termasuk `approval_required` (ADR-025), sejak awal;
     - tambahan `cost_status` (API §11.2) dan `created_at`;
     - `prompt_version` nullable, karena agent tool tidak punya prompt;
     - FK `task_id` → tasks CASCADE dan `agent_id` → agent_profiles RESTRICT;
     - index `(task_id)` dan `(agent_id, started_at)`.
   - Belum ada penulis `agent_runs` di 3.1b; penulisnya 3.1f.
6. **Sinkron `app/services/agents.py::sync_registry`:**
   - di bawah `pg_advisory_xact_lock`, sehingga dua proses yang start bersamaan tidak bentrok;
   - upsert setiap entri, dan baris yang berubah hanya ditulis bila `registry_hash` berbeda;
   - id yang hilang dari file → `in_registry=false`, `enabled=false`. Id tidak pernah dihapus atau dipakai ulang;
   - audit `agent.registry_synced` dengan jumlah inserted/updated/retired, hanya bila ada perubahan.
   - **Dijalankan:** di lifespan API setelah registry valid dimuat, dan lewat CLI `python -m app.cli seed-agents` (RUNBOOK `make seed-agents`).
7. **API:**
   - **`GET /agents?group=&mode=&status=&q=`** (user yang masuk):
     - mengembalikan `[AgentProfileOut]` dan `meta: {total, counts: {mode: {…}, status: {…}}}` untuk chip filter;
     - tanpa paginasi, karena registry terbatas (53);
     - filter tak dikenal → 422; `q` ≤ 100 karakter, tanpa karakter kontrol.
   - **`GET /agents/{agent_id}`:**
     - `AgentProfileOut` + `recent_runs` (≤ 10) + `stats {runs, success_rate, avg_duration_ms}`;
     - run dan statistik **hanya dari task di project yang terlihat oleh user** (`visible_projects_filter`); `success_rate`/`avg_duration_ms` `null` bila tidak ada run;
     - id tak dikenal atau salah bentuk → 404.
   - **`AgentProfileOut`:** field §6 + `purpose`, `triggers`, `input_contract`, `output_contract`, `target_mode`, `phase`, `unavailable_tools`, `status_reasons`; `permission_profile` 8 field.
8. **Layar `/agents` (`features/agents`):**
   - **Katalog:**
     - chip mode dengan jumlah, filter status, dan pencarian (nama, id, tool);
     - kartu dikelompokkan per grup: id, nama, prioritas, mode, status (teks + ikon), dan ringkasan alasan;
     - kalimat "Tidak ada agent yang dapat memberi persetujuan" diturunkan dari data (jumlah `approval_grant ≠ deny` = 0), bukan teks tetap.
   - **Detail `/agents/:agentId`:**
     - tujuan, trigger, capability, tabel izin, tool (yang belum tersedia ditandai), limits, tier model, kontrak;
     - run terbaru, atau keadaan kosong "belum ada run".
   - **State:** loading, error dengan ID permintaan + coba lagi, kosong (filter tanpa hasil), 404 detail.
   - Semua teks lewat kunci i18n `id`/`en`.
9. **Layering:** import-linter menambah `app.agents` di atas `app.tools`, dan `app.tools` di atas `app.workspace | app.gitops | app.sandbox | app.llm` (ARCHITECTURE §3.2; tools → llm(base) diizinkan, konflik #72 butir 5).

## Non-goals

- `PATCH /agents/{id}` / override admin (FR-047, P1). Override harus bertahan melewati sinkron, dan itu butuh kolom serta aturan sendiri.
- `GET /tasks/{tid}/agent-runs`: API task belum ada (WP-3.2).
- Field kontrak I/O (`app/agents/contracts.py`) dan prompt: 3.1f, saat runtime yang memakainya dibangun. Validator CI tetap memakai `FALLBACK_CONTRACTS` sampai saat itu.
- Validasi registry di worker: 3.1f, saat worker memakai agent.
- Readiness gate provider: 3.1e. Sampai saat itu alasan `provider_readiness_unknown` tetap ada.

## Anti-goals

- Katalog menyebut agent "siap" padahal tidak bisa berjalan.
- Registry yang memberi `approval_grant` selain `deny`, atau tool di luar izin, tetap diterima saat runtime.
- Run atau statistik dari project yang tidak terlihat oleh user ikut tampil.
- Dua proses start bersamaan menghasilkan baris ganda atau sinkron setengah jadi.

## Review Focus (dibuktikan test)

1. Registry dengan `approval_grant: allow`, tool di luar izin, R2 tanpa sandbox, atau tool `disabled` di agent aktif → API gagal start, dengan pesan yang menyebut agent dan aturannya. Validator CI menolak registry mutan yang sama.
2. Tidak ada agent berstatus `ready` selama runtime, readiness, atau tool-nya belum ada.
3. `recent_runs` dan `stats` tidak pernah memuat run dari project yang tidak terlihat oleh user.
4. Sinkron idempoten; sinkron paralel tidak bentrok; id yang hilang dari file ditandai pensiun, tidak dihapus.
5. Layar menampilkan status dengan teks + ikon dan alasannya, serta tidak pernah mengklaim kemampuan memberi persetujuan.

## Konflik (ditambahkan ke #72)

- Registry: file v2 disalin ke path v1 di image. AGENT_CATALOG §12.9 menaruh loader v2 di WP-9.0; 3.1b membutuhkannya sekarang karena hanya file itu yang ada.
- Status `not_ready` + `status_reasons` memperluas enum FR-045/API §6 (`ready|disabled|planned`). Alasannya: "siap" tanpa runtime, readiness, dan tool adalah klaim tanpa bukti.
- Kolom tambahan di luar DATA_MODEL: `purpose`, `triggers`, kontrak, field v2, `registry_hash`, `in_registry`, `created_at`, `agent_runs.cost_status`. `permission_profile` di API berisi 8 field, bukan 6.
- `GET /agents` tanpa paginasi (registry terbatas), tetapi dengan `meta.counts`; filter `status` ditambahkan (FR-044).
- Mockup screen-05 dan PRD v2.2 menulis 42 agent; registry v2 berisi 53. Layar mengikuti data.
- `scripts/test_validate_registry.py` ("17 test") yang disebut README, AGENT_CATALOG, dan TEST_STRATEGY tidak ada. Paritas loader–validator diuji di `backend/tests/unit/test_registry_loader.py`.

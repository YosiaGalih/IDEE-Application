## Intent

**Masalahnya.** Sampai WP-1.3 semua komponen hanya berjalan sebagai proses test. AC-20 dan gate G1 butuh satu stack yang bisa dijalankan dari checkout bersih: `make setup && make up`, semua container healthy, dan `/health/ready` ok untuk db, redis, sandbox_manager, migrations. Topologinya sudah dikunci dokumen (ARCHITECTURE §2, DEPLOYMENT); WP ini menuliskannya sebagai file yang bisa dijalankan dan diuji.

**Goals**
1. `infra/compose.yml` dengan 10 service v1:
   - `caddy`, `web` (placeholder), `api`, `migrate`, `worker`, `scheduler`;
   - `postgres`, `redis`, `sandbox-manager`, `docker-socket-proxy`;
   - jaringan `public`, `edge`, `app`, `exec`, `outbound` sesuai ARCHITECTURE §2;
   - hardening, limit, healthcheck, urutan start dari DEPLOYMENT §2 dan RUNBOOK §2.
2. `backend/Dockerfile` (satu image untuk api/worker/scheduler/migrate) dan `sandbox_manager/Dockerfile`:
   - base dipin digest;
   - `uv sync --locked`;
   - uid 10001;
   - aman untuk rootfs read-only;
   - CA proxy build opsional lewat BuildKit secret, tidak masuk layer.
3. `infra/caddy/Caddyfile`: routing dan header keamanan DEPLOYMENT §6.
4. `.env.example`, `scripts/gen-secrets.sh`, `scripts/healthcheck.sh`, `Makefile` (setup, config, up, down, ps, logs, healthcheck).
5. Test kebijakan atas `docker compose config` (JSON), dijalankan di CI.
6. Bukti live: stack dibangun dan dijalankan di container cloud sampai semua healthy, `/health/ready` ok, dan socket-proxy menolak endpoint terlarang.

**Non-goals.** egress-proxy (1.5b), backup/restore (1.5c), frontend asli (WP-1.4), gVisor (opsional, RUNBOOK §11), node executor terpisah (DEPLOYMENT §8).

**Anti-goals**
- Port selain 80/443 dipublikasi di compose produksi.
- docker.sock ada di container selain socket-proxy, atau proxy dapat dijangkau selain dari sandbox-manager.
- Secret sampai ke service yang tidak membutuhkannya.
- Image di-pull dari registry publik untuk service buatan sendiri.
- Stack "healthy" padahal `/health/ready` tidak ok (healthcheck api memakai `/health/ready`).

## Approaches

| | Pendekatan | Trade-off | Status |
|---|---|---|---|
| A | Satu `infra/compose.yml` produksi + `infra/compose.dev.yml` override dev, env lewat `--env-file .env`, anchor YAML untuk env backend | Sesuai DEPLOYMENT/RUNBOOK kata per kata; satu sumber; dev override hanya menambah port loopback | **dipilih** |
| B | Compose per peran (control/executor) sekarang | Diperlukan baru di scale-out (DEPLOYMENT §8); menggandakan file tanpa kebutuhan terukur (prinsip #8) | ditolak |
| C | Helm/Kubernetes | Dilarang tanpa bottleneck terukur (ADR-010) | ditolak |

## Desain

### Service (ringkas; angka dari DEPLOYMENT §2)

| Service | Image | User | Network | Catatan |
|---|---|---|---|---|
| caddy | `caddy:2.11.7-alpine@digest` | root, `cap_drop ALL` + `NET_BIND_SERVICE` | public, edge | satu-satunya `ports`: 80, 443/tcp, 443/udp |
| web | `caddy:…@digest` file_server :8080 | 101 | edge | **placeholder** sampai WP-1.4: halaman statis + `/healthz` (keputusan #3) |
| api | `kodekantor/backend:${KK_IMAGE_TAG}` | 10001 | edge, app | `uvicorn app.main:app`; healthcheck `/api/v1/health/ready` |
| migrate | backend | 10001 | app | `alembic upgrade head`, `restart: "no"` |
| worker | backend | 10001 | app, outbound | `celery … worker`; satu-satunya pemegang `ANTHROPIC_API_KEY` |
| scheduler | backend | 10001 | app | `celery … beat`, schedule di tmpfs |
| postgres | `postgres:16.15-alpine@digest` | 70 | app | read-only + tmpfs socket, scram-sha-256 |
| redis | `redis:7.4.11-alpine@digest` | 999 | app | `requirepass` dari file 0600 di tmpfs, AOF, `noeviction` |
| sandbox-manager | `kodekantor/sandbox-manager:${KK_IMAGE_TAG}` | 10001 | app, exec | tanpa docker.sock; `DOCKER_HOST=tcp://docker-socket-proxy:2375`; workspace di path identik; profil ro |
| docker-socket-proxy | `tecnativa/docker-socket-proxy:v0.5.0@digest` | root, `cap_drop ALL` | exec | socket `:ro`; flag ADR-026 (3) |

Untuk semua service:
- `security_opt: [no-new-privileges:true]`;
- `restart: unless-stopped` (kecuali migrate);
- log `json-file` 10m × 5 terkompresi;
- `deploy.resources.limits` (cpus, memory, pids).

Image buatan sendiri memakai `pull_policy: build`.

### Urutan start

```text
postgres, redis healthy ─► migrate (completed_successfully) ─► api, worker, scheduler
docker-socket-proxy healthy ─► sandbox-manager healthy ─► api
web ─► caddy
```

### Env per service (DEPLOYMENT §7)

- Anchor `x-backend-env` hanya untuk api/worker/scheduler/migrate.
- Compose menurunkan `DATABASE_URL`, `REDIS_URL`, `WORKSPACE_ROOT`, `SANDBOX_MANAGER_URL`, `DOCKER_HOST`, dan `SANDBOX_PROFILES_PATH` dari `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, dan `WORKSPACE_HOST_PATH`. Tidak bisa salah ketik.
- sandbox-manager menerima daftar eksplisit: token, `WORKSPACE_ROOT`, `DOCKER_HOST`, `SANDBOX_*`, `APP_ENV`. Tanpa `SECRET_KEY`, tanpa URL database.
- docker-socket-proxy hanya menerima flag. caddy hanya `APP_DOMAIN`, `CADDY_EMAIL`, `CADDY_HSTS_MAX_AGE`.

### Test kebijakan

`infra/tests/test_compose_policy.py` (stdlib `unittest`, tanpa dependensi) membaca `docker compose -f infra/compose.yml --env-file infra/tests/ci.env config --format json` dan menegakkan tabel ADR di atas. CI job `infra-config` menjalankannya, ditambah `caddy validate` lewat image caddy yang sama.

## Keputusan saya (cek)

1. **egress-proxy ditunda ke 1.5b.** `SANDBOX_EGRESS=off` adalah default, sehingga stack tanpa egress tetap utuh. Jaringan `kk-egress` dibuat bersama proxy-nya.
2. **`ANTHROPIC_API_KEY` hanya ke worker** (konflik #40). api tidak berada di network `outbound`, jadi kunci di api tidak bisa dipakai, hanya menambah eksposur. Smoke test dijalankan lewat `docker compose exec worker`.
3. **`web` placeholder memakai image caddy yang sama** (file_server :8080, uid 101), bukan `kodekantor/web` dari `frontend/`, karena frontend belum ada (WP-1.4). WP-1.4 mengganti service ini tanpa mengubah jaringan dan route.
4. **`INFO=0` di socket-proxy** mengikuti ADR-026 (3) dan `infra.md`. DEPLOYMENT §2 menulis `INFO=1` (konflik #41). Sandbox-manager tidak memanggil `/info` (`test_only_allowed_endpoints`).
5. **Job CI `infra-config`** belum ada di tabel TEST_STRATEGY §6 (konflik #42). Job `clean-install` yang ada di tabel adalah nightly dan butuh WP-1.6, sedangkan kebijakan compose harus dicek di setiap PR.
6. **Base image dipin digest.** Image Docker Hub diambil lewat mirror bila Docker Hub 429; digest tetap sama.
7. **`scripts/healthcheck.sh`**:
   - menunggu semua container healthy (dan migrate exit 0) sampai `--wait` detik;
   - memeriksa `/api/v1/health/live` dan `/ready` lewat Caddy;
   - memeriksa `/` lewat Caddy.

   Untuk `APP_DOMAIN=localhost`, Caddy memakai CA internal, dan skrip memakai `--insecure` hanya untuk host `localhost`.

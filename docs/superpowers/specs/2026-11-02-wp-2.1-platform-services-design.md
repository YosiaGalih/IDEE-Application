## 2.1a — rancangan

### Intent

User yang sudah masuk membuat project kosong atau dari template, melihat daftar project yang boleh ia lihat, mengubah nama, deskripsi, dan setting, lalu mengarsipkan atau mengaktifkan lagi project itu. Setiap project punya repository git lokal di `WORKSPACE_ROOT/<project_id>/repo` pada default branch. Project user lain tidak terlihat sama sekali (AC-01).

### Goals

1. **`POST /projects`** `{name, description?, source:{type:"blank"} | {type:"template", template_id}, default_branch?}` → 201 `Project`.
   - Validasi:
     - `name` 1–120 karakter setelah trim, tanpa karakter kontrol;
     - `description` ≤ 2000;
     - `default_branch` sesuai aturan branch GitAdapter, default `main`;
     - `template_id` harus ada di `list_templates()`.
   - Slug diturunkan dari nama (huruf kecil ASCII, `-`, ≤ 63). Bila sudah dipakai oleh owner yang sama, diberi akhiran `-2`, `-3`, … (UNIQUE `(owner_id, slug)`).
   - Repository:
     - **blank:** `git init` pada default branch, lalu satu commit awal berisi `README.md` (judul = nama project). Alasannya: worktree task (FR-114) butuh base commit, dan repo tanpa commit tidak bisa di-branch.
     - **template:** `materialize`, lalu commit awal "Initial commit from template <id>".
   - Deteksi stack (`workspace/stack.py`) setelah file ada; hasilnya disimpan di `projects.stack`.
   - Baris `repositories`: `provider = local | template`, `branch = default_branch`, `sync_state = ready`.
   - **Atomik:** baris project dibuat di transaksi yang sama. Bila langkah filesystem atau git gagal, transaksi di-rollback dan direktori project dihapus. Bila commit DB gagal setelah direktori dibuat, direktori juga dihapus. Tidak ada project setengah jadi.
   - Audit `project.create` (`metadata: {source, template_id?}`).
2. **`GET /projects?status=&q=`** → project yang terlihat oleh user:
   - yang ia miliki;
   - yang memberinya role berscope `project:<id>` (aturan scope `core/rbac.py`).
   - `status` default `active`. `q` mencocokkan nama atau slug (case-insensitive). Status `deleted` tidak pernah tampil.
3. **`GET /projects/{id}`** → `Project` + `repository` + `stats` + `permissions`. Project di luar scope menghasilkan **404 `NOT_FOUND`** (SECURITY_MODEL §8), bukan 403.
4. **`PATCH /projects/{id}`** (`project:write`) `{name?, description?, settings?}`.
   - `settings` divalidasi dengan model yang menolak kunci asing: `plan_approval_required: bool`, `auto_remediation: bool`. Budget default punya endpoint sendiri (WP-3.1).
   - Slug tidak berubah saat nama berubah, karena slug adalah ID stabil (FR-012).
   - Audit `project.update` (`metadata: {fields}`).
5. **`POST /projects/{id}/archive` / `unarchive`** (`project:write`):
   - `active → archived` dan `archived → active`; selain itu **409 `CONFLICT`**;
   - audit `project.archive` / `project.unarchive`.
6. **`GET /projects/templates`** (auth) → `[{id, name, description, stack, icon}]`.
7. **`GET /projects/{id}/stack`** (`project:read`) → `Stack` tersimpan.
8. **Otorisasi berscope project** (`api/deps.py`, `ProjectAccess`):
   - Memuat project dan menghitung `effective_permissions(grants, user_id, project_id, project_owner_id)`.
   - **404** bila izinnya kosong atau project berstatus `deleted`; **403 `FORBIDDEN`** bila project terlihat tetapi izin yang diminta tidak ada.
   - Service juga memeriksa izin; route hanya pintu pertama (SECURITY_MODEL §8: "diulang di service").
9. **`Project`** (API_CONTRACTS §3 + §11 #14): `{id, name, slug, description, status, stack, default_branch, settings, owner_id, created_at, updated_at, repository:{provider, remote_url, branch, sync_state, last_indexed_at, error}, permissions:[perm], stats:{files, last_commit, open_tasks}}`.
   - `stats.files` bernilai `null` sampai indeks ada (2.1d).
   - `last_commit` dari `GitAdapter.current_commit`.
   - `open_tasks` = jumlah task dengan status non-terminal.
10. **Image backend memasang `git`** (Debian, `--no-install-recommends`). Pembuatan project di stack produksi butuh git. Trivy di CI memeriksa paket barunya.
11. **Layar:**
    - **`/projects`:** daftar dengan pencarian, filter status, state kosong/loading/error, dan aksi arsip/aktifkan sesuai `permissions`.
    - **`/projects/new`:** nama, deskripsi, sumber blank atau template (kartu dari `/projects/templates`); validasi lokal; sukses → `/projects/:id/workspace`.
    - Item navigasi "Project" sudah ada.

### Anti-goals

- Project user lain bisa ditebak lewat 403 atau pesan error. Yang benar adalah 404 untuk semua yang di luar scope.
- Direktori project tertinggal tanpa baris DB, atau baris DB tanpa direktori.
- Nama project masuk ke perintah git atau path. Path selalu `<project_id>`, dan nama hanya muncul sebagai isi README yang ditulis lewat Python.
- Slug berubah saat rename.

## 2.1a — rancangan

### Intent

User yang sudah masuk membuat project kosong atau dari template, melihat daftar project yang boleh ia lihat, mengubah nama, deskripsi, dan setting, lalu mengarsipkan atau mengaktifkan lagi project itu. Setiap project punya repository git lokal di `WORKSPACE_ROOT/<project_id>/repo` pada default branch. Project user lain tidak terlihat sama sekali (AC-01).

### Goals

1. **`POST /projects`** `{name, description?, source:{type:"blank"} | {type:"template", template_id}, default_branch?}` → 201 `Project`.
   - Validasi:
     - `name` 1–120 karakter setelah trim, tanpa karakter Unicode kategori `Cc`, `Cf`, `Zl`, `Zp` (kontrol, bidi override, zero-width, pemisah baris). Alasannya: nama seperti itu bisa tampil sebagai nama project lain (temuan AG-13);
     - `description` ≤ 2000;
     - `default_branch` sesuai aturan branch GitAdapter, default `main`;
     - `template_id` harus ada di `list_templates()`.
   - Slug diturunkan dari nama (huruf kecil ASCII, `-`, ≤ 63). Bila sudah dipakai oleh owner yang sama, diberi akhiran `-2`, `-3`, … (UNIQUE `(owner_id, slug)`).
   - Repository:
     - **blank:** `git init` pada default branch, lalu satu commit awal berisi `README.md` (judul = nama project). Alasannya: worktree task (FR-114) butuh base commit, dan repo tanpa commit tidak bisa di-branch.
     - **template:** `materialize`, lalu commit awal "Initial commit from template <id>".
   - Deteksi stack (`workspace/stack.py`) setelah file ada; hasilnya disimpan di `projects.stack`.
   - Baris `repositories`: `provider = local | template`, `branch = default_branch`, `sync_state = ready`.
   - **Atomik:** baris project dibuat di transaksi yang sama. Bila langkah filesystem atau git gagal, transaksi di-rollback dan direktori project dihapus. Tidak ada project setengah jadi.
     - Bila `COMMIT` sendiri melempar error, DB yang memutuskan. Sesi baru mengecek apakah barisnya ada; bila ada, direktori dipertahankan, karena commit sampai ke server dan hanya jawabannya yang hilang.
     - Pembersihan berjalan sebagai task yang di-shield, sehingga cancel kedua tidak menghentikannya di tengah. Kegagalan pembersihan di-log per path (`project_create_cleanup_failed`).
     - Kegagalan create di-log (`project_create_failed`, dengan tahap dan alasan) dan diaudit `result=error` lewat `write_detached`.
   - **Batas:**
     - 20 create per user per 10 menit (429 `RATE_LIMITED` + `Retry-After`; Redis mati → 503, fail closed);
     - satu create berjalan per owner dan maksimal 4 per proses (`CreateGate`). Yang menunggu tidak memegang koneksi DB;
     - `lock_timeout` 10 detik pada advisory lock slug (→ 429).
   - Kegagalan git → **500 `GIT_ERROR`** (API_CONTRACTS §1: "git juga dapat 400/500"). Alasannya: 409 disimpan idempotency selama 24 jam, padahal kegagalan infrastruktur boleh dicoba lagi.
   - Audit `project.create` (`metadata: {source, template_id?}`, `ip`). Sumber `git_https` ditolak 403 `POLICY_DENIED` dan diaudit `result=denied`.
2. **`GET /projects?status=&q=&page=&page_size=`** → project yang terlihat oleh user:
   - yang ia miliki;
   - yang memberinya role berscope `project:<id>` (aturan scope `core/rbac.py`).
   - `status` default `active`. `q` mencocokkan nama atau slug (case-insensitive); karakter kontrol → 422. Status `deleted` tidak pernah tampil.
   - Dipaginasi (API_CONTRACTS §1): `page` ≥ 1, `page_size` 1–200 (default 50), `meta: {page, page_size, total}`. Urutan `updated_at` menurun.
3. **`GET /projects/{id}`** → `Project` + `repository` + `stats` + `permissions`. Project di luar scope menghasilkan **404 `NOT_FOUND`** (SECURITY_MODEL §8), bukan 403.
4. **`PATCH /projects/{id}`** (`project:write`) `{name?, description?, settings?}`.
   - `settings` divalidasi dengan model yang menolak kunci asing: `plan_approval_required: bool`, `auto_remediation: bool`. Budget default punya endpoint sendiri (WP-3.1).
   - Slug tidak berubah saat nama berubah, karena slug adalah ID stabil (FR-012).
   - `settings: null` atau kunci bernilai `null` → 422. Hanya kunci yang dikirim yang berubah.
   - Audit `project.update` hanya bila ada yang berubah: `metadata: {fields, settings?}`. `settings` memuat nilai baru (boolean, bukan secret), supaya mematikan `plan_approval_required` tercatat beserta nilainya.
5. **`POST /projects/{id}/archive` / `unarchive`** (`project:write`):
   - `active → archived` dan `archived → active`; selain itu **409 `INVALID_TRANSITION`** (kode §1 untuk transisi status; draf awal menulis `CONFLICT`, temuan review N3);
   - audit `project.archive` / `project.unarchive`.
6. **`GET /projects/templates`** (auth) → `[{id, name, description, stack, icon}]`.
7. **`GET /projects/{id}/stack`** (`project:read`) → `Stack` tersimpan.
8. **Otorisasi berscope project** (`api/deps.py`, `require_project_permission(perm)`; draf awal menamainya `ProjectAccess`):
   - Memuat project dan menghitung `effective_permissions(grants, user_id, project_id, project_owner_id)`.
   - **404** bila izinnya kosong atau project berstatus `deleted`; **403 `FORBIDDEN`** bila project terlihat tetapi izin yang diminta tidak ada.
   - Service juga memeriksa izin; route hanya pintu pertama (SECURITY_MODEL §8: "diulang di service").
   - `tests/security/test_cross_project.py` menelusuri router (termasuk route `include_in_schema=False`), dan gagal bila ada route `{project_id}` tanpa dependency ini.
   - Lock baris (`FOR NO KEY UPDATE`) diambil setelah keputusan izin, supaya orang asing tidak pernah memegang lock project orang lain.
9. **`Project`** (API_CONTRACTS §3 + §11 #14): `{id, name, slug, description, status, stack, default_branch, settings, owner_id, created_at, updated_at, repository:{provider, remote_url, branch, sync_state, last_indexed_at, error}, permissions:[perm], stats:{files, last_commit, open_tasks}}`.
   - `stats.files` bernilai `null` sampai indeks ada (2.1d).
   - `last_commit` dari `GitAdapter.current_commit`. Git dijalankan setelah sesi DB ditutup (dan pada update/arsip setelah commit), sehingga disk yang lambat tidak menahan koneksi atau lock baris.
   - Masalah repo (`repository_missing`, `repository_unreadable`, `repository_unsafe`, `repository_without_commit`) tidak disamarkan menjadi `null`. Masalah itu di-log level error dan dikirim sebagai `repository.sync_state = "error"` + `repository.error = <kode>`. `repository_unsafe` (metadata git dirusak, ADR-026) juga diaudit. Daftar hanya mengecek keberadaan folder.
   - `open_tasks` = jumlah task yang belum selesai: semua status kecuali `completed`, `failed`, `cancelled`, `rejected`. Draf awal menulis "non-terminal". Di `workflow.states`, yang terminal hanya `cancelled` dan `rejected`, karena `completed` dan `failed` masih bisa kembali ke `queued`. Akibatnya task yang sudah selesai ikut terhitung "open" (temuan B1/M7).
10. **Image backend memasang `git`** (Debian, `--no-install-recommends`). Pembuatan project di stack produksi butuh git. Trivy di CI memeriksa paket barunya.
11. **Layar:**
    - **`/projects`:** daftar dengan pencarian, filter status, state kosong/loading/error, dan aksi arsip/aktifkan sesuai `permissions`.
    - **`/projects/new`:** nama, deskripsi, sumber blank atau template (kartu dari `/projects/templates`); validasi lokal; sukses → `/projects/:id/workspace`.
    - Item navigasi "Project" sudah ada.

### Anti-goals

- Project user lain bisa ditebak lewat 403 atau pesan error. Yang benar adalah 404 untuk semua yang di luar scope.
- Direktori project tertinggal tanpa baris DB, atau baris DB tanpa direktori.
- Nama project masuk ke perintah git atau path. Path selalu `<project_id>`, dan nama hanya muncul sebagai isi README yang ditulis lewat Python.
- Slug berubah saat rename.

### Keputusan

| Topik | Keputusan | Alasan |
|---|---|---|
| Lokasi repo | `WORKSPACE_ROOT/<project_id>/repo`; `workspace_ref = <project_id>` | ARCHITECTURE §7, DATA_MODEL |
| Commit awal blank | README.md + commit "Initial commit" | Worktree task butuh base commit; FR-013 cukup dengan "repository terinisialisasi". Dicatat di sini sebagai keputusan |
| Author commit awal | `display_name <email>` user pembuat; committer tetap `KodeKantor` | FR-116 (jejak siapa); validasi `_author` GitAdapter menolak `<>`/newline |
| 404 vs 403 | 404 di luar scope, 403 di dalam scope tanpa izin | SECURITY_MODEL §8, API_CONTRACTS §1 |
| Siapa boleh membuat | setiap user aktif (`auth`) | API_CONTRACTS §3. Kuota project per user (FR-153) P1 |
| Status awal | `active` | DATA_MODEL |
| Respons create | 201 + header `Location` | API_CONTRACTS §3 |
| Idempotency | `POST /projects` memakai `Idempotency-Key` yang sudah ditegakkan middleware | API_CONTRACTS §1 |
| Kode git gagal | 500 `GIT_ERROR` | 409 disimpan idempotency 24 jam; kontrak mengizinkan 500 |
| Batas create | 20/user/10 menit; 1 per owner dan 4 per proses sekaligus | Ditemukan review: satu user bisa memperlambat API (AG-13 LOW, S2). FR-153 (kuota) tetap P1 |
| Masalah repo | `sync_state=error` + `error=<kode>` di respons, tanpa menulis DB | Jalur baca tidak menulis; penulisan state (dan penyapu folder yatim) menyusul di 2.1c |
| `open_tasks` | semua status kecuali `completed/failed/cancelled/rejected` | Arti "open" bagi user; `TERMINAL` di `workflow.states` bermakna lain |
| Role global di project yang diberi grant | Berlaku penuh (admin global + `readonly` project → bisa menulis) | API_CONTRACTS §2 apa adanya. AG-13 menandainya sebagai kejutan; **keputusan PO** di tracker. Test HTTP mengunci perilaku ini |

| Bagian | Yang diuji |

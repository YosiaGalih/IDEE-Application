## Intent

Di workspace, user melihat apa yang berubah sejak commit terakhir, memeriksa diff-nya, lalu meng-commit file yang ia pilih dengan pesannya sendiri. User juga bisa membuat branch dan membaca log commit. Panel tidak pernah meng-commit sesuatu yang tidak user lihat, dan tidak pernah membuang atau menimpa perubahan (FR-118).

## Goals

1. **Tampilan Git di kolom kiri.** Dua tombol di atas kolom kiri, **Explorer** dan **Git**, memilih isi kolom. Tombol Git membawa jumlah perubahan (teks + angka, bukan warna saja). Pilihan tidak disimpan antar-kunjungan.
2. **Ringkasan repo:** branch dan head (7 karakter) dari `GET /git/status`. Bila `clean` → "Tidak ada perubahan sejak commit terakhir".
3. **Daftar perubahan** dari `GET /git/status`:
   - status per file berupa teks + ikon (`added`, `modified`, `deleted`, `untracked`, `conflicted`);
   - checkbox per file, semuanya tercentang saat daftar datang, plus "pilih semua / kosongkan";
   - klik path → dialog diff file itu;
   - tombol "Lihat semua diff" → dialog diff seluruh working tree.
4. **Diff** (`GET /git/diff?path=`, `base` default HEAD) dalam dialog lebar:
   - per file: path (dan `old_path` bila berbeda), status, `+additions −deletions`, hunk dengan header, nomor baris lama/baru, dan baris context/add/del;
   - penanda add/del berupa teks dan warna (`+`/`−` di kolom sendiri), bukan warna saja;
   - file biner → "File biner: isi tidak ditampilkan";
   - `truncated: true` → "Diff dipotong di 1 MiB: yang tampil tidak lengkap";
   - semua teks dirender sebagai teks (`<pre>`/`<code>`, tanpa HTML).
5. **Commit** (`POST /git/commit`):
   - textarea pesan; dikirim apa adanya, ditolak bila kosong atau hanya spasi; batas 5000 karakter seperti backend;
   - `paths` = file yang dicentang, **selalu eksplisit**: tidak pernah `paths: null`, supaya perubahan yang muncul sesudah daftar dibaca tidak ikut ter-commit;
   - tombol nonaktif tanpa pesan, tanpa file tercentang, atau saat commit berjalan;
   - berhasil → tampil "Commit <sha7> dibuat"; status (juga penanda di explorer), log, dan branch dibaca ulang; pesan dikosongkan. Tree tidak perlu dibaca ulang karena commit tidak mengubah file;
   - bila ada tab editor yang belum disimpan → peringatan "N file belum disimpan; commit memakai isi yang tersimpan di server" dengan daftar namanya. Commit tetap boleh.
6. **Error commit** (memakai `workspaceErrorText`):
   - 409 `nothing_to_commit` → "Tidak ada yang di-commit: file yang dipilih sama dengan commit terakhir";
   - alasan repository (`project_archived`, `repository_not_ready`, …) → teks yang sudah ada;
   - 422 (`.kk`, pesan, path) → teks validasi;
   - tanpa jawaban (network/timeout/502–504/409 idempotency) → "Belum pasti apakah commit dibuat". Percobaan ulang memakai `Idempotency-Key` yang sama (API_CONTRACTS §1) sampai pesan atau pilihan berubah. Status dan log dibaca ulang.
7. **Branch** (`GET /git/branches`, `POST /git/branch`):
   - daftar branch, dengan penanda "aktif" untuk `status.branch` dan "task" untuk `is_task_branch`;
   - form buat branch: nama + "dari" (pilihan: HEAD atau branch yang ada);
   - berhasil → "Branch X dibuat di <sha7>. Working tree tetap di branch <aktif>; pindah branch belum tersedia";
   - 409 `branch_exists` → "Branch itu sudah ada";
   - 422 → pesan validasi server (termasuk `kk`, `kk/…`, `refs/…`, `HEAD` yang dicadangkan). Petunjuk awalan cadangan juga tampil di form;
   - tanpa jawaban → "belum pasti", dengan key yang sama.
8. **Log** (`GET /git/log?limit=`): 20 commit terakhir, berisi sha7, pesan (subject), author, dan tanggal (`Intl`). "Muat lebih banyak" menaikkan limit 20 → 50 → 100 → 200. Pada 200 tampil "Batas 200 commit" (API tidak punya cursor).
9. **Izin:**
   - tanpa `git:read` → tampilan Git berstatus `permission_denied`;
   - form commit hanya dengan `workspace:write` pada project aktif dan repository siap (sama dengan `canWrite` 2.2a);
   - form branch hanya dengan `git:branch` pada project aktif dan repository siap.
10. **State wajib** (`.claude/rules/frontend.md`): loading, empty (clean), error dengan sebab + ID permintaan + coba lagi, permission denied, partial (diff `truncated`). Error status mempertahankan daftar yang sudah terbaca dan menyebut bahwa daftar itu mungkin basi; aturannya sama dengan penanda Git di 2.2a.

## Non-goals

- Stage/unstage, discard, checkout/pindah branch, rename, merge3: v2.1 M26 (FR-244, API §13.3, *turunan*).
- Push, pull, PR: jalur R3 GitHub App (FR-191, WP-INT).
- Diff antar-commit, branch task terhadap base (`base=<ref>` dipakai backend, tetapi UI 2.2b hanya HEAD↔working tree), blame.
- Hapus branch atau reset (FR-118).

## Anti-goals

- Commit yang memuat file yang tidak terlihat oleh user saat ia menekan tombol.
- Penanda status atau angka diff hanya dengan warna.
- Pesan commit atau baris diff dirender sebagai HTML atau Markdown.
- "Commit berhasil" tanpa sha dari server.

## Pendekatan

| | Isi | Untung | Rugi |
|---|---|---|---|
| **A. Toggle Explorer/Git di kolom kiri** (dipilih) | Kolom kiri berganti isi; diff di dialog lebar | Dekat dengan file yang dikerjakan (pola SCM editor umum); editor dan tab tetap; tidak mengubah reducer tab | Kolom 16 rem sempit untuk log yang panjang (diatasi dengan truncate + `title`) |
| B. Tab "Git" di panel kanan (sebelah Cari/Chat) | Semua git di panel kanan | Tanpa mengubah kolom kiri | 20 rem bersaing dengan pencarian; diff tetap butuh dialog/area lain |
| C. Route terpisah `/projects/:id/git` | Halaman penuh | Lebar penuh untuk diff dan log | Meninggalkan editor (penjaga perubahan belum disimpan memblokir); bukan "panel" seperti di spec 2.2 |

Diff di **dialog** (keputusan Lead), bukan tab editor: `DiffFile` dari API berupa hunk, bukan isi file utuh, sehingga diff Monaco (yang butuh dua teks utuh) tidak cocok tanpa endpoint tambahan. Tampilan baris unified dengan nomor baris cukup dan aman.

## Bentuk data (dari 2.1c)

```text
GitStatus  {branch|null, head|null, clean, changes:[{path, status: added|modified|deleted|untracked|conflicted}]}
Diff       {base, head|null, files:[DiffFile], stats:{files, additions, deletions}, truncated}
DiffFile   {path, old_path|null, status: added|modified|deleted, additions, deletions, is_binary,
            hunks:[{header, old_start, old_lines, new_start, new_lines,
                    lines:[{type: context|add|del, old_no|null, new_no|null, text}]}]}
Branch     {name, head, is_task_branch}
LogEntry   {commit, author ("nama <email>"), date (ISO 8601), message (subject)}
POST /git/branch → {name, head} (201) · POST /git/commit → {commit} (201)
```

Klien memvalidasi semua bentuk di atas dengan Zod. Jawaban yang tidak cocok → `bad_response`, tidak pernah dianggap kosong.

## Keputusan Lead

1. Pendekatan A (di atas).
2. Commit selalu dengan `paths` eksplisit (Goal 5).
3. Satu `Idempotency-Key` per niat commit/branch: dipakai ulang setelah hasil tidak pasti, diganti saat input berubah atau setelah berhasil.
4. Daftar perubahan dan explorer memakai query status yang sama (`gitStatusKey`). Commit dan simpan file membaca ulang keduanya.
5. Pilihan checkbox mengikuti daftar terbaru: file baru di daftar ikut tercentang; file yang hilang dari daftar hilang dari pilihan; pilihan user pada file yang tetap ada dipertahankan.
6. Teks dari repo (path, nama branch, pesan, author, baris diff) selalu teks React biasa.
7. Explorer dan tampilan Git sama-sama tetap ter-mount. Yang tidak dipilih disembunyikan (`hidden`), sehingga folder yang terbuka dan teks commit yang sedang ditulis tidak hilang saat berpindah.

## Review Focus (dibuktikan test)

1. Commit mengirim tepat path yang tercentang dan terlihat, tidak pernah `null`, termasuk saat status dibaca ulang di tengah jalan.
2. Hasil tidak pasti: percobaan ulang memakai key yang sama; key berganti saat pesan berubah.
3. `nothing_to_commit`, `branch_exists`, dan 422 punya teks sendiri; tidak satu pun tampil sebagai "berhasil".
4. Diff `truncated`, file biner, dan file `deleted` tampil jujur; baris diff yang berisi markup tampil sebagai teks.
5. Tanpa `workspace:write` atau `git:branch`, form-nya tidak tampil; tanpa `git:read`, tampilan Git berstatus izin ditolak.
